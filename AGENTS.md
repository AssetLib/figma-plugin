# AGENTS.md

Public repository `AssetLib/figma-plugin`: Assetlib for Figma. A Figma design plugin that inserts an app's placement artwork as image-filled components and library images as image-filled frames, sends one selected node to an Assetlib placement as a draft, then re-syncs that node's later edits. It calls the hosted console's token identity, placements, artwork, image library, rendition, and drafts endpoints with an app-scoped `draft` token. Publishing stays in the console; this plugin never publishes. TypeScript, bundled with esbuild, no runtime dependencies. See README for install, connection, and data handling.

## Commands

Node.js 22 or later (`engines` in `package.json`; `.nvmrc` is 24).

```sh
npm ci
npm run typecheck   # tsc for the main thread (tsconfig.json) and the UI (tsconfig.ui.json); no emit
npm test            # scripts/test.mjs: compiles src/shared to .test-build/, then node --test tests/*.test.mjs
npm run build       # scripts/build.mjs: minified dist/code.js and a self-contained dist/ui.html (over 160 KB, 160,000 bytes, it fails and writes none)
npm run verify      # typecheck, test, build
npm run test:browser  # build, then scripts/ui-browser.mjs drives dist/ui.html in headless Chrome (CHROME_PATH to choose one)
npm run watch       # build --watch: unminified with inline source maps, rebuilt on every change (build --dev builds once)
npm run contrast    # scripts/contrast.mjs: every text colour pair in Figma's light and dark themes (npm test runs it too)
npm run e2e:local -- --connection <file>   # live local console; not part of npm test (README "Development and verification")
```

CI (`.github/workflows/verify.yml`) runs `npm ci`, `npm run verify`, and `npm run test:browser` on Node.js 22 and 24. There is no lint script. `npm run verify` and `npm run test:browser` must pass before work is done. They cannot exercise real Figma exports, client storage across restarts, console CORS, or authenticated draft and rebind behavior. `npm run e2e:local` covers the token-only connect (`GET /api/token`), the authenticated reads, inserts, the draft round trip, and CORS preflights against a local console, still without real Figma; a change touching Figma behavior also needs a manual run in Figma desktop against a console (README "Development and verification").

## Layout

- `manifest.json`: Figma manifest. Plugin `id`, `main: dist/code.js`, `ui: dist/ui.html`, `documentAccess: "dynamic-page"`, network allowlist.
- `src/code.ts`: main thread in Figma's sandbox. Selection (and the current page's `nodechange`, so a resize on the canvas reaches the UI), `exportAsync`, Match ratio, inserting image components for placement art and frames for library images (`createImage`, `createComponent`, `createFrame`, pluginData), `figma.clientStorage`. No DOM and no HTTP here.
- `src/ui.html` and `src/ui/`: the UI iframe and every HTTP call. `ui.html` is the app shell: a first-run screen without a connection; otherwise a top bar (tabs, and the account chip, which is the `#settings` details' summary and opens the connection settings below the bar), the view (Insert: search, scope bar, and `#list-region`, the only part that scrolls; Send: its form), then the fixed `#messages` error line (`#error-box`: the `#error` text and at most one `#error-action`), the `#selection-bar` slot (A.7), and the footer of the view in front. `main.ts` is the entry: it routes main's messages and registers the renderer. `http.ts` makes every console request; `connection.ts` (form, connection test, label, and `fitWorkspace`, which sizes the chip's shortened workspace name to its ellipsis so the spaces around "·" match), `send.ts` (Send tab), `insert.ts` (Insert tab), and `thumbnails.ts` (previews) own their state and DOM; `state.ts` holds what more than one of them reads, including `ops`; `dom.ts` holds element, error, render-scheduling, and focus helpers. Modules import in one direction, `main` → `insert` → `thumbnails` → `connection` → `send` → `dom`, `http`, `state` (any may skip levels); keep it acyclic. `ui.html` must contain exactly one `<!-- ASSETLIB_SCRIPT -->` marker, where the build inlines the bundled UI script, and one `/* ASSETLIB_FONT */` marker, where it inlines Instrument Sans as a base64 `@font-face`. `src/image.ts` is browser-only (WebP to PNG through a canvas) and is imported by `src/ui/insert.ts` only.
- `src/assets/`: `instrument-sans-variable.woff2` and its licence `OFL.txt`, copied from the workspace's `brand/` by `sh brand/sync.sh`. Don't hand-edit them; change the brand source and sync.
- `src/shared/`: pure logic used by both sides (origin, token, and connection validation, placement parsing, export settings, PNG header check, draft body and response parsing, error text, `links.ts` for console links, and in `library.ts` the artwork, image page, rendition choice, layer name, insert link, label, and preference rules, and in `marker.ts` the placement marker). It must run in the sandbox too, so avoid browser-only globals such as `URL`. `http.ts` holds the timeout and retry rules. `protocol.ts` defines the main and UI messages, `parseUiMessage`, main's shape check, and `toastText`.
- `tests/shared.test.mjs` covers the compiled shared modules and checks that `manifest.json` and the origin picker list the same origins as `connection.ts`. `tests/plugin.test.mjs` bundles `code.ts` and `ui/main.ts` with esbuild and runs them in `node:vm` with the fake `figma`, DOM, console, and `fetch` from `tests/fakes.mjs` (not a test file itself). The fake `fetch` honours `AbortSignal` and answers `GET /api/token` for a token `saveConnection` typed (or `console.identity`), else 404 as an older console does; animation frames run at once unless a test sets `manualFrames`; fake elements report their `tagName` (fields and selects) and, for the connection settings, `contains()`, and have a `style` object and empty boxes (`getBoundingClientRect`), so the UI measures nothing; the fake `figma` also records `notify` options, `commitUndo`, `triggerUndo`, `openExternal`, `ui.resize`, relaunch data, root plugin data, `clientStorage.deleteAsync`, and answers `findAllWithCriteria` and `drop`. `tests/contrast.test.mjs` runs `scripts/contrast.mjs` over `tests/fixtures/figma-theme.json` (Figma's documented light and dark variables). `scripts/e2e-local.mjs` reuses those fakes with Node's real `fetch` against a running local console. `scripts/ui-browser.mjs` is the browser suite: dependency-free DevTools protocol over `--remote-debugging-pipe`, `node:test`, and an in-page fake main thread and console (previews are real PNGs in each image's proportions, so screenshots show contained art over the checkerboard); it is not a Figma run. A page opened with a `theme` gets Figma's variables and `figma-dark`/`figma-light` class from the fixture; `ASSETLIB_SCREENSHOTS=<dir>` writes every state in both themes there (for review; never commit them).
- `dist/`, `.test-build/`, and `graft/` are generated and gitignored. Don't edit or commit them.
- `WORKSTREAM-G-REPORT.md` is a historical implementation report, not instructions.

## Invariants

- **Read and draft only.** Under `/api/apps/{orgId}/{appId}/` the plugin calls `GET placements`, `GET placements/artwork`, `GET assets`, `GET assets/{assetId}/renditions/{sha256}`, and `POST drafts`, nothing else; outside an app it calls only `GET /api/token`, which tells a pasted token its own organization, app, names, and scopes. Every request goes through `src/ui/http.ts`: `send()`, whose `appUrl` refuses any other path, and `identify()`, whose `tokenUrl` builds only `{origin}/api/token` for the two allowed origins. Don't call `fetch` anywhere else. Console links (**Open console**, **View in console**, **Open in console**) are browser navigations built by `consoleLink` from validated IDs on the connected origin, never carrying the token; main's `notify` opens a toast button's URL with `figma.openExternal` only when `isConsoleLink` accepts it for the current connection. Insert and Send both require a token with the `draft` scope. Never add a publish, release, or restore call, never ask for a broader scope, never call the public delivery routes, and never accept a Figma token in its place.
- **Rendition URLs are built from validated ids, never taken from a response.** `renditionUrl` takes a uuid asset id and a 64-hex sha256; the `url` field the console sends is ignored. The bearer token must never go to a URL that came from a response body.
- **Inserted frames carry pluginData `assetlib.link.v1` without the token.** It names the origin, organization, app, cell, environment, asset, and the frame's own node id. `reportSelection` uses it only when no client storage target exists, and only when its node id equals the selected node's id (a Cmd+D copy keeps the data with another id) and the origin (legacy host mapped to production), organization, and app match the connection. A Sync of a linked frame binds exactly the cell it was inserted from; the draft wire shape is unchanged.
- **Placement art is a component carrying a marker.** An insert from a placement creates a component; a library image stays a frame. Either takes layers inside without changing its node id. `placementMarker` writes the component's `description` (the key, the declared size, and an instruction to use the generated accessor instead of exporting the image) and one `documentationLinks` entry, `{origin}/w/{orgId}/{appId}/placements` from validated IDs (legacy host mapped to production). Figma's MCP server returns both to coding agents in `get_design_context`, and returns neither shared nor private plugin data (tested live on October 11, 2026). Anyone with the file reads them, so never put the token, or anything beyond the key, size, and console link, in either. The key is the only text from the console in the description, so it must match the catalog's key grammar (`^[A-Za-z][A-Za-z0-9_.-]{0,119}$`) and the size must be two positive integers; otherwise the insert is a plain linked frame with no marker, so a console response can never put its own words into instructions an agent follows. A documentation link Figma refuses is skipped; the insert still succeeds.
- **The `inserted` message carries `connectionGeneration`**, and the UI ignores one that does not match its pending insert. Main rejects an `insert` whose `connectionGeneration` is not current, and the UI drops a download that finishes after a connection change.
- **The `importing` and `exporting` guards are mutually exclusive:** main refuses an insert during an export and an export during an insert.
- **Placements are read, not created.** Placements are declared in the app's repository and synced to the console. The plugin lists them and binds to declared cells (state, appearance, arm). Don't add placement creation or editing.
- **Plugin id.** `manifest.json` carries the Figma-assigned `id`. Without one the plugin loads, but client storage fails with "Cannot access client storage without a plugin ID". Saved connections and sync targets are scoped to that id, so don't remove or change it. If you substitute your own development id (README "Install as a development plugin"), don't commit it.
- **`documentAccess: "dynamic-page"`** is required. Use the async document APIs (for example `figma.getNodeByIdAsync`); the synchronous variants throw under it.
- **Allowed origins** are production `https://console.assetlib.dev` and development `http://localhost:3100`; only these two can be chosen for a connection. They are set in `manifest.json` (`allowedDomains`, `devAllowedDomains`), `src/shared/connection.ts` (`PRODUCTION_ORIGIN`, `DEVELOPMENT_ORIGIN`), the origin `<select>` in `src/ui.html`, both test files, and README. Change them together. Figma rejects IP-literal development domains, so use `localhost`, never `127.0.0.1`. `devAllowedDomains` is not available to a published plugin. Local development needs the console server on port 3100.
- **Legacy production host.** `https://assetlib-console.vercel.app` (`LEGACY_PRODUCTION_ORIGIN`) was the production origin before October 9, 2026. The console still accepts app tokens there, never redirects it, and rejects sign-in and the console's own session API there. `loadSavedConnection` moves a saved connection on that host to `PRODUCTION_ORIGIN` with the same token and `code.ts` saves it back; `reportSelection` still reads sync targets keyed by the legacy origin. It stays in `allowedDomains` so a `dist/` built before the move keeps working. Don't offer it for new connections, don't drop that load path, and don't link people to it.
- **UI message guard.** Figma posts plugin messages from its top window, not from the iframe's direct parent, so `window.onmessage` in `src/ui/main.ts` accepts `event.source` of `parent` or `top`. Narrowing it to `parent` drops every message and the UI stays on "Saving connection…".
- **Main's message guard.** `figma.ui.onmessage` checks each message's shape with `parseUiMessage` before acting, so a malformed one gets a plain error, not a script error; main still validates values with their own messages. Every message main can refuse carries a positive integer `requestId` (`save-connection`, `save-file-url`, `export`, `remember`, `insert`, `match-ratio`, `clear-connection`), main's `error` names it when the message did, and the UI ends only the operation with that id (`failConnection`, which also ends Disconnect, `failSend`, `failInsert`). An error with no id ends nothing. `notify` (a toast) is never refused, so it has none: main shortens its text to 100 characters (`toastText`) and drops a button whose URL is not a console link for the connection. A new refusable message needs a `requestId` and a check in `parseUiMessage`.
- **Requests.** `send()` sends the bearer token only (`credentials: 'omit'`, `redirect: 'error'`). A GET times out at 20 s (plus 15 s per MiB of a listed download) and retries twice, after 1 s and 4 s (or an exposed `Retry-After`, when longer), on a network error, 502, 503, or 504, and on 429 only with an exposed `Retry-After`. A `Retry-After` over 30 s (`MAX_RETRY_AFTER_SECONDS`) stops the retries for any status. A POST (drafts) times out at 30 s plus 15 s per MiB of body and is never retried, because it may have arrived. A new list or search load aborts the previous one (`channel: 'list'`), and a connection change aborts everything (`abortAll`). Callers drop an `aborted` result quietly. Previews and the quiet placements reload pass `retry: false` and keep their own rules.
- **Busy model.** `state.ops` (`connecting`, `sending`, `syncing`, `inserting`, and `loadingList`, the Insert list loading now) replaces a global busy flag. Only actions that conflict wait, through `actionsBlocked()`: Connect, Disconnect, Send, Sync, Insert, Match ratio, and Send's Try again get `aria-disabled` (`setUnavailable`), never the `disabled` attribute, so they keep focus, and their handlers check the same condition (Send and Sync through `actionPlacement`), so a click on an unavailable one does nothing, as on a disabled button. Tabs, lists, search, browse, environment, scale, pickers, the connection fields, and Refresh stay live; a loading list is `aria-busy` and shows skeleton rows or tiles. The running action says so on its own button ("Connecting…", "Sending…", "Syncing…", "Inserting…"). A running operation keeps the status line. State changes call `scheduleRender()` (`scheduleRender(true)` to rebuild the list); one render runs per animation frame, and it puts focus back on the same control, its rebuilt row, or the search field or current tab, never the page (`checkVisibility` also catches a control in a closed `<details>`). Code that hides a focused control outside a render moves focus first: `closeSettings` renders (so a connection made on the first-run screen has its chip) and moves focus to `#settings-summary`, the account chip, and `clearError` asks for a render when the error or its action had focus. On the first-run screen the fallback is the token field. Use `flushRender()` only to measure or scroll the result in the same task.
- **Connection generation.** Every `connection` and `selection` message carries `connectionGeneration`. The UI ignores selection replies from an older generation, and saving a connection clears the remembered binding and sets the generation aside (null) until main answers, so a slow storage read cannot rebind another app's artwork. A pasted token is identified (`GET /api/token`) before the save starts; until then the old connection stands, and a connection message makes that identification stale (`identifyTicket`). If main refuses the save (a client storage error, say), the old connection stands: `failConnection` puts back the generation, the Send placements, and the typed token; main reports the selection again after the error; and `connectionKept` reloads the Insert list in view when a load ended unseen during the wait or a Refresh, search, or Load more was asked for meanwhile, keeping loaded rows and the choice otherwise. The error stays under the token field. Any new main-to-UI message that depends on the connection needs the same check. `tests/plugin.test.mjs` covers app switches, token rotation, and refused saves.
- **Export bounds and limits.** `chooseExportSettings` exports PNG with `useAbsoluteBounds: true`, constrained to the placement's width, or its height when the node is proportionally taller. `buildDraftBody` rejects settings that no longer match the node and placement. Send and Sync stay disabled while the node's ratio differs from their placement's by more than 2% (`aspectMismatch`); **Match ratio** (`match-ratio`) keeps the width, sets the height with `matchedHeight` after fixing a hug or fill height (put back if the resize throws), and calls `figma.commitUndo()` before and after the resize so it is one undo step of its own. Main reports the selection again, throttled to 150 ms, on a `PROPERTY_CHANGE` to the selected node, re-registering on `currentpagechange`, so the gate never acts on a stale size. Before upload the UI also reads the PNG IHDR and stops if the aspect ratio differs from the placement by more than 2%. Size limits are 4 MiB decoded PNG (`MAX_IMAGE_BYTES`) and a 4,500,000-byte JSON body (`MAX_BODY_BYTES`), Vercel's request limit, so a base64 PNG above about 3.3 MB decoded does not fit.
- **Wire shapes.** `DraftBody` (`schemaVersion: 1`) and the placements, artwork, image page, and draft responses in `src/shared/types.ts` match the hosted console's API. Change them only together with the console.
- **Previews** of list rows and tiles load only for images the `IntersectionObserver` reports within `300px` of the list's view (its `root` is `#list-region`, the scroll container; an explicit root also keeps the margin in Figma's cross-origin iframe, where the implicit root ignores it), at most three at once, newest first. The footer's image is outside the list, so it loads whenever it shows; jobs whose images scroll away or leave the list before starting are dropped. Network errors and 5xx retry at 1 s and 4 s, 429 pauses all previews for 15 s, and Refresh clears failed previews. Previews never use the error line.
- **First run and the token form.** Without a connection the plugin shows only the first-run screen, which is the open `#settings` (render keeps it open; Esc closes the settings only with a connection). A typed token must match `alk_` and 43 base64url characters (`checkTokenFormat`), checked before anything is sent; saved connections are not checked again, so older saves load. With the ID fields hidden, Connect asks `GET /api/token` (tried once) and saves the connection it names, with `workspaceName` and `appName` when the console returns them; a 401 or 403 is the token field's error, a token without the `draft` scope too, and a 404 or a network failure (an older console without the route or its CORS headers) shows the organization and app ID fields under `OLDER_CONSOLE` (`askForIds`), which the form then uses. That is a step, not a mistake: `#connection-error` becomes a neutral `.info` notice, announced through `#status`, no field is marked invalid, and the organization ID takes focus; any later form error puts back the `.error` callout. The ID fields belong to that console (`idsOrigin`): they show, and the form uses them, only while it is the chosen one; choosing another console hides them and clears a form error about the first, and a connection message without a connection (Disconnect) forgets it. A blank token tests the saved connection again on its own console. Disconnect (`clear-connection`) deletes `assetlib.connection.v1`, bumps the generation, and main toasts that the token still works elsewhere. Without names from the console, the chip and the panel name the app by the start of its ID (the panel's title has both IDs on hover), and the Connected toast says "Connected to Assetlib", never two raw IDs.
- **Connection state.** A failed read never opens the connection settings: `needsAttention` shows the chip's warning glyph and, for a failed connection test or a refused token on a list read, keeps the reason in `#connection-error` under the token field (a `read` error, marking the token for a 401 or 403), where it shows whenever the settings are open. Each failure is said once (`problemInSettings`): while the settings are open and hold a read error, they say it (announced, and the token field focused unless focus is in a field, `inField`), and the view's own copy steps aside; otherwise the view in front says it. A failed connection test (`state.testFailure`) is said by the Insert list in `#insert-empty` (`listUnavailable`) and by Send's `#send-problem` above the Placement field, each with one action from `readProblem`: Try again (on Send it runs the test again, `testConnection` in `main.ts`) or Update token (`openSettings`, at the token field). The view in front announces it and takes focus unless the person is in a field; the other keeps it for when it shows. Any successful authenticated read (placements, artwork, assets, rendition) sets the label to connected and clears the read error and `testFailure`; it never closes the settings. A passing connection test closes them, unless the person works in them (`settingsInUse`; the fields stay live during the test): focus is in one of their fields that it moved to after the test started (`focusMark`; the field they submitted from, or one the code focused, does not count), or a token is typed or the origin, organization, or app differs from the saved connection. After a failed connection test it first reads placements again quietly (`reloadPlacements`, tried once and at most once per 15 s), so Send never sits without them under a connected label. A preview that started before the last failed read (`attentionCount`) does not count. Form errors (the answer to the person's submit) also render in `#connection-error`, marking and focusing the field at fault (`connectionErrorField`). Other errors (`showError`) show in `#error` inside `#error-box`, the fixed line above the footer, with at most one action button (`#error-action`: Refresh after an image was removed); they scroll into view and take focus, except from a field the person is in (`inField`: an input, select, or textarea, such as the token, file link, or search), which keeps focus and is scrolled back into view. A list that can't load is not an `#error`: its reason and one action (Try again, Update token, Go to Send) replace the list in `#insert-empty`, which takes focus unless the person is in a field; a failed Load more keeps its pages and uses `#error`. **Connect** is `primary` only on the first run and while the connection needs attention, so the footer's Insert or Send is the one ink primary otherwise.
- **Live regions and toasts.** `#status` (role=status) and `#alert` (role=alert) are fixed in the DOM and visually hidden. Every error is announced through `#alert` (`announceError`), and every toast and result through `#status`. Finished operations are Figma toasts (`notify`, at most 100 characters): Inserted (main), Sent and Synced (with Review, a link to the console's releases), Connected, and Disconnected (main). A 409 partial result shows its notice and link inline, with no success toast.
- **HTTP 409** on a draft can still mean the asset was created. Keep showing the partial result and the console's message.
- **Token handling.** The token goes only as a bearer header to the chosen origin, with `credentials: 'omit'` and `redirect: 'error'`. Never log it, put it in a URL, or display more than `tokenPrefix()`.
- **Storage keys** `assetlib.connection.v1` (now with optional `workspaceName` and `appName`), `assetlib.file-url.v1`, `assetlib.target.v1:…`, and `assetlib.preferences.v1` (tab, browse mode, environment, scale, and the optional `window` and `hintSeen`, absent unless set; the default tab is Insert) hold users' saved state in client storage. Renaming them silently drops saved connections, sync targets, and preferences. Stored sync targets keep their original shape; `insertedFrom` is derived from a link, never stored.

## Dependencies and versions

Dev dependencies are exact pins: `@figma/plugin-typings` 1.117.0, `typescript` 5.9.3, `esbuild` 0.25.12. README records why each version was chosen; keep pins exact and update that table when one changes. Every lockfile entry has its registry `resolved` URL and `integrity` hash; keep it that way so `npm ci` verifies each package.

`package.json` is `private` at version 0.1.0 and nothing else reads that version. The plugin runs as a Figma development plugin and is not published to the Figma Community (as of 2026-10-09). There are no release tags. Ask the maintainer before any publication step.

## Writing rules

- The product is "Assetlib" in prose and UI copy. `AssetLib` is only the GitHub org slug.
- UI and error text is plain and says what to do next (see `src/shared/errors.ts`), following §4.6 of the parity plan: no HTTP codes except "Assetlib had a problem ({status})", no manifests, PNG chunks, node IDs, or "update the console". No overstated claims such as "instantly". No emojis. Don't describe a feature before it ships (the hint bar's drag and Enter copy waits for A.4 and A.6).
- Visual tokens: colours only from Figma's `--figma-color-*` variables with brand fallbacks; meta text is `--al-text-meta` (text at 70%), never `text-secondary` or `text-tertiary`; vermilion is only the focus ring. `npm run contrast` must pass after any colour change, and it refuses a text colour it does not measure. Figma's `bg-hover` and `bg-pressed` equal `bg-secondary` in both themes, so hover never relies on them over a `bg-secondary` surface: a hovered secondary button steps to `bg-tertiary`, and a hovered tab or segment turns to ink without a fill. A neutral step (an older console's IDs) is an `.info` callout with an ink icon, never a warning or danger one. Controls inside a callout (`.notice`, `.error`) sit on `bg` with a `border`, never on the callout's own `bg-secondary`; `npm run test:browser` checks every one in both themes.

## Don'ts

- Don't add a publish or release path, or any network origin beyond the production, legacy production, and development origins above.
- Don't send anything beyond what README "Data and network access" lists. Never send the Figma document or a Figma token.
- Don't commit `dist/`, `.test-build/`, `graft/`, or a changed plugin id.
- Fix a confirmed defect you find in the same change, with a test. Defer only when a fix is unsafe now, and say when it will happen.
