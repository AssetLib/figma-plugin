# AGENTS.md

Public repository `AssetLib/figma-plugin`: Assetlib for Figma. A Figma design plugin that inserts an app's placement artwork as image-filled components and library images as image-filled frames (or, by the selection, into a container, or fills or replaces the selected layers' images; or where a row or tile dragged onto the canvas lands), sends one selected node to an Assetlib placement as a draft, then re-syncs that node's later edits. It calls the hosted console's token identity, placements, artwork, image library, rendition, and drafts endpoints with an app-scoped `draft` token. Publishing stays in the console; this plugin never publishes. TypeScript, bundled with esbuild, no runtime dependencies. See README for install, connection, and data handling.

## Commands

Node.js 22 or later (`engines` in `package.json`; `.nvmrc` is 24).

```sh
npm ci
npm run typecheck   # tsc for the main thread (tsconfig.json) and the UI (tsconfig.ui.json); no emit
npm test            # scripts/test.mjs: compiles src/shared to .test-build/, then node --test tests/*.test.mjs
npm run build       # scripts/build.mjs: minified dist/code.js and a self-contained dist/ui.html (over 160 KB, 160,000 bytes, it fails and writes none)
npm run verify      # typecheck, test, build
npm run test:browser  # build, then scripts/ui-browser.mjs drives dist/ui.html in headless Chrome (CHROME_PATH to choose one)
npm run watch       # build --watch: unminified with inline source maps, rebuilt on every change (build --dev builds once)
npm run contrast    # scripts/contrast.mjs: every text colour pair in Figma's light and dark themes (npm test runs it too)
npm run e2e:local -- --connection <file>   # live local console; not part of npm test (README "Development and verification")
```

CI (`.github/workflows/verify.yml`) runs `npm ci`, `npm run verify`, and `npm run test:browser` on Node.js 22 and 24. There is no lint script. `npm run verify` and `npm run test:browser` must pass before work is done. They cannot exercise real Figma exports, client storage across restarts, console CORS, or authenticated draft and rebind behavior. `npm run e2e:local` covers the token-only connect (`GET /api/token`), the authenticated reads, inserts, the draft round trip, and CORS preflights against a local console, still without real Figma; a change touching Figma behavior also needs a manual run in Figma desktop against a console (README "Development and verification").

## Layout

- `manifest.json`: Figma manifest. Plugin `id`, `main: dist/code.js`, `ui: dist/ui.html`, `documentAccess: "dynamic-page"`, `enablePrivatePluginApi` (a development or organization-private plugin gets `figma.fileKey`; a Community build can't have it, and parity plan D removes it), `relaunchButtons` (`sync`, "Sync to Assetlib"; `open`, "Open Assetlib"), network allowlist.
- `src/code.ts` and `src/main/`: the main thread in Figma's sandbox. No DOM and no HTTP here. `code.ts` is the entry: it routes and checks the UI's messages (and hands Figma's `drop` events to `insert.ts`), keeps the connection and preferences in `figma.clientStorage`, exports for Send (`exportAsync`) and links the sent layer (`linkSent`), saves a pasted file link, runs Match ratio, sizes the window (`resize`, `reset-size`), tells the UI it was opened from a relaunch button (`launch`), and watches the selection (and the current page's `nodechange`, so a resize on the canvas reaches the UI and a later edit to filled layers retires a fill's Undo). `main/selection.ts` reports the selection, with sync targets, the layer's link (`link`: linked, a copy, or another app's), the file key and where it came from (`file`), and `insertTarget` (what Insert does with it), and writes links (`writeLink`, with the layer's relaunch button). `main/identity.ts` is the document's identity: the file key (`fileIdentity`, `currentFileKey`), a pasted link (`linkFile`), and `markDocument`. `main/insert.ts` inserts image components for placement art and frames for library images (`createImage`, `createComponent`, `createFrame`, pluginData), into a container or beside the selection, fills and replaces, and answers drops (`drop`: a placeholder where a dragged row or tile lands, or the image frame it lands on, which the drop's insert fills). `main/state.ts` holds what they share (the connection, its generation, the `importing` and `exporting` guards, `post`). They import in one direction, `code` → `insert` → `selection` → `identity`, `state` (any may skip levels).
- `src/ui.html` and `src/ui/`: the UI iframe and every HTTP call. `ui.html` is the app shell: a first-run screen without a connection; otherwise a top bar (tabs, and the account chip, which is the `#settings` details' summary and opens the connection settings below the bar), the view (Insert: search, scope bar, and `#list-region`, the only part that scrolls; Send: its form), then the fixed `#messages` error line (`#error-box`: the `#error` text and at most one `#error-action`), the `#selection-bar` (the Sync bar, both tabs), the `#hint-bar` (Insert, nothing chosen, until the first insert), and the footer of the view in front. `main.ts` is the entry: it routes main's messages, registers the renderer, and runs the resize grip (`#resize-grip`). `http.ts` makes every console request; `connection.ts` (form, connection test, label, and `fitWorkspace`, which sizes the chip's shortened workspace name to its ellipsis so the spaces around "·" match), `send.ts` (Send tab, the file link, and Sync, whose bar state is `syncBar()`), `syncbar.ts` (the Sync bar's DOM, the relaunch focus, and Cmd+Enter), `insert.ts` (Insert tab, its downloads, and dragging rows and tiles onto the canvas), and `thumbnails.ts` (previews) own their state and DOM; `state.ts` holds what more than one of them reads, including `ops`; `dom.ts` holds element, error, render-scheduling, and focus helpers, and `post` and `postDrop`, the only ways to message Figma. Modules import in one direction, `main` → `syncbar` → `insert` → `thumbnails` → `connection` → `send` → `dom`, `http`, `state` (any may skip levels); keep it acyclic. `ui.html` must contain exactly one `<!-- ASSETLIB_SCRIPT -->` marker, where the build inlines the bundled UI script, and one `/* ASSETLIB_FONT */` marker, where it inlines Instrument Sans as a base64 `@font-face`; a release build first drops the template's CSS and HTML comments and indentation (`compact` in `scripts/build.mjs`), so keep `/*` and `<!--` out of anything but comments, and no `<pre>` or `<textarea>`. `src/image.ts` is browser-only (WebP to PNG through a canvas) and is imported by `src/ui/insert.ts` only.
- `src/assets/`: `instrument-sans-variable.woff2` and its licence `OFL.txt`, copied from the workspace's `brand/` by `sh brand/sync.sh`. Don't hand-edit them; change the brand source and sync.
- `src/shared/`: pure logic used by both sides (origin, token, and connection validation, file links and the document identity in `connection.ts` (`parseFileLink`, `slugify`, `linkNamesFile`, `parseFileIdentity`), placement parsing, export settings, PNG header check, draft body and response parsing, error text, `links.ts` for console links, and in `library.ts` the artwork, image page, rendition choice, layer name, insert link (`linkInApp`, `linkMatches`), relaunch description (`syncDescription`), label, preference, and window size (`clampWindow`, `defaultWindowSize`) rules, and in `marker.ts` the placement marker). It must run in the sandbox too, so avoid browser-only globals such as `URL`. `http.ts` holds the timeout and retry rules. `protocol.ts` defines the main and UI messages, `parseUiMessage`, main's shape check, and `toastText`.
- `tests/shared.test.mjs` covers the compiled shared modules and checks that `manifest.json` and the origin picker list the same origins as `connection.ts`. `tests/plugin.test.mjs` bundles `code.ts` and `ui/main.ts` with esbuild and runs them in `node:vm` with the fake `figma`, DOM, console, and `fetch` from `tests/fakes.mjs` (not a test file itself). The fake `fetch` honours `AbortSignal` and answers `GET /api/token` for a token `saveConnection` typed (or `console.identity`), else 404 as an older console does; animation frames run at once unless a test sets `manualFrames`; fake elements report their `tagName` (fields and selects) and, for the connection settings and the file link form, `contains()`, and have a `style` object and empty boxes (`getBoundingClientRect`), so the UI measures nothing; `dispatch(type, init)` passes an event with `target` and `preventDefault` and returns it, and `keydown(init, listener)` delivers a key press to the element whose listener handles it (the list, for a row) and then, unless prevented, to the document (`navigator.platform` is `MacIntel`); the fake `figma` also records `notify` options (and whether a toast was cancelled), `commitUndo`, `triggerUndo`, `openExternal`, `ui.resize` (`uiResizes`; it also sets the UI window's `innerWidth` and `innerHeight` and calls its `resize` listener), `showUI`'s options and each `ui.show` (`uiShown`), `viewport.zoom`, relaunch data (`relaunches`, with the document as `0:0`), root plugin data (seeded with `rootPluginData`; `readOnlyRoot` refuses writes, as a view-only file; `rootName` names the document), `clientStorage.deleteAsync`, and answers `findAllWithCriteria`; `command` sets `figma.command`; a `pluginDrop` the UI posts is kept in `pluginDrops` (it is Figma's, never a plugin message), `dropOnCanvas({ node, absoluteX, absoluteY })` turns the last one into main's drop event as Figma would, `drop(event)` delivers any drop event, `close()` closes the plugin, and `dataTransfer()` makes a dragstart's DataTransfer that records its data and drag image; fake elements keep pointer capture (`setPointerCapture`, `hasPointerCapture`, `releasePointerCapture`) for the grip. Its nodes come from plain specs: `children` specs become child nodes with a `parent`, `x` and `y` are relative to a parent frame and `absoluteBoundingBox` adds the parents', `appendChild` and `remove` move them, and, as Figma is expected to, a layer inside an instance (an id with `;`) refuses plugin data, an instance or a layer inside one refuses children, and a component refuses to go inside a component, component set, or instance, or anything inside one (`refusePluginData` and `refuseChildren` make any node refuse). In `tests/plugin.test.mjs`, `openInsert` clears the selection (nothing selected makes a new frame) unless given `{ keep: true }`. `tests/contrast.test.mjs` runs `scripts/contrast.mjs` over `tests/fixtures/figma-theme.json` (Figma's documented light and dark variables). `scripts/e2e-local.mjs` reuses those fakes with Node's real `fetch` against a running local console. `scripts/ui-browser.mjs` is the browser suite: dependency-free DevTools protocol over `--remote-debugging-pipe`, `node:test`, and an in-page fake main thread and console (previews are real PNGs in each image's proportions, so screenshots show contained art over the checkerboard); it is not a Figma run. A page opened with a `theme` gets Figma's variables and `figma-dark`/`figma-light` class from the fixture; `ASSETLIB_SCREENSHOTS=<dir>` writes every state in both themes there (for review; never commit them).
- `dist/`, `.test-build/`, and `graft/` are generated and gitignored. Don't edit or commit them.
- `WORKSTREAM-G-REPORT.md` is a historical implementation report, not instructions.

## Invariants

- **Read and draft only.** Under `/api/apps/{orgId}/{appId}/` the plugin calls `GET placements`, `GET placements/artwork`, `GET assets`, `GET assets/{assetId}/renditions/{sha256}`, and `POST drafts`, nothing else; outside an app it calls only `GET /api/token`, which tells a pasted token its own organization, app, names, and scopes. Every request goes through `src/ui/http.ts`: `send()`, whose `appUrl` refuses any other path, and `identify()`, whose `tokenUrl` builds only `{origin}/api/token` for the two allowed origins. Don't call `fetch` anywhere else. Console links (**Open console**, **View in console**, **Open in console**) are browser navigations built by `consoleLink` from validated IDs on the connected origin, never carrying the token; main's `notify` opens a toast button's URL with `figma.openExternal` only when `isConsoleLink` accepts it for the current connection. Insert and Send both require a token with the `draft` scope. Never add a publish, release, or restore call, never ask for a broader scope, never call the public delivery routes, and never accept a Figma token in its place.
- **Rendition URLs are built from validated ids, never taken from a response.** `renditionUrl` takes a uuid asset id and a 64-hex sha256; the `url` field the console sends is ignored. The bearer token must never go to a URL that came from a response body.
- **Inserted, filled, replaced, and sent layers carry pluginData `assetlib.link.v1` without the token** (sent layers since parity plan A.7, pending the founder's review). It names the origin, organization, app, cell, environment, asset, and the layer's own node id; a fill of several layers links each with its own id. After a Send or Sync the console bound (`remember` carries the draft's `assetId`, null for a 409 or an unbound draft), main writes the link with `environment: 'draft'`, that asset, and the send time, and a component's marker for that placement (`writeMarker`, with the placement's declared size kept in `exported`), as an undo step of its own (`linkSent`, after `retireUndo`), so teammates and other devices find it. Every plugin edit that is a step of its own (a Send's link, a file link) goes through `commitOwnStep`, which commits nothing while a drop's placeholder waits (`dropPending`), so that drop's insert commits the placeholder and its image as one step. `writeLink` (in `selection.ts`) also gives the layer one `setRelaunchData({sync: syncDescription(link)})` call (its cell and environment, at most 1000 characters; a refusal keeps the link) and runs `markDocument`. Placement art only: a library image never writes or removes a link, so a linked layer filled with one stays linked to its cell. Layers inside an instance (an id with `;`, `insideInstance`) are filled but never linked, because Figma keeps no plugin data there; `writeLink` skips them and catches a refusal from any other layer, which then stays unlinked without failing the insert. `reportSelection` uses it only when no client storage target exists for the layer on this device, and only when its node id equals the selected node's id (a Cmd+D copy keeps the data with another id) and the origin (legacy host mapped to production), organization, and app match the connection. A fill or replace that writes a link deletes the layer's stored targets in this file (`dropStoredTargets`, current and legacy origin), so Sync follows the relink instead of a target an earlier Send or Sync stored; before the file key is known, or after a storage failure, `reportSelection` ignores those targets until it can delete them. A later Send or Sync stores a new target (`storeTarget`), which wins again. A target another device stored stays there until that device sends the layer again. A Sync of a linked frame binds exactly the cell it was inserted from, or last filled or replaced with; the draft wire shape is unchanged.
- **Placement art is a component carrying a marker.** An insert from a placement creates a component; a library image stays a frame. Either takes layers inside without changing its node id. `placementMarker` writes the component's `description` (the key, the declared size, and an instruction to use the generated accessor instead of exporting the image) and one `documentationLinks` entry, `{origin}/w/{orgId}/{appId}/placements` from validated IDs (legacy host mapped to production). Figma's MCP server returns both to coding agents in `get_design_context`, and returns neither shared nor private plugin data (tested live on October 11, 2026). Anyone with the file reads them, so never put the token, or anything beyond the key, size, and console link, in either. The key is the only text from the console in the description, so it must match the catalog's key grammar (`^[A-Za-z][A-Za-z0-9_.-]{0,119}$`) and the size must be two positive integers; `validateInsertLink` refuses any other key (`validPlacementKey`), so an insert, fill, drop, or a Send's link never carries one into a marker, relaunch text, a layer name, or a toast, and a console response can never put its own words into instructions an agent follows; a size that isn't two positive integers makes a plain linked frame with no marker. A documentation link Figma refuses is skipped; the insert still succeeds. A fill, replace, or Send with placement art (`writeMarker`) rewrites a component's description and documentation link only when the description is empty or a marker (`isPlacementMarker`), so a relinked component names its new placement and a description the designer wrote is never changed. The same relink renames a layer still named for the placement its link named (the key, or the key then ` · `; `renameRelinked`) to the new cell's layer name (`layerName`); a name the designer gave it stays.
- **Insert follows the selection.** `reportSelection` classifies the current selection on every report (`classifyInsertTarget` in `library.ts`, `selection.insertTarget`): one shape, frame, component, or instance with a matching link is **replace** (a linked text, group, line, or section, which a Send links, takes no image and is classified as any other layer); a `FRAME` or `COMPONENT` with children, not inside an instance, is **into** (Figma gives an instance no new children, so an instance with children is not a container), with `insideComponent` when it is a component or sits inside a component, component set, or instance (`inComponent` in `selection.ts`); shapes and childless frames, components, and instances are **fill** (other layers are skipped); otherwise **new**. The footer's primary takes its `label` ("Insert", "Insert into {name}", "Fill {name}", "Fill {n} layers", "Replace image"), hides the scale for fill and replace, and offers **Insert as new frame** (`#insert-new`) in the other modes; into a container narrower than the new frame, `#insert-note` names a scale that fits. Figma puts no component inside a component, so with `insideComponent` and placement art that main inserts as a component (`placementMarker` accepts its key and size), the UI treats the target as **new** ("Insert", beside the container) and `#insert-note` says why (`besideComponent`); a library image, a frame, still goes in. Main refuses placement art into such a container before creating anything; the fake's `appendChild` refuses a component there too. The UI captures the destination when Insert is chosen (`insert.target`: `new`, `into` with the container, or `fill` with the layers); main checks it still names the selection (`stillSelected`) and otherwise refuses with "The selection changed. Check it and try again." and reports the selection again. A new layer goes into the container (centered, or appended to auto layout; removed again if Figma refuses the child), else 40 px right of the selection's page bounds, else centered in the view, and is selected. A fill replaces each layer's topmost `IMAGE` paint with the new hash, keeping every other field of that paint, or appends `{type:'IMAGE', scaleMode:'FILL'}`; other paints, size, position, and constraints stay. New layers download `insertRendition` (the largest); fill and replace download `fillRendition` for the width the art is drawn at, `max(containerWidth, containerHeight × art width / art height)` over the widest and tallest layers. Every insert, fill, and replace ends with exactly one `figma.commitUndo()`, after all its edits and never before them, so it is one undo step. A fill's or replace's toast has **Undo** (`figma.triggerUndo()`), which runs only while the toast is current and every layer it filled keeps the paints, name, and component description the fill left (`snapshot`), and then reports the selection again (the link Undo puts back changes no selection), else says "Not undone"; the toast is cancelled (`retireUndo`) when the selection or the page changes, another insert or drop starts, Match ratio, a Send's link, or a file link is written, or a local `nodechange` anywhere on the page is a creation, a deletion, or a change beyond the fill's own `fills`, `backgrounds`, `fillStyleId`, `pluginData`, `description`, `documentationLinks`, and `name` (`retireUndoOnEdit`), or one of those on a layer other than a filled one, an instance, or a layer inside one (a filled component's instances follow it), so its Undo never takes back a later edit, such as another layer hidden or locked in the layers panel. A marker Figma refuses (`writeMarker`, description or link) never fails the fill.
- **Drag to canvas.** A row or tile is `draggable` when Insert could insert it now (`canDrag`: connected, and its item has a version Figma can take; the chosen row drags the cell its pickers show, and `renderInsertBar` gives the row chosen before (`dragFollows`) its base cell's again), so Not set, Unavailable, Needs re-upload, and over-4-MiB items stay put, and its thumbnail `<img>` is never draggable itself. `dragstart` refuses while an action waits (`actionsBlocked()`, a pending insert or drop), sets the data (`application/x-assetlib-item`, the key, which no field in the panel takes), the `.thumb` as the drag image, and starts the insert download (`download`: `insertRendition`, as PNG bytes, kept by sha256 while it runs and for 60 s after it finishes, at most three, per connection generation; a drop, another drag, or an Insert of that version reuses it, an Insert still saying when it converts a WebP, and a failed one is forgotten). `dragend` does nothing when `event.view.length === 0` (Figma's check: the drag ended in the plugin window); otherwise `postDrop` posts `{pluginDrop: {clientX, clientY, files: [], dropMetadata}}` (no `pluginMessage`, as Figma documents it), with `dropMetadata` `{assetlib: 1, dropId, connectionGeneration, name, frame, scale, link}` (`DropMetadata`, never the token), and Insert waits (`ops.inserting`). Main's `drop` returns undefined for any drop without `dropMetadata.assetlib === 1`, so a file from the desktop keeps Figma's behaviour, and false for every Assetlib drop: one that doesn't parse (`parseDropMetadata`), names an older `connectionGeneration`, arrives while an insert or export runs or another drop waits, or carries a size or link main refuses is refused with an `error` naming `dropId`; a drop newer than the one main holds means the UI gave up on that one (it waits for one at a time), so its placeholder goes and the newer drop is taken. Main refuses an export and Match ratio while a drop waits (`dropPending`). Otherwise, if `e.node` is an image frame (an `IMAGE` paint and no children, or linked to this app), main selects it and the drop replaces its image through the fill path; else it makes a placeholder named "{name} · loading", sized as Insert would at the drop's scale, filled `#EEF0F3`, a component for placement art with a marker (as Insert makes it), inside `e.node` when that is a frame, group, section, or component outside an instance (for placement art, not in or inside a component), else on the page, centered on (`absoluteX`, `absoluteY`) unless an auto layout parent places it, and selected; and posts `dropped` `{dropId, nodeId, connectionGeneration}`. Main holds one pending drop (`drops`). The UI fills it with an `insert` naming the drop (`drop: dropId`, `target: {kind:'fill', nodeIds:[nodeId]}`); main then skips the selection check, fills a placeholder with the image alone, renames, marks, and links it (or fills the image frame as Fill does), and commits once, so the placeholder and its image are one undo step (the drop itself never commits). A placeholder deleted before its image arrives fails the drop's insert with "The placeholder was deleted before its image arrived. Drag the image again." A placeholder whose image never comes goes: main removes it when the drop's insert fails, on `discard-placeholder` (the UI's download failed, or `dropped` came after the UI stopped waiting, `DROP_REPLY_MS`, 5 s, the time a drag that ended off the canvas waits for nothing), on a connection change (`discardDrops`), and when the plugin closes. `discard-placeholder` removes only a placeholder main made and still holds, never another layer. The hint bar ("Drag onto the canvas, or select an item and press Enter.", `.hint-narrow` "Drag onto the canvas or press Enter." below 400 px) shows on the Insert tab with rows or tiles, nothing chosen, and no Sync bar, until the first successful insert or drop, or its Close, sets `hintSeen`. Draggable rows and tiles show `cursor: grab`.
- **The Sync bar** (`#selection-bar`, `syncbar.ts`, from `syncBar()` in `send.ts`) shows on both tabs whenever the selection is linked or remembered: `linked` ("Linked to {key}", meta "{declared axes} · from {Environment}" (Draft for a stored target), the linked image's preview from the Insert artwork (`linkedArt`), **Open in console** when the layer's own link names this cell, and **Sync to draft**); with the ratio more than 2% off, the meta is the ratio sentence and **Match ratio** (`sync-match`) shows, unless the Send tab's callout names the same placement; `removed` (its placement or cell is gone once the placements loaded: "Linked to {key}", meta "This placement (or cell) no longer exists in this app.", **Send elsewhere…**); `copy` (`link.kind` copy: **Send…** prefills the Send tab with its link's cell, for a Send without rebind); `other` (another app's link: "Linked to another workspace", meta "Connect to that workspace to sync it."). The title never holds a sentence; the meta, three lines at most, says why. The ratio meta is "This frame is {w} × {h}; {key} is {W} × {H}. Match ratio makes it {w} × {h′}." (`sizeLabel` keeps each size whole with no-break spaces), and while the ratio blocks Sync, **Match ratio** is the bar's primary (unless the Insert footer shows). `#sync-preview` hides when there is no image to show. Focused itself (launched with no action to press), the bar shows its ring inside it. Sync is `primary` unless the Insert footer shows or the ratio blocks it. **Cmd+Enter** (Ctrl+Enter off Apple platforms) is Sync while the bar offers it, except inside `#settings`. The Send footer has only **Send to draft**, secondary while a usable target exists. Opened from **Sync to Assetlib** (`figma.command === 'sync'`), main posts `launch` and the bar focuses its first action (or itself) once the current selection arrives; it never syncs by itself. The document gets **Open Assetlib** relaunch data once it has a link (`markDocument`).
- **Document identity.** The file key is Figma's (`figma.fileKey`, valid only), else a link pasted this session that the document refused (view-only), else root pluginData `assetlib.file.v1` (`{v: 1, fileKey, source: 'figma' | 'link', savedAt, name}`, `parseFileIdentity`). Nothing is written when the plugin opens: `markDocument` saves Figma's key there (when missing or different, as in a duplicated file) with each link written, inside that edit's undo step. Without a key, Send and Sync stay available; choosing one asks for the file's link on the Send tab (`askForFile`, focus in the field) and runs once `file-saved` arrives, if the same layer is selected. `parseFileLink` reads `/file/` and `/design/` links, and a branch's (`/design/{key}/branch/{branchKey}/{name}`) as the branch's key and name. Main compares the link's slug with `figma.root.name` (`linkNamesFile`: `slugify` keeps letters of every script and digits, lower case, one "-" per run of spaces and punctuation; only a non-empty equal pair matches, so a link without a name, or a name of punctuation alone, is questioned too) and answers `file-mismatch` unless `force` (Use anyway; editing the field withdraws it); it retires a fill's Undo and saves the key in the document (`commitOwnStep`) or, refused, for the session (`file-saved` `session: true`, said by `VIEW_ONLY`). A key from the document or session shows "File: {name} · Change". `assetlib.file-url.v1` is still written and read, but fills in the field only when `linkNamesFile` matches it to this file's name; it is never used without the person submitting it. The ask is an `.info` notice (a neutral step) naming Cmd+L, or Ctrl+L off Apple platforms (`COMMAND` in `dom.ts`, which `showError` also applies to main's words).
- **The `inserted` and `dropped` messages carry `connectionGeneration`**, and the UI ignores an `inserted` that does not match its pending insert, and discards the placeholder of a `dropped` that does not match its pending drop. Main rejects an `insert` whose `connectionGeneration` is not current, and the UI drops a download that finishes after a connection change.
- **The `importing` and `exporting` guards are mutually exclusive:** main refuses an insert during an export and an export during an insert, and a drop during either.
- **Placements are read, not created.** Placements are declared in the app's repository and synced to the console. The plugin lists them and binds to declared cells (state, appearance, arm). Don't add placement creation or editing.
- **Plugin id.** `manifest.json` carries the Figma-assigned `id`. Without one the plugin loads, but client storage fails with "Cannot access client storage without a plugin ID". Saved connections and sync targets are scoped to that id, so don't remove or change it. If you substitute your own development id (README "Install as a development plugin"), don't commit it.
- **`documentAccess: "dynamic-page"`** is required. Use the async document APIs (for example `figma.getNodeByIdAsync`); the synchronous variants throw under it.
- **Allowed origins** are production `https://console.assetlib.dev` and development `http://localhost:3100`; only these two can be chosen for a connection. They are set in `manifest.json` (`allowedDomains`, `devAllowedDomains`), `src/shared/connection.ts` (`PRODUCTION_ORIGIN`, `DEVELOPMENT_ORIGIN`), the origin `<select>` in `src/ui.html`, both test files, and README. Change them together. Figma rejects IP-literal development domains, so use `localhost`, never `127.0.0.1`. `devAllowedDomains` is not available to a published plugin. Local development needs the console server on port 3100.
- **Legacy production host.** `https://assetlib-console.vercel.app` (`LEGACY_PRODUCTION_ORIGIN`) was the production origin before October 9, 2026. The console still accepts app tokens there, never redirects it, and rejects sign-in and the console's own session API there. `loadSavedConnection` moves a saved connection on that host to `PRODUCTION_ORIGIN` with the same token and `code.ts` saves it back; `reportSelection` still reads sync targets keyed by the legacy origin. It stays in `allowedDomains` so a `dist/` built before the move keeps working. Don't offer it for new connections, don't drop that load path, and don't link people to it.
- **UI message guard.** Figma posts plugin messages from its top window, not from the iframe's direct parent, so `window.onmessage` in `src/ui/main.ts` accepts `event.source` of `parent` or `top`. Narrowing it to `parent` drops every message and the UI stays on "Saving connection…".
- **Main's message guard.** `figma.ui.onmessage` checks each message's shape with `parseUiMessage` before acting, so a malformed one gets a plain error, not a script error; main still validates values with their own messages. Every message main can refuse carries a positive integer `requestId` (`save-connection`, `save-file-url` (optional boolean `force`), `export`, `remember` (optional `assetId`, a string or null), `insert`, `match-ratio`, `clear-connection`; an `insert` also needs a well-formed `target`, and its optional `drop` must be a request id too), main's `error` names it when the message did, and the UI ends only the operation with that id (`failConnection`, which also ends Disconnect, `failSend`, `failInsert`, `failDrop`, whose id is the drop's `dropId`). An error with no id ends nothing. `discard-placeholder` is never refused, so it has none. `notify` (a toast) is never refused, so it has none: main shortens its text to 100 characters (`toastText`) and drops a button whose URL is not a console link for the connection. `resize` (finite numbers, which main clamps) and `reset-size` are never refused either. A new refusable message needs a `requestId` and a check in `parseUiMessage`.
- **Requests.** `send()` sends the bearer token only (`credentials: 'omit'`, `redirect: 'error'`). A GET times out at 20 s (plus 15 s per MiB of a listed download) and retries twice, after 1 s and 4 s (or an exposed `Retry-After`, when longer), on a network error, 502, 503, or 504, and on 429 only with an exposed `Retry-After`. A `Retry-After` over 30 s (`MAX_RETRY_AFTER_SECONDS`) stops the retries for any status. A POST (drafts) times out at 30 s plus 15 s per MiB of body and is never retried, because it may have arrived. A new list or search load aborts the previous one (`channel: 'list'`), and a connection change aborts everything (`abortAll`). Callers drop an `aborted` result quietly. Previews and the quiet placements reload pass `retry: false` and keep their own rules.
- **Busy model.** `state.ops` (`connecting`, `sending`, `syncing`, `inserting`, and `loadingList`, the Insert list loading now) replaces a global busy flag. Only actions that conflict wait, through `actionsBlocked()`: Connect, Disconnect, Send, Sync, Insert (and Insert as new frame, and a drag, which a drop holds from its `dragend` until its insert ends), Match ratio, and Send's Try again get `aria-disabled` (`setUnavailable`), never the `disabled` attribute, so they keep focus, and their handlers check the same condition (Send and Sync through `actionPlacement`), so a click on an unavailable one does nothing, as on a disabled button. Tabs, lists, search, browse, environment, scale, pickers, the connection fields, and Refresh stay live; a loading list is `aria-busy` and shows skeleton rows or tiles. The running action says so on its own button ("Connecting…", "Sending…", "Syncing…", "Inserting…", `setBusy`), with `aria-busy`, which keeps the ink (at 80%, measured by `scripts/contrast.mjs`) and draws a spinner (none with reduced motion), so it never looks unavailable; `#insert` keeps a 104 px minimum, so its busy label moves nothing beside it. A running operation keeps the status line. State changes call `scheduleRender()` (`scheduleRender(true)` to rebuild the list); one render runs per animation frame, and it puts focus back on the same control, its rebuilt row, or the search field or current tab, never the page (`checkVisibility` also catches a control in a closed `<details>`). Code that hides a focused control outside a render moves focus first: `closeSettings` renders (so a connection made on the first-run screen has its chip) and moves focus to `#settings-summary`, the account chip, and `clearError` asks for a render when the error or its action had focus. On the first-run screen the fallback is the token field. Use `flushRender()` only to measure or scroll the result in the same task.
- **Connection generation.** Every `connection` and `selection` message carries `connectionGeneration`. The UI ignores selection replies from an older generation, and saving a connection clears the remembered binding and sets the generation aside (null) until main answers, so a slow storage read cannot rebind another app's artwork. A pasted token is identified (`GET /api/token`) before the save starts; until then the old connection stands, and a connection message makes that identification stale (`identifyTicket`). If main refuses the save (a client storage error, say), the old connection stands: `failConnection` puts back the generation, the Send placements, and the typed token; main reports the selection again after the error; and `connectionKept` reloads the Insert list in view when a load ended unseen during the wait or a Refresh, search, or Load more was asked for meanwhile, keeping loaded rows and the choice otherwise. The error stays under the token field. Any new main-to-UI message that depends on the connection needs the same check. `tests/plugin.test.mjs` covers app switches, token rotation, and refused saves.
- **Export bounds and limits.** `chooseExportSettings` exports PNG with `useAbsoluteBounds: true`, constrained to the placement's width, or its height when the node is proportionally taller. `buildDraftBody` rejects settings that no longer match the node and placement. Send and Sync stay disabled while the node's ratio differs from their placement's by more than 2% (`aspectMismatch`): Send's callout names the chosen placement, and the Sync bar names Sync's when it is another (or on Insert), each with its own **Match ratio**. **Match ratio** (`match-ratio`) keeps the width, sets the height with `matchedHeight` after fixing a hug or fill height (put back if the resize throws), and calls `figma.commitUndo()` once, after the resize, so it is one undo step of its own (every other plugin edit commits its own, so nothing earlier joins it). Main reports the selection again, throttled to 150 ms, on a `PROPERTY_CHANGE` to the selected node, re-registering on `currentpagechange`, so the gate never acts on a stale size. Before upload the UI also reads the PNG IHDR and stops if the aspect ratio differs from the placement by more than 2%. Size limits are 4 MiB decoded PNG (`MAX_IMAGE_BYTES`) and a 4,500,000-byte JSON body (`MAX_BODY_BYTES`), Vercel's request limit, so a base64 PNG above about 3.37 MB decoded does not fit; every limit, and an HTTP 413, says `EXPORT_TOO_LARGE` ("over 3.3 MB as a PNG", the size that always fits). Send's export line (`#export-note`) is empty, and takes no room, while the ratio blocks the export.
- **Wire shapes.** `DraftBody` (`schemaVersion: 1`) and the placements, artwork, image page, and draft responses in `src/shared/types.ts` match the hosted console's API. Change them only together with the console.
- **Previews** of list rows and tiles load only for images the `IntersectionObserver` reports within `300px` of the list's view (its `root` is `#list-region`, the scroll container; an explicit root also keeps the margin in Figma's cross-origin iframe, where the implicit root ignores it), at most three at once, newest first. The footer's image is outside the list, so it loads whenever it shows; jobs whose images scroll away or leave the list before starting are dropped. Network errors and 5xx retry at 1 s and 4 s, 429 pauses all previews for 15 s, and Refresh clears failed previews. Previews never use the error line.
- **Window size.** `showUI` opens the window hidden (`visible: false`); once the preferences are read, main resizes it to `preferences.window` or `defaultWindowSize(viewport.bounds.height × viewport.zoom)` (420 wide, that height less 64, from 480 to 720; 720 when the viewport can't be read) and calls `figma.ui.show()`. The grip (`#resize-grip`, a 12 px corner over the 12 px side padding, so no control sits under it; the hint bar keeps 12 px on its right for that) takes pointer capture, keeps focus where it was (`preventDefault` on `pointerdown` and `mousedown`), and posts `resize` with the size under the pointer, clamped (`clampWindow`, 320–900 × 480–1000), at most once per animation frame; main clamps again and calls `figma.ui.resize`, and a size Figma refuses is ignored. On pointer-up a size that changed is saved as `state.prefs.window` (`savePreferences`); a double-click deletes it and posts `reset-size`, which resizes to the default for the canvas then. Layout is CSS: below 400 px `#env-group` gives way to `#env-select` (same choices and rules; a `focusout` handler moves focus from the one that hides to the other, because Chrome drops it before any resize event), the footer's `.picker-word`s hide (each select keeps its `aria-label`), and so does `#insert-preview`; `.footer-text` keeps 88 px, and `#insert` shortens first (40% at most, 50% below 400 px); from 560 px a row's `.row-text` is `display: contents`, so its meta is a right-aligned column (`fit-content(40%)`, so the key keeps most of the room) before a tag column; the image grid is `repeat(auto-fill, minmax(112px, 1fr))`, and a tile's name breaks after `.`, `_`, or `-` first (`<wbr>`). The chip is at most `min(320px, 100% - 136px)`. The window's `resize` asks for a render, which fits the chip's workspace name again (its fit is keyed by the window's width too). The first run's column sits in the middle of the window's height.
- **First run and the token form.** Until main's first connection message (`state.preferencesLoaded`) the connection is unknown, not absent: `render` does nothing, so a render then (the window's resize, a font loading) never shows the first-run screen, which once left the settings open over a saved connection whose opening test failed. Without a connection the plugin shows only the first-run screen, which is the open `#settings` (render keeps it open; Esc closes the settings only with a connection). A typed token must match `alk_` and 43 base64url characters (`checkTokenFormat`), checked before anything is sent; saved connections are not checked again, so older saves load. With a working connection the account panel is a menu (`#update-token` shows the form; `formOpened`, reset when the settings close): the form shows on the first run, while the connection needs attention, after Update token, while it holds a typed token or something to say, or while ID fields show, and its submit says **Save token** with a healthy connection, else **Connect**. The panel's title is the app's name, whole; the line below is "{Workspace} · Connected with token {prefix}…". **Disconnect** sits apart on the right. With the ID fields hidden, Connect asks `GET /api/token` (tried once) and saves the connection it names, with `workspaceName` and `appName` when the console returns them; a 401 or 403 is the token field's error, a token without the `draft` scope too, and a 404 or a network failure (an older console without the route or its CORS headers) shows the organization and app ID fields under `OLDER_CONSOLE` (`askForIds`, above the ID fields), which the form then uses; after a network failure (`idsUnsure`), a Connect with the ID fields still empty asks `GET /api/token` again, and a 200 forgets the ID fields for that console. That is a step, not a mistake: `#connection-error` becomes a neutral `.info` notice, announced through `#status`, no field is marked invalid, and the organization ID takes focus; any later form error puts back the `.error` callout. The ID fields belong to that console (`idsOrigin`): they show, and the form uses them, only while it is the chosen one; choosing another console hides them and clears a form error about the first, and a connection message without a connection (Disconnect) forgets it. A blank token tests the saved connection again on its own console. Disconnect (`clear-connection`) deletes `assetlib.connection.v1`, bumps the generation, and main toasts that the token still works elsewhere, with **Undo** for 6 s (`reconnect`: saves the same connection again and bumps the generation, unless another connection was saved meanwhile; the token never appears in the toast). Without names from the console, the chip and the panel name the app by the start of its ID (the panel's title has both IDs on hover), and the Connected toast says "Connected to Assetlib", never two raw IDs.
- **Connection state.** A failed read never opens the connection settings: `needsAttention` shows the chip's warning glyph and, for a failed connection test or a refused token on a list read, keeps the reason in `#connection-error` under the token field (a `read` error, marking the token for a 401 or 403), where it shows whenever the settings are open. A 403 is about the token's scope only when the console's message says "scope" ("This API token lacks the required scope."); any other 403, such as a revoked token's, is a refused token, as a 401 is (`tokenRefused` in `errors.ts`, `refusedToken` in `ui/state.ts`). Each failure is said once (`problemInSettings`): while the settings are open and hold a read error, they say it (announced, and the token field focused unless focus is in a field, `inField`), and the view's own copy steps aside; otherwise the view in front says it. A failed connection test (`state.testFailure`) is said by the Insert list in `#insert-empty` (`listUnavailable`) and by Send's `#send-problem` above the Placement field, each with one action from `readProblem`: Try again (on Send it runs the test again, `testConnection` in `main.ts`) or Update token (`openSettings`, at the token field). The view in front announces it and takes focus unless the person is in a field; the other keeps it for when it shows. Any successful authenticated read (placements, artwork, assets, rendition) sets the label to connected and clears the read error and `testFailure`; it never closes the settings. A passing connection test closes them, unless the person works in them (`settingsInUse`; the fields stay live during the test): focus is in one of their fields that it moved to after the test started (`focusMark`; the field they submitted from, or one the code focused, does not count), or a token is typed or the origin, organization, or app differs from the saved connection. After a failed connection test it first reads placements again quietly (`reloadPlacements`, tried once and at most once per 15 s), so Send never sits without them under a connected label. A preview that started before the last failed read (`attentionCount`) does not count. Form errors (the answer to the person's submit) also render in `#connection-error`, marking and focusing the field at fault (`connectionErrorField`). Other errors (`showError`) show in `#error` inside `#error-box`, the fixed line above the footer, with at most one action button (`#error-action`: Refresh after an image was removed); they scroll into view and take focus, except from a field the person is in (`inField`: an input, select, or textarea, such as the token, file link, or search), which keeps focus and is scrolled back into view. A list that can't load is not an `#error`: its reason and one action (Try again, Update token, Go to Send) replace the list in `#insert-empty`, which takes focus unless the person is in a field; a failed Load more keeps its pages and uses `#error`. **Connect** is `primary` only on the first run and while the connection needs attention, so the footer's Insert or Send is the one ink primary otherwise.
- **Keyboard.** The Insert list and the image grid are each a `role=listbox` (`aria-label` Placements or Images) while they hold rows or tiles, which are `div`s with `role=option` and `aria-selected`, not buttons; placements sit in a `role=group` per screen named by its header (`aria-labelledby`, the header `role=presentation` and `aria-hidden`, so it isn't read twice). Each list is one tab stop (roving `tabindex`, `updateSelected`): the row last focused or chosen (`activeKey`), else the chosen one, else the first. `listKeydown` moves focus and the choice together on ↑ and ↓ (in the grid ← and → by a tile, ↑ and ↓ by a row of tiles from `columns()`), Home, End, and type-ahead (`typeAhead`: letters less than 500 ms apart; Space inside one is a letter, otherwise Space chooses the focused row); reaching a list with Tab chooses nothing. Enter (not its repeats, `event.repeat`, nor on the Insert buttons) and a double-click run `insertFrom`: choose, then the footer's primary (Insert, Insert into, Fill, or Replace image, as the selection decides), or, on a row Insert can't use, the footer's note in `#status`. Choosing the chosen row again keeps its picked cell. The tab list and the Browse, Environment, and Insert at radio groups use `arrowKeys` and `rovingStops` (`dom.ts`): one stop each, arrows choose (tabs also Home and End), wrapping and passing over disabled items. Esc in the search or the list (`escape`) clears the search, then the choice (not while an insert runs). A document keydown in `main.ts` sends `/` outside a field, and Cmd+F (Ctrl+F off Apple platforms, where Ctrl+F moves the caret), to the search on the Insert tab (`focusSearch`), Cmd+Enter to the Sync bar (`syncFromKeyboard`), and ignores a key a handler already prevented. **Tab** reaches the Sync bar after the list and before the footer. Nothing inside a row or tile may be positioned (`.thumb` is static): a positioned child paints over the focus ring, as it once did over a tile's. A row's ring sits inside it (offset −2); a tile's sits 2 px outside it, clear of its name, and on the chosen tile replaces its selection ring. An environment chosen while the artwork loaded that turns out to have nothing published hands focus to the one shown.
- **Live regions and toasts.** `#status` (role=status) and `#alert` (role=alert) are fixed in the DOM and visually hidden. Every error is announced through `#alert` (`announceError`), and every toast and result through `#status`. Finished operations are Figma toasts (`notify`, at most 100 characters): Inserted, Filled, and Replaced (main, after an Insert or a drop alike; a fill or replace with Undo; for layers it couldn't link, inside an instance or refused by Figma, it says Sync isn't available, and when Figma refused the image on some layers it says how many were filled, and then also whether Sync is unavailable for any of them; a fill names placement art by its key; the `inserted` message's `notice` carries the words, which `#status` repeats), Sent and Synced (with Review, a link to the console's releases), Connected, and Disconnected (main). A 409 partial result shows its notice and link inline, with no success toast.
- **HTTP 409** on a draft can still mean the asset was created. Keep showing the partial result and the console's message.
- **Token handling.** The token goes only as a bearer header to the chosen origin, with `credentials: 'omit'` and `redirect: 'error'`. Never log it, put it in a URL, or display more than `tokenPrefix()`.
- **Storage keys** `assetlib.connection.v1` (now with optional `workspaceName` and `appName`), `assetlib.file-url.v1` (a prefill only), `assetlib.target.v1:…`, and `assetlib.preferences.v1` (tab, browse mode, environment, scale, and the optional `window` and `hintSeen`, absent unless set: `window` is set when a drag on the grip ends at a new size and removed by its double-click, and `hintSeen` is set by the first successful insert or drop, or the hint bar's Close; the default tab is Insert) hold users' saved state in client storage. Renaming them silently drops saved connections, sync targets, and preferences. Stored sync targets keep their original shape; `insertedFrom` is derived from a link, never stored. In the document, `assetlib.link.v1` (layers) and `assetlib.file.v1` (root) are plugin data, never renamed either.

## Writing rules

- The product is "Assetlib" in prose and UI copy. `AssetLib` is only the GitHub org slug.
- UI and error text is plain and says what to do next (see `src/shared/errors.ts`), following §4.6 of the parity plan: no HTTP codes except "Assetlib had a problem ({status})", no manifests, PNG chunks, node IDs, or "update the console". No overstated claims such as "instantly". No emojis. Don't describe a feature before it ships.
- Visual tokens: colours only from Figma's `--figma-color-*` variables with brand fallbacks; meta text is `--al-text-meta` (text at 70%), never `text-secondary` or `text-tertiary`; vermilion is only the focus ring. `npm run contrast` must pass after any colour change, and it refuses a text colour it does not measure. Figma's `bg-hover` and `bg-pressed` equal `bg-secondary` in both themes, so hover never relies on them over a `bg-secondary` surface: a hovered secondary button steps to `bg-tertiary`, and a hovered tab or segment turns to ink without a fill. A neutral step (an older console's IDs, the file link) is an `.info` callout with an ink icon, never a warning or danger one. Controls inside a callout (`.notice`, `.error`, `.info`) sit on `bg` with a `border`, never on the callout's own `bg-secondary` (a focused invalid field drops its red border for the ring); `npm run test:browser` checks every one in both themes.

## Don'ts

- Don't add a publish or release path, or any network origin beyond the production, legacy production, and development origins above.
- Don't send anything beyond what README "Data and network access" lists. Never send the Figma document or a Figma token.
- Don't commit `dist/`, `.test-build/`, `graft/`, or a changed plugin id.
- Fix a confirmed defect you find in the same change, with a test. Defer only when a fix is unsafe now, and say when it will happen.
