# AGENTS.md

Public repository `AssetLib/figma-plugin`: Assetlib for Figma. A Figma design plugin that inserts an app's placement artwork as image-filled components and library images as image-filled frames (or, by the selection, into a container, or fills or replaces the selected layers' images; or where a row or tile dragged onto the canvas lands), sends one selected node to an Assetlib placement as a draft, then re-syncs that node's later edits. It connects in one click (the console's connect page approves a connection request, and the console issues the plugin a draft-only token of its own) or with a pasted app-scoped `draft` token, and calls the hosted console's token identity, placements, artwork, image library, rendition, and drafts endpoints with that token. Publishing stays in the console; this plugin never publishes. TypeScript, bundled with esbuild, no runtime dependencies. See README for install, connection, and data handling.

## Commands

Node.js 22 or later (`engines` in `package.json`; `.nvmrc` is 24).

```sh
npm ci
npm run typecheck   # tsc for the main thread (tsconfig.json) and the UI (tsconfig.ui.json); no emit
npm test            # scripts/test.mjs: compiles src/shared to .test-build/, then node --test tests/*.test.mjs
npm run build       # scripts/build.mjs: minified dist/code.js and a self-contained dist/ui.html (release CSS minified; over 196,000 bytes for ui.html or 50,000 bytes for code.js, it removes that output and fails; prints both sizes)
npm run verify      # typecheck, test, build
npm run test:browser  # build, then scripts/ui-browser.mjs drives dist/ui.html in headless Chrome (CHROME_PATH to choose one)
npm run watch       # build --watch: unminified with inline source maps, rebuilt on every change (build --dev builds once)
npm run contrast    # scripts/contrast.mjs: every text colour pair in Figma's light and dark themes (npm test runs it too)
npm run e2e:local -- --connection <file>   # live local console, the token path; not part of npm test (README "Development and verification")
npm run e2e:local -- --pair --account <file>   # live local console with migration 039, one-click Connect
```

CI (`.github/workflows/verify.yml`) runs `npm ci`, `npm run verify`, and `npm run test:browser` on Node.js 22 and 24. There is no lint script. `npm run verify` and `npm run test:browser` must pass before work is done. They cannot exercise real Figma exports, client storage across restarts, console CORS, or authenticated draft and rebind behavior. `npm run e2e:local` covers the token-only connect (`GET /api/token`), the authenticated reads, inserts, the draft round trip, and CORS preflights against a local console, and `--pair` one-click Connect (start, cancel, approval through the console's session routes, the claim, Disconnect ending the token, and the four routes' preflights), still without real Figma; a change touching Figma behavior also needs a manual run in Figma desktop against a console (README "Development and verification").

## Layout

- `manifest.json`: Figma manifest. Plugin `id`, `main: dist/code.js`, `ui: dist/ui.html`, `documentAccess: "dynamic-page"`, `menu` (Open Assetlib, a separator, Insert artwork…, Send selection to draft…), `enablePrivatePluginApi` (a development or organization-private plugin gets `figma.fileKey`; a Community build can't have it, and parity plan D removes it), `relaunchButtons` (`sync`, "Sync to Assetlib"; `open`, "Open Assetlib"), network allowlist.
- `src/code.ts` and `src/main/`: the main thread in Figma's sandbox. No DOM and no HTTP here. `code.ts` is the entry: it routes and checks the UI's messages (and hands Figma's `drop` events to `insert.ts`), keeps the connection and preferences in `figma.clientStorage`, opens the browser (`openUrl`: a console link or the connect page, nothing else), adopts a connection another window saved from a claimed request (`adopt`) or that replaced this window's refused browser connection on the device (`reload`), exports for Send (`exportAsync`) and links the sent layer (`linkSent`), saves a pasted file link, runs Match ratio, sizes the window (`resize`, `reset-size`), tells the UI it was opened from Sync to Assetlib or an Insert or Send menu command (`launch`), and watches the selection: `selectionchange`, `currentpagechange`, and a 250 ms check (`setInterval`) that reports the selection again, and retires a fill's Undo, when `selectionStale` finds the one selected layer no longer shows what the last report did (a resize, a rename, its link or visible image changing, a Cmd+Z of any of them). Figma desktop sends a plugin no event for the person's own edit that keeps the selection: a page's `nodechange` never runs for it, and `documentchange` needs `loadAllPagesAsync`, which the plugin avoids (tested October 14, 2026). `main/selection.ts` reports the selection (`canvasView` reads all it shows of the canvas at once; `selectionStale` compares that with the last report and also compares the layer's visible image hashes, which the report doesn't post), with sync targets, the layer's link (`link`: linked, a copy, or another app's), the file key and where it came from (`file`), and `insertTarget` (what Insert does with it), and writes links (`writeLink`, with the layer's relaunch button). `main/identity.ts` is the document's identity: the file key (`fileIdentity`, `currentFileKey`), a pasted link (`linkFile`), and `markDocument`. `main/insert.ts` inserts image components for placement art and frames for library images (`createImage`, `createComponent`, `createFrame`, pluginData), into a container or beside the selection, fills and replaces, and answers drops (`drop`: a placeholder where a dragged row or tile lands, or the image frame it lands on, which the drop's insert fills). `main/pairing.ts` keeps a one-click Connect request waiting for approval (`assetlib.pairing.v1`: `parsePairing`, `loadPairing`, `savePairing`, `clearPairing`, and `takeTurn`, which lets one plugin window at a time ask the console about it) and offers the workspaces this page's links name (`pageHints`); only `code.ts` imports it. `main/state.ts` holds what they share (the connection, its generation, the Connect request, the `importing` and `exporting` guards, `post`). `main/inventory.ts` scans the connected app’s local links (`scanLinks`, `scheduleScan`) and selects a listed node (`selectNode`); `main/export.ts` reads raster sizes for the export density (`rasterDensity`). They import in one direction, `code` → `insert` → `inventory` → `selection` → `identity`, `state` (any may skip levels); `code` also imports `pairing` and `export`. Keep imports acyclic.
- `src/ui.html` and `src/ui/`: the UI iframe and every HTTP call. `ui.html` is the app shell: a first-run screen without a connection; otherwise a top bar (tabs, and the account chip, which is the `#settings` details' summary and opens the connection settings below the bar), the view (Insert: search, scope bar, and `#list-region`, which scrolls apart from the footer’s bounded cell strip; Send: its form), then the fixed `#messages` error line (`#error-box`: the `#error` text and at most one `#error-action`), the `#selection-bar` (the Sync bar, both tabs), the `#hint-bar` (Insert, nothing chosen, until the first insert), and the footer of the view in front. `main.ts` is the entry: it routes main's messages, registers the renderer, and runs the resize grip (`#resize-grip`). `http.ts` makes every console request; `connect.ts` (one-click Connect: starting a request, polling, the `#pairing` block and `#pairing-note`, Connect to Assetlib, Use a token instead, Switch workspace, and Connect again), `connection.ts` (the token form, saves, Disconnect, connection test, label, and `fitWorkspace`, which sizes the chip's shortened workspace name to its ellipsis so the spaces around "·" match), `send.ts` (Send tab, the placement picker’s Fits this layer and screen groups, whose options read "{key} · {ratio}" with the reference size on hover, Draft-art suffixes on the cell pickers through `draftArtState`, the `sendChoice` read by Send’s current-art preview, the file link, and Sync, whose bar state is `syncBar()`), `syncbar.ts` (the Sync bar's DOM, the relaunch focus, and Cmd+Enter), `insert.ts` (Insert tab, its downloads, and dragging rows and tiles onto the canvas), `cells.ts` (the Insert cell strip), `infile.ts` (local inventory requests, scope, file rows, and placement file chips), and `thumbnails.ts` (previews) own their state and DOM; `state.ts` holds what more than one of them reads, including `ops` and the `fileLinks` index; `dom.ts` holds element, error, render-scheduling, and focus helpers, `post` and `postDrop`, the only ways to message Figma, and `reloadConnection` (main reads the saved connection again for a refused browser connection). Modules import in one direction, `main` → `syncbar` → `insert` → `cells` → `infile` → `thumbnails` → `connect` → `connection` → `send` → `dom` → `state`, and `http` (any may skip levels); keep it acyclic. `ui.html` must contain exactly one `<!-- ASSETLIB_SCRIPT -->` marker, where the build inlines the bundled UI script, and one `/* ASSETLIB_FONT */` marker, where it inlines Instrument Sans as a base64 `@font-face`; a release build drops the template’s CSS and HTML comments and indentation and then minifies the embedded CSS with esbuild, without a target (`compact` in `scripts/build.mjs`); the inlined UI script keeps its copy in UTF-8, and optional HTML attribute quotes are omitted only for values without spaces or delimiters, so keep `/*` and `<!--` out of anything but comments, and no `<pre>` or `<textarea>`. `src/image.ts` is browser-only (WebP to PNG through a canvas) and is imported by `src/ui/insert.ts` only.
- `src/assets/`: `instrument-sans-variable.woff2` and its licence `OFL.txt`, copied from the workspace's `brand/` by `sh brand/sync.sh`. Don't hand-edit them; change the brand source and sync.
- `src/shared/`: pure logic used by both sides (origin, token, and connection validation, file links and the document identity in `connection.ts` (`parseFileLink`, `slugify`, `linkNamesFile`, `parseFileIdentity`), placement parsing, export settings, PNG header check, draft body and response parsing, error text, `links.ts` for console links, and in `library.ts` the artwork, image page, rendition choice, layer name, insert link (`linkInApp`, `linkMatches`), relaunch description (`syncDescription`), label, preference, and window size (`clampWindow`, `defaultWindowSize`) rules, and in `marker.ts` the placement marker). It must run in the sandbox too, so avoid browser-only globals such as `URL`. `http.ts` holds the timeout and retry rules. `protocol.ts` defines the main and UI messages, `parseUiMessage`, main's shape check, `toastText`, and the Connect and Disconnect copy. `connection.ts` also holds one-click Connect's wire checks (`pairingUrl`, `parsePairingStart`, `parseClaim`), and `links.ts` the connect page (`connectPageUrl`, `isConnectPageUrl`).
- `tests/shared.test.mjs` covers the compiled shared modules and checks that `manifest.json` and the origin picker list the same origins as `connection.ts`. `tests/plugin.test.mjs` bundles `code.ts` and `ui/main.ts` with esbuild and runs them in `node:vm` with the fake `figma`, DOM, console, and `fetch` from `tests/fakes.mjs` (not a test file itself). The fake `fetch` honours `AbortSignal` and answers `GET /api/token` for a token `saveConnection` typed (or `console.identity`, or a token it issued), else 404 as an older console does, and 401 without a token; its connection request routes (`start`, `claim`, `cancel`, `current`) keep each request in `console.pairings` (a status, a `connection` to issue once approved, and scripted `answers`), the tokens they issued in `console.issued` and ended in `console.revoked` (an ended token gets 403 `revoked` elsewhere), and `codes[route]` adds a refused Figma connection's `code`; an older console is `failures` on `start` (its missing routes send no CORS headers) with `GET /api/token` still answering; `now` gives both sides a clock a test moves (`plugin.test.mjs` passes it to the console too, whose claim of a pending request sooner than its interval − 0.5 s after the last answers `slow_down` and grows the interval, as the console's does), and with it `fireDue()` runs every timer due by then; main's `setInterval` is kept apart from those timers (`intervals`), and `tick()` runs each once, as main's canvas check; a test edits a fake node directly for a canvas edit Figma reports to no listener (assigning `figma.currentPage.selection` fires no event; `select` does), and each page has an id (`0:1` on); `store` shares client storage between two harnesses (two windows; `windows()` in `plugin.test.mjs` opens several sharing storage, the console, and a clock, which `advance` moves), `focusWindow()` fires the window's `focus`, and `setVisibility(value)` the document's `visibilitychange`; animation frames run at once unless a test sets `manualFrames`; fake elements support nested `optgroup` options in a select and report their `tagName` (fields and selects) and, for the connection settings and the file link form, `contains()`, and have a `style` object and empty boxes (`getBoundingClientRect`), so the UI measures nothing; `dispatch(type, init)` passes an event with `target` and `preventDefault` and returns it, and `keydown(init, listener)` delivers a key press to the element whose listener handles it (the list, for a row) and then, unless prevented, to the document (`navigator.platform` is `MacIntel`); the fake `figma` also records `notify` options (and whether a toast was cancelled), `commitUndo`, `triggerUndo`, `openExternal`, `ui.resize` (`uiResizes`; it also sets the UI window's `innerWidth` and `innerHeight` and calls its `resize` listener), `showUI`'s options and each `ui.show` (`uiShown`), `viewport.zoom`, relaunch data (`relaunches`, with the document as `0:0`), root plugin data (seeded with `rootPluginData`; `readOnlyRoot` refuses writes, as a view-only file; `rootName` names the document), `clientStorage.deleteAsync`, and answers `findAllWithCriteria`; `command` sets `figma.command`; a `pluginDrop` the UI posts is kept in `pluginDrops` (it is Figma's, never a plugin message), `dropOnCanvas({ node, absoluteX, absoluteY })` turns the last one into main's drop event as Figma would, `drop(event)` delivers any drop event, `close()` closes the plugin, and `dataTransfer()` makes a dragstart's DataTransfer that records its data and drag image; fake elements keep pointer capture (`setPointerCapture`, `hasPointerCapture`, `releasePointerCapture`) for the grip. Its pages (`pages`) populate `figma.root.children`, each with its own `findAllWithCriteria` and `loadAsync` (recorded in `loadedPages`); `figma.setCurrentPageAsync` switches pages and fires the page listener. `getImageByHash(hash).getSizeAsync()` reads `imageSizes` or a generated image’s PNG header. An instance’s `main` spec or node id is returned by `getMainComponentAsync`, with `remote` on that component; a main resolved from a spec is found by `getNodeByIdAsync` too. `exportBytes` can return bytes, a byte count, or compute either from the node and settings; numeric counts pad a PNG header with the settings’ dimensions. Its nodes come from plain specs: `children` specs become child nodes with a `parent`, `x` and `y` are relative to a parent frame and `absoluteBoundingBox` adds the parents', `appendChild` and `remove` move them, and, as Figma is expected to, a layer inside an instance (an id with `;`) refuses plugin data, an instance or a layer inside one refuses children, and a component refuses to go inside a component, component set, or instance, or anything inside one (`refusePluginData` and `refuseChildren` make any node refuse). In `tests/plugin.test.mjs`, `openInsert` clears the selection (nothing selected makes a new frame) unless given `{ keep: true }`. `tests/contrast.test.mjs` runs `scripts/contrast.mjs` over `tests/fixtures/figma-theme.json` (Figma's documented light and dark variables). `scripts/e2e-local.mjs` reuses those fakes with Node's real `fetch` against a running local console. `scripts/ui-browser.mjs` is the browser suite: dependency-free DevTools protocol over `--remote-debugging-pipe`, `node:test`, and an in-page fake main thread and console (previews are real PNGs in each image's proportions, so screenshots show contained art over the checkerboard); it is not a Figma run. A page opened with a `theme` gets Figma's variables and `figma-dark`/`figma-light` class from the fixture; `ASSETLIB_SCREENSHOTS=<dir>` writes every state in both themes there (for review; never commit them).
- `dist/`, `.test-build/`, and `graft/` are generated and gitignored. Don't edit or commit them.
- `WORKSTREAM-G-REPORT.md` is a historical implementation report, not instructions.

## Invariants

- **Read and draft only.** Under `/api/apps/{orgId}/{appId}/` the plugin calls `GET placements`, `GET placements/artwork`, `GET assets`, `GET assets/{assetId}/renditions/{sha256}`, and `POST drafts`, nothing else; outside an app it calls only `GET /api/token`, which tells a pasted token its own organization, app, names, and scopes (asked without a token, after a connection request or a pasted token’s GET got no answer, it tells an older console from one that can't be reached), and one-click Connect's four routes: `POST /api/plugin-connections` (no Authorization), `POST /api/plugin-connections/claim` and `/cancel` (the request's `alr_` read key as the bearer), and `DELETE /api/plugin-connections/current` (a browser connection's own token). Every request goes through `src/ui/http.ts`: `send()`, whose `appUrl` refuses any other path, `identify()` and `consoleAnswers()`, whose `tokenUrl` builds only `{origin}/api/token` for the two allowed origins, and `pairingRequest()` and `revokeConnection()`, whose `pairingUrl` builds only those four routes for them. Don't call `fetch` anywhere else. Console links (**Open console**, **View in console**, **Open in console**) are browser navigations built by `consoleLink` from validated IDs on the connected console's page origin (`consolePageOrigin`: production as is; the development console's `http://127.0.0.1:3100`, where it signs people in), including image and placement pages (`images/{id}` and `placements/{id}`), never carrying the token; main's `notify` opens a toast button's URL with `figma.openExternal` only when `isConsoleLink` accepts it for the current connection. Insert and Send both require a token with the `draft` scope. Never add a publish, release, or restore call, never ask for a broader scope, never call the public delivery routes, and never accept a Figma token in its place.
- **Opening the browser.** Main opens a page only through `openUrl` in `code.ts`, the one `figma.openExternal(` call: a toast button's console link that `isConsoleLink` accepts for the current connection, or, for `open-connect-page`, the URL `connectPageUrl` builds from a fixed map of the two console origins and a well-formed write key, checked again with `isConnectPageUrl` (production `https://console.assetlib.dev/connect/figma#alw_…`, development `http://127.0.0.1:3100/connect/figma#alw_…`). Anything else is refused with "The plugin can’t open that page."; main never opens a URL the UI built.
- **Rendition URLs are built from validated ids, never taken from a response.** `renditionUrl` takes a uuid asset id and a 64-hex sha256; the `url` field the console sends is ignored. The bearer token must never go to a URL that came from a response body.
- **Inserted, filled, replaced, and sent layers carry pluginData `assetlib.link.v1` without the token** (sent layers since parity plan A.7, pending the founder's review). It names the origin, organization, app, cell, environment, asset, and the layer's own node id; a fill of several layers links each with its own id. After a Send or Sync the console bound (`remember` carries the draft's `assetId`, null for a 409 or an unbound draft), main writes the link with `environment: 'draft'`, that asset, and the send time, and a component's marker for that placement (`writeMarker`, with the placement's declared size kept in `exported`), as an undo step of its own (`linkSent`, after `retireUndo`), so teammates and other devices find it. Every plugin edit that is a step of its own (a Send's link, a file link) goes through `commitOwnStep`, which commits nothing while a drop's placeholder waits (`dropPending`), so that drop's insert commits the placeholder and its image as one step. `writeLink` (in `selection.ts`) also gives the layer one `setRelaunchData({sync: syncDescription(link)})` call (its cell and environment, at most 1000 characters; a refusal keeps the link) and runs `markDocument`. Placement art only: a library image never writes or removes a link, so a linked layer filled with one stays linked to its cell. Layers inside an instance (an id with `;`, `insideInstance`) are filled but never linked, because Figma keeps no plugin data there; `writeLink` skips them and catches a refusal from any other layer, which then stays unlinked without failing the insert. `reportSelection` uses it only when no client storage target exists for the layer on this device, and only when its node id equals the selected node's id (a Cmd+D copy keeps the data with another id) and the origin (legacy host mapped to production), organization, and app match the connection. Update rewrites the link with the same cell and environment, the current image, and the update time; main accepts it only while the layer’s link still names the asset the UI saw and the layer shows a visible image with no children. A fill, replace, or Update that writes a link deletes the layer's stored targets in this file (`dropStoredTargets`, current and legacy origin), so Sync follows the relink instead of a target an earlier Send or Sync stored; before the file key is known, or after a storage failure, `reportSelection` ignores those targets until it can delete them. A later Send or Sync stores a new target (`storeTarget`), which wins again. A target another device stored stays there until that device sends the layer again. A Sync of a linked frame binds exactly the cell it was inserted from, or last filled or replaced with; the draft wire shape is unchanged.
- **Placement art is a component carrying a marker.** An insert from a placement creates a component; a library image stays a frame. Either takes layers inside without changing its node id. `placementMarker` writes the component's `description` (the key, the declared size, and an instruction to use the generated accessor instead of exporting the image) and one `documentationLinks` entry, `consoleLink(…, 'placements')` from validated IDs (legacy host mapped to production; the development console on `http://127.0.0.1:3100`). Figma's MCP server returns both to coding agents in `get_design_context`, and returns neither shared nor private plugin data (tested live on October 11, 2026). Anyone with the file reads them, so never put the token, or anything beyond the key, size, and console link, in either. The key is the only text from the console in the description, so it must match the catalog's key grammar (`^[A-Za-z][A-Za-z0-9_.-]{0,119}$`) and the size must be two positive integers; `validateInsertLink` refuses any other key (`validPlacementKey`), so an insert, fill, drop, or a Send's link never carries one into a marker, relaunch text, a layer name, or a toast, and a console response can never put its own words into instructions an agent follows; a size that isn't two positive integers makes a plain linked frame with no marker. A documentation link Figma refuses is skipped; the insert still succeeds. A fill, replace, or Send with placement art (`writeMarker`) rewrites a component's description and documentation link only when the description is empty or a marker (`isPlacementMarker`), so a relinked component names its new placement and a description the designer wrote is never changed. The same relink renames a layer still named for the placement its link named (the key, or the key then ` · `; `renameRelinked`) to the new cell's layer name (`layerName`); a name the designer gave it stays.
- **Insert follows the selection.** `reportSelection` classifies the current selection on every report (`classifyInsertTarget` in `library.ts`, `selection.insertTarget`): one shape, frame, component, or instance with a matching link and a visible `IMAGE` paint (`hasImagePaint`: `p.type === 'IMAGE' && p.visible !== false`) is **replace** (a linked text, group, line, or section, which a Send links, takes no image and is classified as any other layer); a `FRAME` or `COMPONENT` with children, not inside an instance, is **into** (Figma gives an instance no new children, so an instance with children is not a container), with `insideComponent` when it is a component or sits inside a component, component set, or instance (`inComponent` in `selection.ts`); shapes and childless frames, components, and instances are **fill** (other layers are skipped, with `skipped` when the count is positive); otherwise **new** (`beside: true` when any layer is selected). The footer's primary takes its `label` ("Insert", "Insert into {name}", "Fill {name}", "Fill {n} layers", "Replace image"), hides the scale for fill and replace, and offers **Insert as new layer** (`#insert-new`) in the other modes; `#insert-note` leads with the mode’s destination and link effects, counts skipped layers in a fill, makes no link claim for layers inside instances (and names the linkable count for a mix), and names the old and new cells in a relink (or that the link stays, including for a library image). New with nothing selected has no note. The beside-component explanation follows. New and into show the actual arrow size; only new shows the 1×, 2×, and 3× radios. `insertSize(frame, scale, container?)`, shared by main and UI, divides the reference size by scale without a container; with a positive container width and height it multiplies by `min(1, container.width / frame.width, container.height / frame.height)`. Both sides round to two decimals. Into carries `containerHeight` as well as width, fits both dimensions, and never enlarges the reference. Fill and replace keep the layer’s size and show no scale or arrow size. Figma puts no component inside a component, so with `insideComponent` and placement art that main inserts as a component (`placementMarker` accepts its key and size), the UI treats the target as **new** ("Insert", beside the container) and `#insert-note` says why (`besideComponent`); a library image, a frame, still goes in. `insertTarget` in `selection.ts` is async: for at most 200 selected layers it asks each instance’s `getMainComponentAsync`, never the synchronous `mainComponent`, and treats a main as placement art when it carries this app’s link under any node id (a copied main, or a library component, whose link names another node) or a placement marker description (`isPlacementMarker`; what a library publishes even if Figma drops plugin data); the note's link sentence needs this app's link. A single local Assetlib main becomes Replace in component when it has a visible image, otherwise Fill component, with the main’s id, size, name, link, and `mainOf` instance identity. The note explains that every instance follows and whether the main stays linked or relinks. A remote main gives Insert beside and `lockedMain`, with a note to change it in the library file. In a mixed selection these instances are excluded and counted in `skippedInstances`; over 200 selected layers every instance is excluded without asking for its main. Main awaits a fresh classification, re-checks the selected objects, connection and operation guards, compares the destination’s main id, and resolves a non-removed, local `COMPONENT` before filling it; otherwise `SELECTION_MOVED`. The fill, marker, link, relink rename, and one commit apply to the main, never to the instance; its toast offers no Undo, because the main isn't the selection Undo watches, and Cmd+Z takes the step back. Its toast says “Replaced the image in main component {name}; its instances follow” or “Filled main component {name} with {key}; its instances follow”, through `toastText`. Main refuses placement art into such a container before creating anything; the fake's `appendChild` refuses a component there too. The UI captures the destination when Insert is chosen (`insert.target`: `new`, `into` with the container, or `fill` with the layers); main checks it still names the selection (`stillSelected`) and otherwise refuses with "The selection changed. Check it and try again." and reports the selection again. A new layer goes into the container at its fitted size (centered, or appended to auto layout; removed again if Figma refuses the child), else 40 px right of the selection's page bounds, else centered in the view, and is selected. A fill, replace, drop on an image frame, or Update replaces each layer's topmost visible image paint (`IMAGE` with `visible !== false`) with the new hash, keeping every other field of that paint, or appends `{type:'IMAGE', imageHash, scaleMode:'FILL'}` when none is visible; hidden image paints stay; other paints, size, position, and constraints stay. New layers download `insertRendition` (the largest); fill and replace download `fillRendition` for the width the art is drawn at, `max(containerWidth, containerHeight × art width / art height)` over the widest and tallest layers. Every insert, fill, replace, and Update ends with exactly one `figma.commitUndo()`, after all its edits and never before them, so it is one undo step. A fill, replace, or Update records what it overwrote on each layer: paints, fill style id, the raw `assetlib.link.v1` data, relaunch data, name, and a component's description and documentation links. Its toast offers **Undo** only when, once the fill and stored-target deletion finish, the selection holds every filled layer and each layer's earlier paints are an array (`figma.mixed` cannot be restored exactly), no layer had a fill style (a non-empty string or a non-string `fillStyleId` counts as styled), and no layer is an instance or sits inside one; Cmd+Z on the canvas still takes the fill back. Undo runs only while the toast is current, the page and the whole selection are still those recorded with the toast (including skipped layers, order ignored), and every filled layer still matches what the fill left (`snapshot`: its parent id, child count, fill style id, a component's description and documentation links, its raw link and relaunch data, and `KEPT`: paints, name, position, rotation and transform, size, visibility, lock, opacity, blend mode, mask, strokes, stroke weights (each side), effects, corner radii (each corner), constraints, clipping, and auto-layout sizing), else says "Not undone". It writes back only recorded values that differ, commits once if anything was written (an undo step of its own, so Cmd+Z after it brings the fill back), and reports the selection again (the link put back changes no selection). It never calls `figma.triggerUndo()`, so an edit Figma doesn't report (to another layer, a reorder among siblings, or a property outside `KEPT`) stays, except a reorder in an auto layout frame, where moving the layer changes its position and Undo says "Not undone". A write Figma refuses puts back what that Undo already wrote, in reverse order, commits nothing when every rollback write succeeds or once if a rollback write itself throws, and says `UNDO_REFUSED` ("Not undone. Figma didn’t let the plugin change these layers back."). `package.json` is `private` at version 0.1.0 and nothing else reads that version. The plugin runs as a Figma development plugin and is not published to the Figma Community (as of 2026-10-09). There are no release tags. Ask the maintainer before any publication step.

## Writing rules

- The product is "Assetlib" in prose and UI copy. `AssetLib` is only the GitHub org slug.
- UI and error text is plain and says what to do next (see `src/shared/errors.ts`), following §4.6 of the parity plan: no HTTP codes except "Assetlib had a problem ({status})", no manifests, PNG chunks, node IDs, or "update the console". No overstated claims such as "instantly". No emojis. Don't describe a feature before it ships.
- Visual tokens: colours only from Figma's `--figma-color-*` variables with brand fallbacks; meta text is `--al-text-meta` (text at 70%), never `text-secondary` or `text-tertiary`; vermilion is only the focus ring. `npm run contrast` must pass after any colour change, and it refuses a text colour it does not measure. Figma's `bg-hover` and `bg-pressed` equal `bg-secondary` in both themes, so hover never relies on them over a `bg-secondary` surface: a hovered secondary button steps to `bg-tertiary`, and a hovered tab or segment turns to ink without a fill. A neutral step (an older console's IDs, the file link) is an `.info` callout with an ink icon, never a warning or danger one. Controls inside a callout (`.notice`, `.error`, `.info`) sit on `bg` with a `border`, never on the callout's own `bg-secondary` (a focused invalid field keeps its 1 px danger border inside the 2 px vermilion ring, offset 2 px; that offset applies only to invalid inputs and selects); `npm run test:browser` checks every one in both themes.

## Don'ts

- Don't add a publish or release path, or any network origin beyond the production, legacy production, and development origins above.
- Don't send anything beyond what README "Data and network access" lists. Never send the Figma document or a Figma token.
- Don't commit `dist/`, `.test-build/`, `graft/`, or a changed plugin id.
- Fix a confirmed defect you find in the same change, with a test. Defer only when a fix is unsafe now, and say when it will happen.
