# Assetlib for Figma

Insert your app's placement artwork and library images into Figma, send one selected Figma node to an Assetlib placement as a draft, then sync that node's later edits. Inserting only reads; sending and syncing update drafts; publishing remains a separate action in the Assetlib console.

## Install as a development plugin

Use Node.js 22 or newer (`.nvmrc` names 24) and the Figma desktop app.

```sh
npm ci
npm run verify
```

The build creates a minified `dist/code.js` and a self-contained `dist/ui.html`. Both outputs must exist before importing the plugin. While changing the source, `npm run watch` rebuilds both, unminified and with inline source maps, on every save.

1. In Figma desktop, open a design file, select **Plugins → Development → Import plugin from manifest…**, and choose this repository's `manifest.json`.
2. Run **Plugins → Development → Assetlib → Open Assetlib**. Rebuild after source changes; use Figma's development hot reload or reopen the plugin.

`manifest.json` commits the plugin `id` `1690264758934826227`, which Figma assigned when this plugin was created as a development plugin. The plugin is not published to the Figma Community. Figma scopes client storage to the plugin ID, so saved connections and sync destinations belong to that ID; don't change it in the repository. A manifest without an `id` imports, but the plugin then cannot save its connection: Figma reports `Cannot access client storage without a plugin ID`.

To use a development ID of your own instead: select **Plugins → Development → New plugin**, choose **Figma design** and **Custom UI**, save the generated starter in a separate temporary folder, and copy its `id` into your local `manifest.json` before importing. If Figma lists that starter under the same ID, remove its development entry first. Don't commit your ID. Client storage under a different ID starts empty, so connections and sync destinations saved under the other ID don't carry over.

See Figma's [development plugin instructions](https://help.figma.com/hc/en-us/articles/360042786733-Create-a-classic-plugin-for-development), [manifest reference](https://developers.figma.com/docs/plugins/manifest/), and [client storage reference](https://developers.figma.com/docs/plugins/api/figma-clientStorage/). The manifest uses Plugin API `1.0.0` and the required `documentAccess: "dynamic-page"`. It sets `enablePrivatePluginApi`, which gives a development or organization-private plugin the open file's key (`figma.fileKey`); a plugin published to the Figma Community can't have it, so such a build asks for each file's link once instead (see [Sync later edits](#sync-later-edits)). It declares two relaunch buttons for Figma's properties panel: **Sync to Assetlib** on linked layers and **Open Assetlib** on a document that has any.

## Connect

The plugin opens on a first-run screen until it is connected: the Assetlib lockup, "Insert your app’s placement art onto the canvas, and send frames back as drafts. The plugin can’t publish; nothing goes live until someone publishes in Assetlib.", **Connect to Assetlib**, and **Use a token instead**. Under Connect, it says: "Your browser opens so you can sign in and approve. You need edit access (editor, publisher, or owner) in your team’s Assetlib workspace; a workspace owner can invite you or change your role." **How the Figma plugin works** opens the [guide](https://www.assetlib.dev/guide#figma). A Figma access token is neither needed nor accepted.

**Connect to Assetlib** starts a connection request on the chosen console and opens its connect page in your browser (`https://console.assetlib.dev/connect/figma`, or `http://127.0.0.1:3100/connect/figma` for the development console). The plugin then shows "Approve in your browser" and a code such as `BCDF-GHJK`; sign in, check that the page shows the same code, choose the workspace, and approve. Assetlib never asks you to type the code. The request expires after 10 minutes ("Waiting for approval · expires in {n} min", renewed every 15 seconds), with a spinner while waiting or saving (none with reduced motion). The plugin asks the console every 2 seconds whether it was approved (less often if the console asks it to, or while the console can't be reached), and again when you come back to Figma; **Check now** asks now, **Open browser again** opens the page again, and **Cancel** ends the request. A request still waiting when you close the plugin resumes when you open it again ("Approve in the {host} tab you opened earlier, or cancel and start again."). Once approved, the console issues the plugin a draft-only token of its own, which the plugin saves with the workspace and app names and the email that approved it, and a toast says "Connected to {Workspace} · {App} as {email}". A declined request says "The request was declined in the browser. Connect again to approve it, or choose another workspace." An expired or cancelled request says so too, with **Connect to Assetlib** to start again; one approved for another plugin window on this device connects this window too (plugin windows waiting on one request take turns asking the console, so they never slow each other down, and **Cancel** in one keeps a connection another already saved from it); one used elsewhere is stopped ("This request was already used, so Assetlib stopped it. Connect again."). An approval that arrives while a Send, Sync, or Insert runs is saved once it ends ("Saving connection…"), so that operation finishes with the connection it started with. **Connect again** from Insert or Send opens the connection settings and focuses **Check now** once the request waits. If the settings were already open, **Cancel** returns focus to the visible connection button; otherwise it closes the settings and returns focus to the account chip. A console from before one-click Connect (its connection routes give a plugin window no answer, while `GET /api/token` does) opens the token form ("This console can’t connect from Figma yet. Use a token instead."), and hides **Connect to Assetlib** and its browser help until another console is chosen. The token form’s button becomes the primary action, including for a refused pasted token. A console that can’t be reached says "Assetlib couldn’t be reached. Check your internet connection, then try again." ("Can’t reach the console at localhost:3100. Check that it’s running." locally), with **Try again** and **Use a token instead**. When layers on the current page are linked to one of your workspaces, the connect page offers that workspace first.

While the settings are open for a refused pasted token, Insert and Send keep their duplicate failure notices hidden, including after an empty, malformed, or refused replacement token is submitted. Send’s **Try again** keeps its notice and focus while retesting the same connection; identifying or saving a replacement connection hides the old notice.

**Use a token instead** shows the token form and makes **Connect with token** its main button, with **Connect to Assetlib** secondary (an unreachable console keeps **Try again** primary). The help says "Only a workspace owner can create one: Assetlib console › Settings › Tokens › Draft token. Not a Figma token." To connect, create a **Draft token** in **Settings › Tokens** in the [Assetlib console](https://console.assetlib.dev) (only workspace owners can create tokens), paste it into **Draft token**, and choose **Connect with token**. A draft token can read every image in its app and update draft placement bindings; treat it accordingly.

A pasted token must look like an Assetlib token (`alk_` and 43 more characters); anything else is refused at once, with nothing sent. The plugin then asks the console which organization and app the token belongs to (`GET /api/token`), so nobody copies IDs, and saves the connection with the workspace and app names when the console returns them. Once a session, after the saved connection's first passing test, it asks again quietly, so a connection saved before the console named apps, or a workspace or app renamed since, shows today's names; a failure, or an answer without names, changes nothing. A token the console refuses or has revoked, or one without the Draft permission (a CI declare token), is explained under the token field, which is marked and focused. A console from before `GET /api/token` (it answers 404, or the token’s request gets no readable answer but a tokenless request does) gets the organization and app ID fields instead, under "This console also needs the organization and app IDs. Find them in Settings › General.", a neutral notice rather than an error (no field is marked), with the organization ID focused; the form then uses them. If neither request gets an answer, the form says the console couldn’t be reached, marking no field and asking for no IDs. If the token request failed on the network but the tokenless request answered, submitting again with both ID fields empty re-asks the token; a successful answer hides the ID fields and saves the returned names. The ID fields belong to the console that asked for them: choosing the other console hides them (a token pasted for it is identified with `GET /api/token` again), and **Disconnect** forgets them.

The line "Assetlib at console.assetlib.dev · Change" keeps the console choice out of the way. The line and the console picker both stay hidden while a connection request waits or a healthy account menu shows. **Change** reveals and focuses **Console**; it starts revealed for a chosen or saved development console, a request or page hint on it, or while ID fields show. **Console** chooses `console.assetlib.dev` (the default) or `localhost:3100 (development)`. Figma rejects IP-literal development domains such as `http://127.0.0.1:3100`, and the console accepts the `localhost` host for token routes and the connection request routes in local mode; its sign-in, connect page, and every console page the plugin links to (**Open console**, **Open in console**, **View in console**, a toast's **Review**, a component's documentation link) are on `127.0.0.1`, which the plugin only opens in your browser. Other origins are rejected.

Once connected, the plugin shows its tabs, and the account chip at the top right names the connection: "{Workspace} · {App}" when the console said (a long workspace name shortens first, so the app's name stays whole, and an app name that leaves the workspace no room shows alone, as in a narrow window), else the app by the start of its ID. A Figma toast says "Connected to {Workspace} · {App}" (the app's name alone when both would pass the toast's 100 characters), or "Connected to Assetlib" when the console gave no names. The chip opens the account menu below the top bar: the app's name (without names, the app as the chip names it, with both IDs on hover), "{Workspace} · Connected with token {prefix}…", **Open console**, **Connect with browser**, **Update token**, and, set apart on the right when the actions fit on one line, **Disconnect**. The actions wrap in a narrow window. **Connect with browser** starts a request offering the current workspace; its approval replaces the pasted connection without ending the pasted token (an owner revokes it). **Update token** shows the token form (paste another token and choose **Save token**; with the field empty, it tests the saved connection again); the form shows at once while the connection needs attention. A refused pasted token offers **Connect to Assetlib** as the panel’s main button, with secondary **Save token** below; a blank Save token says "Paste a new token, or choose Connect to Assetlib above." without sending anything. A network or server failure keeps **Connect** as the form’s main button. Otherwise the footer's **Insert** or **Send** is the main button. **Esc** closes the menu, which is a menu again the next time it opens. **Disconnect** forgets the token on this device and returns to the first-run screen; after a refused pasted token it says "Disconnected. Assetlib had stopped accepting that token." with no Undo. For a healthy pasted token, its toast has **Undo** for six seconds, which saves the same connection again (only an owner can create another token), unless you connected again meanwhile. A healthy pasted token itself keeps working elsewhere until an owner revokes it in the console.

A connection made with **Connect to Assetlib** shows "{Workspace} · Connected as {email}" in the account menu, with **Open console**, **Switch workspace**, and **Disconnect**, and no token form. **Switch workspace** starts a new request while the current connection keeps working (Insert and Send included); once the new one is approved, the token it replaces is ended (and so is a browser connection another plugin window saved on this device meanwhile), and **Cancel** leaves everything as it was. A plugin window whose connection another window replaced that way takes up the device's connection when the console refuses its own, rather than asking you to connect again; a draft refused that way says "The connection changed in another plugin window, so nothing was sent. Try again." **Disconnect** ends the token in the console first, so it has no Undo: "Disconnected. This connection was ended." If the console can't be reached, the plugin forgets the connection anyway and says "Disconnected on this device. End the connection in the console under Settings › Profile." When a linked layer belongs to another app on the same console, the Sync bar says "Switch to that workspace to sync it." with **Switch workspace**, which offers that workspace first.

Each time the plugin opens, it tests the saved connection by reading the placements. A failed test opens nothing: the chip shows a warning, and the view in front says why, once, with the one action that helps. On **Insert** the list says it in its place; on **Send** a notice above **Placement** says it. The action is **Try again** (offline, busy, a server error, or a timeout; on Send it runs the test again) or, for a refused pasted token, **Connect again**, which starts a browser request offering the current workspace. It says "Assetlib no longer accepts this token. Connect again to approve the plugin in your browser, or paste a new token." A token lacking the required scope keeps **Update token**, which opens the settings at the token field. While the settings are open the reason shows under the token field instead (a refused token is marked), and the list or the notice steps aside, so the failure is never said twice; a test that fails while you are in the settings (after you saved a new token, say) is said there and focuses the token field, unless you are typing in another field. A refused token on a later read (the Insert list, or an insert) works the same way. A refused Send or Sync also warns the chip and offers **Connect again** in the error line. A connection made with **Connect to Assetlib** never shows the token form: when the console no longer accepts it, the view says why ("This Figma connection was ended.", "Your role no longer allows sending drafts. Ask a workspace owner, then connect again.", or "This Figma connection expired.", each followed by what to do) with **Connect again**, which starts a request offering the same workspace; a refused insert or draft says it in the error line with the same action. The chip returns to connected after the next successful read, and the reason goes. An artwork read that started before a newer refusal still supplies artwork, but cannot clear that refusal or its recovery action. If the test itself failed, for example while offline, the next successful read also loads the placements before the label changes, so Send works without another test. If Figma can't save new settings, the previous connection keeps working, with its lists, Send, and Sync, and the message under the token field asks you to try again; the token you pasted stays in the field.

Connections saved by earlier builds may name the console's previous host, `https://assetlib-console.vercel.app`, and have no names. The plugin loads such a connection on `https://console.assetlib.dev` with the same token and saves the change, and sync destinations remembered under the previous host still apply. The console still accepts app tokens on the previous host, and the manifest keeps it allowed so an unrebuilt `dist/` keeps working. New connections cannot choose it. Saved tokens are not checked against the `alk_` format again, so an older save keeps loading.

Settings and the token are saved through `figma.clientStorage` on this device. The token field is cleared after saving, and only a short prefix of a pasted token is displayed afterward; a token the console issued to **Connect to Assetlib** is never displayed or put in a field. While a request waits, only its read key, code, expiry, and when a plugin window last asked about it are kept there (at most 15 minutes, and deleted when the request ends). The plugin does not log the token. Figma client storage is local plugin storage, not an encrypted credential vault; clearing it or changing the plugin ID loses the connection and remembered sync destinations.

Each Send records which Figma file the art came from, by the file's key. Where Figma gives the plugin the key (a development or organization-private plugin), the plugin uses it, and saves it in the document with the first layer it links. Otherwise it uses the key saved in the document, which everyone who opens the file shares. A file with neither is asked for its link once, at its first **Send to draft** or **Sync** and not when the plugin opens: the Send tab says, in a neutral notice, "Link this file once so Assetlib can trace art back to it. In Figma, press Cmd+L to copy the file's link, then paste it here." (Ctrl+L on Windows and Linux). The plugin reads the key from `https://www.figma.com/file/<key>/…` or `https://www.figma.com/design/<key>/…` (a branch's link, `…/<key>/branch/<branch key>/…`, names the branch), saves it in the document, and then runs the Send or Sync that asked. The link's file name is compared with this file's, letters of every script included; a link that names another file (for example "This link is for “Coast-house”, but this file is “Roam onboarding”. Paste this file's link."), or names none, is questioned and saved only after **Use anyway**, and editing the link withdraws the question. In a file you can only view, the plugin can't save it in the document, so the key lasts until you close the plugin, and the Send tab says so. Once the key comes from the document, the Send tab names the file it was saved for ("File: {name} · Change"). A duplicated file keeps its original's key until its own link is pasted with **Change**. The link last pasted on this device fills in the field only for the file it names.

## Insert artwork

The plugin opens on **Insert** (it remembers the tab you last used). The first connected Placements view explains placements, cells, and environments in a callout that scrolls with the list, with **How the Figma plugin works** linking to the [Figma guide](https://www.assetlib.dev/guide#figma). **Got it** hides it and focuses the search; the first successful insert or drop hides it too. It stays hidden on Images, when the list is empty or has an error, and after dismissal on this device. The drag hint stays hidden while the intro shows. **Search placements or screens** matches placement keys and screen names. Its bars stay fixed and only the list scrolls: the top bar (the **Insert** and **Send** tabs and the account chip), the search field and **Refresh**, then **Placements**, **Images**, or **In this file** and, for placements, the environment. A chosen placement’s cell strip scrolls separately in its footer when needed.

The window opens 420 px wide and 64 px shorter than the canvas on screen, from 480 to 720 px tall. Drag the grip in its bottom-right corner to resize it, from 320 × 480 up to 900 × 1000; only the list grows. The size you leave it at is remembered on this device, and a double-click on the grip goes back to the default. Below 400 px wide the environment becomes a dropdown; from 560 px a placement’s ratio and declarations move to a column on the right, with its short name over its full key, and the image grid adds columns as it widens.

- **Placements** lists the app’s placements grouped by screen. Each 56 px row has a preview in the placement’s proportions, a short name (the last part of its key), and the full key and ratio with its declared axes, such as `3:4 · 2 states · light/dark · arm b`. An empty cell has a dashed slot in the same proportions. One chip says **{n} behind**, **In this file · current**, **In this file** (copies only), or **Not in this file**; until all pages are included it says “on this page” instead. Behind counts linked layers whose art differs from their environment’s current art; select a layer and choose **Update** to change it. Before artwork loads the chips say only whether the placement is present. **Unavailable** and **Needs re-upload**, with a warning glyph, take precedence when Insert cannot use the base art. Draft status stays in the row’s tooltip: no art, new or changed Draft art, or how many cells inherit. New and Changed compare cells’ own Draft art with Production when it has a release; inherited art is present, while a null cell shows nothing. Production is the automatic environment, falling back to Draft until a Production release exists. Picking **Draft**, **Staging**, or **Production** remembers an explicit choice; old saved environments without an explicit choice use the new automatic default. An explicitly chosen environment without a release shows Draft and a note until it has one. Environment tooltips explain where the art goes and name published releases and dates. Sending changes Draft; publishing stays in the console. Select a row to show its cell strip when it has several cells. State rows start with the default, and columns show Control then the declared arms, with Any, Light and Dark within each. Each cell previews its art; a dashed outline means it inherits, and its tooltip names the source. The footer names the chosen axes and any inherited art. A cell with no art in the shown environment says "No image in Draft for this cell yet.", or "No image in {Environment} for this cell. Sending puts it in Draft." With one exportable layer selected, **Send selected layer here** opens Send with that placement and cell chosen and **Send to draft** focused; without a selection, only the note shows. This explicit Send keeps the footer visible even when the layer is already linked to that empty cell. Inherited art is present, so it offers no empty-cell action.
- **Images** lists every active image in the app, newest first, in a grid, with search by name and **Load more**. Each tile's name takes at most two lines and then ends in an ellipsis, breaking after a `.`, `_`, or `-` first (`travel.coast.|background`) and anywhere only as a last resort; its tooltip has the whole name, size, and type.
- **In this file** lists this app’s linked layers and copies, grouped by their top-level frame. Search matches layer names, placement keys, and frame names. Each row shows the linked image, layer name, cell and environment, with **Behind**, **Current**, **Copy**, or **Removed** after artwork loads. Click a row, press **Enter**, or double-click to select and reveal it on the canvas; arrows only choose in the list. The Sync bar then offers the layer’s available actions. On a multi-page file the list starts with “This page only.”; **Include all pages** loads the other pages for the rest of this plugin session and labels groups with page and frame. **Refresh** scans again, as does returning to this view or window. The local scan holds at most 2,000 entries. It sends no document inventory to the console and never updates artwork by itself. This view has no Insert footer or environment selector.


While a list loads it shows grey placeholder rows or tiles. A list that can’t load shows a headline above its reason, with the one action that helps: “Couldn’t load the list” with **Try again** (a network, busy, or server error), “Connect to Assetlib again” with **Connect again** (a refused token), “This token can’t be used here” with **Update token** (a token without the Draft permission; it opens the settings at the token field), or “Insert isn’t available here” with **Go to Send** (a console without the Insert routes). The action is primary unless the Sync bar shows, when it is secondary. An empty app says where placements come from (**Read the guide**), an empty library offers **Open console**, and a search with no matches offers **Clear search**.

While the plugin connects, sends, syncs, inserts, or updates a linked layer, only the actions that would conflict with it wait (**Connect**, **Disconnect**, **Send to draft**, **Sync**, **Insert**, **Update**, and **Match ratio**); they keep keyboard focus and say they are unavailable, and choosing one then does nothing. The running one says what it is doing on its button ("Connecting…", "Sending…", "Syncing…", "Inserting…", "Updating…"), with a spinner, in ink, so it never looks like an unavailable one. Update keeps the Insert button’s usual label; only Update says "Updating…". The tabs, lists, search, connection fields, environment, and scale stay usable throughout. A list that is loading can still be searched, and **Refresh** or a new image search replaces the load. An error that arrives while you type in a field (a token, a file link, a search) is shown and announced without taking focus from the field; that includes a failed connection test, which opens nothing and marks the token field without moving to it. When a connection test passes, the connection settings close and keyboard focus moves to the account chip. They stay open while you work in them: while you are in one of their fields that you moved to during the test, or while an entry you changed (a new token, an edited ID, another console) is not saved yet.

**Keyboard.** **Tab** moves between the panel's parts: the tabs, the account chip, the search, **Refresh**, **Placements**, **Images**, or **In this file**, the environment, the list, the Sync bar’s title and actions (when the selected layer is linked), then the footer. The tabs, each segmented control, and the list are one stop each, and the arrow keys move inside them: **←** and **→** switch tabs (and show the one they reach) and choose within the Browse choices, the environment (passing over one with nothing published), and **1×**/**2×**/**3×**. In the list, **↑** and **↓**, **Home**, and **End** move the choice, and typing the start of a placement’s short name or full key, a layer name, or an image name jumps to the next one that matches; in the image grid **←** and **→** move by one tile and **↑** and **↓** by a row. **Enter** or a double-click inserts the row or tile, with the cell chosen in the footer (choosing the chosen row again keeps it); on one Insert can't use, it says why instead. In the cell strip, one checked cell is a tab stop: **←/→** choose in its row, **↑/↓** choose the same or nearest occupied column in the next state row, **Home/End** choose the row’s ends, and **Space** chooses. **Enter** or a double-click inserts that cell. The strip is at most 160 px tall and scrolls when it has many cells. In **In this file**, **Enter** and a double-click reveal the layer instead of inserting. **/** (outside a text field) or **Cmd+F** (Ctrl+F on Windows and Linux) focuses the search from either tab, with its text selected. **Esc** in the search or the list clears the search, then the choice. When an insert fails, focus moves to its error.

**Drag.** You can also drag a row or tile onto the canvas. Only one that **Insert** could insert now drags (not one marked **Not set**, **Unavailable**, or **Needs re-upload**, nor an image over 4 MiB in every version, nor while something else is being inserted, sent, or synced); the chosen row drags the state, appearance, and A/B arm its footer shows. The download starts as the drag starts. Where it lands decides what happens: on an image frame (never an instance; a frame showing an image with nothing inside, such as one the plugin inserted), its image is replaced, as **Fill** or **Replace image** would; anywhere else a grey placeholder named "{name} · loading" appears there, centered on the drop point (or added last to an auto layout frame), inside the nearest frame, group, section, or component that can hold it, or on the page. An instance’s image is never replaced by a drop; its nearest permitted ancestor holds the placeholder. Placement art cannot go inside a component or instance. The placeholder fits both dimensions of a frame or component without enlarging the reference art; elsewhere **1×**, **2×**, or **3×** sets its size. It takes the image when its download finishes, and the placeholder and its image are one undo step. If the download fails, the placeholder goes and the error says why. A drag that ends back in the plugin window inserts nothing, and a file dragged from your desktop keeps Figma's own behaviour. Rows and tiles that drag show a grab cursor. Until your first insert, a hint bar under the list says "Drag onto the canvas, or select an item and press Enter." ("Drag onto the canvas or press Enter." below 400 px), except while the Sync bar or intro shows; its close button hides it for good on this device.

What is selected on the canvas decides what the footer’s main button does, and names it. The note explains the destination and link before any component limitation: a fill names the layer or count and cell, says its size and position stay for one layer, and counts skipped layers; an insert into a container names it; an insert beside an unsupported selection says so. Replace names the old and new cell when it relinks, or says the link stays (including with a library image). Nothing selected needs no note:

| Selected | Button | What happens |
| --- | --- | --- |
| Nothing | **Insert** | A new layer, centered in the current view |
| One instance of a local Assetlib placement component | **Replace in component** or **Fill component** | Changes the main’s image and link, so every instance follows; never writes an override on this instance |
| One instance of an Assetlib component from a library | **Insert** | A new layer beside it; change the library’s image in its own file |
| Several layers including Assetlib placement instances | **Fill {n} layers** when any can be filled | Skips those instances so they keep following their main; the note counts them |
| One linked shape, frame, component, or other instance that shows an image (art inserted, filled, replaced, or sent from this app; not a copy) | **Replace image** | Its image is swapped, and it is linked to the chosen cell |
| A frame or component with layers inside | **Insert into {name}** | A new layer inside it, centered, or added last in an auto layout frame. Placement art is a component, and Figma doesn't put a component inside another, so with a component, or a frame inside one, it is **Insert** and goes 40 px right of it instead |
| Shapes (rectangle, ellipse, polygon, star, vector, boolean), or frames, components, and other instances with nothing inside | **Fill {name}** or **Fill {n} layers** | Each one shows the image; text, lines, groups, sections, and frames with layers inside are skipped |
| Only layers that can't show an image (text, lines, groups, sections, linked by a Send or not), or an instance with layers inside | **Insert** | A new layer 40 px right of the selection |

A new layer has an image fill and is selected, and a Figma toast says so: art from a placement as a component, an image from the library as a frame. Placement inserts are named after the placement and cell (for example `onboarding.hero · b · dark`) and sized to the placement's width and height; image inserts take the image's name and size. **1×**, **2×**, and **3×** show only for a new layer on the canvas or beside the selection: 1× keeps the reference size, 2× and 3× divide it. Into a container, the art fits both its width and height while keeping its proportions, never enlarging the reference size. The footer shows the actual resulting size first (for example `→ 390 × 520 · Production`), then the chosen cell’s axes. Fill and replace keep the existing layer’s dimensions. An item that can’t be inserted shows no scale control; below 400 px the footer drops its preview so the name stays readable. Figma gives instances no new layers, so an instance with layers inside is not a frame to insert into; if Figma refuses a frame anyway, nothing is left behind and the error suggests **Insert as new layer**. A component, or a frame inside a component, takes a library image but not placement art, which is a component itself; the footer then says the art goes beside it.

A fill keeps the layer's size, position, constraints, and other paints, so the scale control is hidden. It replaces the layer's topmost visible image paint, keeping its scale mode, crop, filters, opacity, blend mode, and visibility, or adds a visible image paint on top when none is visible. Hidden image paints stay as they are. Each layer filled with placement art is linked to the cell with its own ID, so each syncs on its own and later shows **Replace image**. Layers inside an instance are filled but can't be linked, since Figma keeps no plugin data there, and the toast says Sync isn't available for them (it says so too for any other layer Figma doesn't let the plugin link). If Figma refuses the image on some of the selected layers, the toast says how many it filled, and whether Sync is unavailable for any of them. **Replace image** relinks the layer to the chosen cell; on a component the plugin inserted, the description agents read then names that placement, and a layer still named for the placement it showed takes the new one's name (a description or name you wrote yourself is never changed). A library image never writes or removes a link, so a linked layer filled with one stays linked to its cell. In the modes that use the selection, **Insert as new layer** under the main button makes a new layer beside the selection instead.

Every insert, fill, replace, and drop is one undo step (Cmd+Z). The toast after a fill, replace, or Update offers **Undo**, which takes back the fill's image, link, name, and marker and nothing else. It isn't offered when the selection moved away from the filled layers before the fill finished, or when any filled layer had a fill style, is an instance, or sits inside one; Cmd+Z on the canvas still takes the fill back. The toast goes when the selection or the page changes, when a Send or Sync starts, when the plugin makes another edit (a file link, a Send's link, Match ratio), or, with one filled layer selected, when it is resized or renamed or its image changes on the canvas (Cmd+Z included). Undo takes nothing back, and says "Not undone. These layers changed after the fill.", if a filled layer was moved, resized, rotated, hidden, locked, renamed, relinked, repainted, restyled (fill style, opacity, strokes, effects, corners, constraints), moved into another layer, or deleted since the fill. Edits Figma doesn't tell plugins about stay as they are after Undo: one to another layer that leaves the selection as it was (hiding or locking it in the layers panel, say), a reorder among siblings (except in an auto layout frame, where moving the layer changes its position and Undo says "Not undone"), or a change to a filled layer the guard doesn't compare (stroke position or dashes, export settings, layout grids, absolute position, prototype links). Undo is its own step, so Cmd+Z after it brings the fill back. If Figma refuses one of Undo's changes, Undo puts back what it already changed and says it didn't undo the fill. The choice, the tab, the browse mode (including In this file), an explicitly chosen environment, the scale, the window's size, and whether the hint bar and intro were dismissed are remembered on this device.

A placement's component carries a description that names the placement and its size, and a documentation link to the app's placements in the console. Figma's MCP server passes both to coding agents that build the screen from the file, so the description tells them the image is data-supplied and that its exact match in code is the accessor generated for that placement, which carries the bundled fallback: they render it with that accessor instead of a downloaded file, and download it only as the bundled fallback of a placement not yet in the app's catalog. These are the two exceptions Figma's design-to-code skill allows to its rule that agents download every image. Copies and instances of the component carry the same description. If the file is published as a team library, these components appear in the publish dialog; leave them unselected.

For a new layer (and a drag) the plugin downloads the largest prepared version of the image that is PNG or WebP and at most 4 MiB, preferring PNG; for a fill or a replace, the smallest one at least three times as wide as the image is drawn in the layers (it covers each layer, so a layer proportionally taller than the image draws it wider than the layer), never wider than the original, else the largest. Figma accepts PNG but not WebP, so a WebP version (photos have only WebP versions) is converted to PNG in the plugin window first, with a Display P3 image converted to sRGB. An image larger than 4 MiB in every version can't be inserted, and the footer says so before you try, with **Open in console**; so does an image uploaded before the console prepared versions, which has none (upload it again to use it in Figma). A version downloaded for an insert or a drag is kept in the plugin window for a minute, so dropping it, or inserting it again, doesn't download it twice. Originals are never downloaded. An animated (Lottie) image is inserted as its still poster, and an SVG image as its PNG version, not as editable vectors.

Previews are downloaded the same way, from the smallest version up to 512 KiB, and shown from memory; an image without such a version shows an empty checkerboard. Only rows and tiles within 300 px of the list's view load previews, three at a time, the most recently scrolled-in first; one that scrolls away before its download starts gives up its place. The footer’s and Send’s current Draft previews load whenever they show. A preview that fails with a network or server error is tried again after 1 and 4 seconds, and **Refresh** tries every failed preview again. If the console limits requests, previews pause and resume shortly.

## Send artwork

On the **Send** tab:

1. Select exactly one layer. The plugin shows its name and size in whole pixels, or says why the selection can't be sent ("Select a frame or layer to send.", "Select one layer. Sending several at once isn't supported yet.", "This layer has no visible area to export.").
2. Choose a placement: nothing is chosen for you, unless the layer is linked or was sent before. Placements are grouped by screen, in the Insert list’s order. With an exportable layer selected, placements within 2% of its ratio come first under **Fits this layer**, and appear only there. State, appearance, and A/B arm choices are limited to what that placement declares. Once artwork has loaded, each option describes the Draft cell it would choose with the other pickers kept as they are: " (not set)" for no art, " (inherits)" for inherited art, and no suffix for its own art. A 32 px preview under the pickers shows the chosen cell’s current Draft art: "Now in Draft" for its own art, "Now in Draft: inherits Control · Any art" for inherited art (naming its source), or an empty slot with "Nothing in Draft yet". It stays hidden until artwork has loaded and a placement is chosen. **Any** appearance and **Control** arm map to `null` in the API. Omitting a state uses the placement's declared default state; choosing **Default** or that named state means the same cell. An explicit state must be declared. The console publishes a state set only when every state has a draft image, so a new state set needs each state sent before it can be published. The line under the pickers names the largest PNG the export may make (for example "Exports up to 1168 × 876 PNG, 3× this layer."); it steps aside while the ratio callout below says the export can't be sent. With nothing to send, the layer card is a dashed slot saying why.
3. Choose **Send to draft** in the footer. On a linked or remembered cell, the footer is hidden and **Sync to draft** is the main action, except after **Send selected layer here**; **Send as a new image instead** under the pickers uploads to that cell without replacing earlier sends in other cells. While it runs, that action itself says "Sending…" with a spinner, in ink, and keeps focus. Choosing another placement or cell shows **Send to draft** as the main action and makes Sync secondary; the line under the export size says it will link the layer there after Send, and where it stays linked until then. An empty picker does not count as another cell. The first Send or Sync in a file whose key the plugin doesn't have asks for the file's link first (see [Sync later edits](#sync-later-edits)). When the layer's ratio differs from the placement's by more than 2%, Send stays unavailable and a callout gives the layer's size and the ratio and size the placement needs ("This frame is 390 × 844. home.banner needs 2.44 : 1 (1170 × 480). Match ratio makes it 390 × 160. Or choose a placement that fits."). The last sentence appears only when the height would change by more than half. Resize the layer, or choose **Match ratio**: the plugin keeps the layer's width and sets its height to the placement's ratio (an auto-layout hug or fill height becomes fixed), as one undo step. The size follows a resize on the canvas within a quarter of a second, without reselecting.
4. A Figma toast says where the art went ("Sent to {placement} draft", with **Review**, which opens the console's releases), and the result under the form says "Draft updated. Publish it from the console when it's ready." with **View in console**, in place of the footnote about drafts. When a Sync also updated other draft cells that used the layer's earlier art, the result says how many, with the cells under **Details** (each named by its placement and the axes it declares). The sent layer is now linked to that cell (see below); a component's description, when Assetlib wrote it or it was empty, then names that placement for coding agents, as an insert's does.

Exports are PNG at up to 3× the layer’s size, capped by the sharpest raster’s native density (at least 1×) and a 2048 px long edge, the largest rendition Assetlib keeps. The export snaps down to a multiple of the placement’s reduced ratio when possible: a 390 × 292.5 layer for 1200 × 900 exports 1168 × 876. When the edge cap binds, the note ends “the largest size Assetlib keeps.” If the PNG exceeds 3.3 MB, the plugin tries 2× and then 1× with the same native-density and edge limits, skipping duplicate sizes, and refuses it if none fit. Figma preserves the layer’s aspect ratio; the plugin does not crop or stretch it. The placement’s width and height are a reference for proportions and the app’s requested size. Before upload the plugin reads the PNG’s own dimensions and refuses a long edge over 2048 px or a ratio more than 2% off the placement.

If a binding fails with HTTP 409, the console may still have created the image. The result says so with the console's own words ("The image was uploaded, but Assetlib couldn't put it in {placement}: …") and **Open image in console** in the same callout, and no success toast appears; check the console before retrying to avoid unnecessary duplicate images. A send does not publish a release; drafts don't go live until someone publishes in the Assetlib console.

## Sync later edits

Art inserted from a placement, a layer filled or replaced or dropped with it, and a layer sent to a placement are linked to their cell. Whenever one is selected, on either tab, the **Sync bar** above the footer says "Linked to {placement}", with the cell and where that image is published: "in Production (release {n})", "in Staging, not in Production", or "in Draft, not published", checking Production first. While the layer stays selected, the bar follows a resize, a rename, or a Cmd+Z on the canvas within a quarter of a second. Update, changed or missing art, and publication status are offered only from artwork whose request started at or after this plugin window first saw the layer’s current link. Those times come from this window’s clock, never the time another device wrote in the link. Until that artwork arrives, or when none of those environments has that image, it keeps "{Environment} art" (a sent layer says "sent to Draft"). The image’s preview loads on either tab and while Images is browsed, using the link’s environment, and refreshes after a bound Send or Sync along with the row’s thumbnail and tags. A quiet refresh keeps the previous art without an error line if it fails. A newly seen link reads artwork once, even within a minute of the last load, unless a quiet read started at or after it was seen is already waiting. Reselecting the same layer and link keeps its first-seen time and starts no further read. Returning to the window or making it visible refreshes artwork when the last load finished at least a minute ago. **Open in console** opens the placement’s page when the loaded artwork names it, otherwise the image’s page; it stays hidden during Update and the ratio gate. Choose the title to show the placement in Insert › Placements, clear a search that hides it, choose its cell and published environment, and focus the row. A title reveal that starts a full list load waits for its row before scrolling and focusing. A pending reveal is discarded when its artwork load finishes unless Insert › Placements is still in front and the selection still links the same placement. The title also reveals a copy’s original placement; a removed placement or another workspace has a plain title. **Sync to draft** sends later edits back. **Cmd+Enter** (Ctrl+Enter on Windows and Linux) is Sync too, outside the connection settings, except while Update is offered or the Send pickers name another cell: while Update is offered it changes nothing on the canvas and announces "Update first, or choose Sync to draft to replace Draft’s art with this layer."; with another cell chosen, it announces which cell Sync updates and that **Send to draft** sends to the chosen one. The bar’s tooltip ends "Sync updates Draft only; publishing stays in the console." On Send, the linked cell hides the footer (except after **Send selected layer here**) and keeps the separate **Send as a new image instead** action; choosing another cell restores the footer and relinks only once sent. Sync re-exports the layer and sends it to that cell's draft with `rebind: true`: the console replaces the layer's earlier sends wherever they are bound in draft in the connected app, the result says how many other cells it updated (with the cells under **Details**), and a toast says "Synced {placement} to draft" with **Review**. A linked layer's first Sync fills exactly its cell, never the cell it inherited from. The link travels with the file, so teammates connected to the same app see the Sync bar on the layers you inserted or sent.

When the cell’s current art in the linked environment differs, a layer that qualifies for **Replace image**, shows a visible image, and has nothing inside offers **Update** as the main action, with "{Environment} has different art now" and a preview of the art it will bring. Update replaces the image in place, keeping its crop, scale mode, size, position, cell, and environment, and records the new image in the link. It is one undo step; the toast says "Updated {name} with the latest {Environment} art" with **Undo**. The bar’s tooltip says "Update puts this {Environment} art in the layer. Sync updates Draft only; publishing stays in the console." Sync is secondary and its tooltip says "Sync replaces Draft’s art for this cell with this layer." The ratio gate keeps Match ratio primary. A sent frame with layers inside, a layer without a visible image paint, or a layer that cannot use Replace image (such as text or a section) never offers Update; if its link names Draft and Draft now has different art, it says "Draft has different art now. Sync replaces it with this layer." If the linked environment no longer has art, it says "{Environment} no longer has art for this cell." without Update. A layer whose link or contents changed before Update is applied is refused with "This layer changed since the plugin checked it. Select it again."

Linked layers also show **Sync to Assetlib** in Figma's properties panel, with their cell under it, and a document with any linked layer shows **Open Assetlib** when nothing is selected. **Sync to Assetlib** opens the plugin with the Sync bar focused; it never syncs by itself. The plugin’s menu and Figma’s Actions search also offer **Open Assetlib** (the remembered tab, without moving focus), **Insert artwork…** (Insert with the search focused), and **Send selection to draft…** (Send). Insert and Send remember the tab they open, as a tab click does. Without a saved connection, every command shows the first-run screen.

The Sync bar also says when Sync can't run, with the one action that helps:

- The layer's ratio is more than 2% off the placement's: "This frame is {w} × {h}; {placement} is {W} × {H}. Match ratio makes it {w} × {h′}.", with **Match ratio** as the bar's main button, and Sync unavailable. On the Send tab the callout above says it when it is about the placement chosen there.
- A copy of a linked layer (for example made with Cmd+D) isn't linked: "Copy of a linked frame. Copies aren’t linked. Send it to a cell of {placement}." **Send…** opens the Send tab with the first other cell without its own Draft art (inherited or null) when artwork has loaded, else the first other declared cell; a single-cell placement keeps the original cell. Focus goes to the first visible cell picker, or Send if there are none, for a **Send to draft** of its own (not a Sync, so the original's earlier sends stay). Once sent, the copy is linked in its own right.
- A layer linked to a placement in another app or workspace: "Linked to another workspace. Connect to that workspace to sync it."
- A placement or cell that no longer exists in the app: "Linked to {placement}. This placement no longer exists in this app." (or "This cell…"); **Send elsewhere…** opens the Send tab to choose another.

The bar shows the linked image's preview only once it has one: another workspace's link, a removed placement, or art the artwork request hasn’t loaded shows no image square. Layers linked before the Sync to Assetlib button existed (and their documents) get the button the next time they are inserted, filled, replaced, sent, or synced; nothing adds it to them in bulk.

After a Send or Sync the plugin also remembers the layer's placement and cell on this device, and that wins over the layer's link there. **Replace image**, a fill with placement art, or **Update** links the layer to its resulting cell and forgets the target this device remembered for it, so its next Sync goes to the new cell; Undo doesn't bring that target back, so a layer that was sent but never linked then needs **Send to draft** again. Another device that sent or synced the layer keeps its own remembered target until it sends the layer again. Library images are not linked to a placement. A layer inside an instance can't be linked, and a draft the console didn't put in its cell (the 409 result above) links nothing.

## Data and network access

The plugin sends only the selected node's exported PNG bytes (base64 in JSON), node ID and name, file key, PNG export settings, chosen placement coordinates, asset name, schema version, and sync flag. `source.versionId` is `null`. The app-scoped draft token is sent as a bearer token to the chosen console origin, including once to `GET /api/token` when it is pasted and once a session for the saved connection's names (again when a connection change cut that request short or the answer could not be used, and the same connection came back). **Connect to Assetlib** sends `{"client":"figma"}`, with the organization and app IDs of a workspace this page's layers link as a hint when there is one, to start a connection request, with no credentials; then the request's read key as the bearer to ask whether it was approved or to cancel it; and a connection's own token to end it, at **Disconnect**, after **Switch workspace** or another plugin window's connection replaces it, or when Figma couldn't save it. When the start, or a pasted token’s `GET /api/token`, gets no answer, it asks `GET /api/token` with no token at all, to tell an older console from one that can't be reached. It opens the console's connect page in your browser with the request's write key in the URL's fragment; the plugin never stores the write key, and the browser doesn't send a fragment to a server.

It never sends the Figma document, unrelated layers, or a Figma token. Selecting a frame or group exports its visible contents as one PNG; it does not upload its editable layer tree.

It receives the pasted token's organization and app IDs, the workspace and app names when the console returns them, and the token's scopes; for a connection request, its read and write keys, code, and expiry, and once it is approved, the issued token, the organization and app IDs and names, and the email of the account that approved it, which is saved with the connection on this device and shown as "Connected as"; the app's placements; for each placement cell, which image it shows in draft, staging, and production, and when staging and production were published; the app's image names, sizes, and prepared versions; and the bytes of the versions it previews or inserts. Rendition URLs are built from the image ID and hash; the plugin never sends the token to a URL taken from a response.

Art inserted from a placement, a layer filled, replaced, or dropped with it, and a layer sent to a placement store plugin data `assetlib.link.v1`: the console origin, organization and app IDs, placement key, state, appearance, arm, environment, image ID, the node's ID, and the insert or send time. It never holds the token. The document stores `assetlib.file.v1` on its root: the file's key, whether it came from Figma or a pasted link, when it was saved, and the file's name then. A linked layer's relaunch data holds the text under its **Sync to Assetlib** button (its placement key, cell, and environment), and the document's holds the text under **Open Assetlib**. Plugin data is private to this plugin but travels with the file, so anyone with a copy of the file can read it; organization and app IDs are not secret, since they appear in public delivery URLs. Its component description holds the placement key and size, and its documentation link is `{console}/w/{organization ID}/{app ID}/placements` (on `http://127.0.0.1:3100` for the development console); anyone who can open the file reads both, including coding agents through Figma's MCP server. Neither holds the token.

The manifest declares:

```json
{
  "allowedDomains": ["https://console.assetlib.dev", "https://assetlib-console.vercel.app"],
  "devAllowedDomains": ["http://localhost:3100"],
  "reasoning": "Reads images from, and sends exported artwork to, the Assetlib console you connect."
}
```

A drag onto the canvas hands Figma the drop point and a description of what to insert (the name, size, scale, placement cell, and image ID), never the token; the download is the same request as an insert's. Every request goes through one module that refuses any other route: `GET /api/token` on the chosen console, which tells a pasted token its own organization and app (tried once, so the form answers at once), and which, without a token, tells an older console from one that can't be reached after a connection request or a pasted token’s `GET /api/token` got no answer; the connection request routes `POST /api/plugin-connections`, `POST /api/plugin-connections/claim`, `POST /api/plugin-connections/cancel`, and `DELETE /api/plugin-connections/current` (each tried once with a 10-second timeout; the plugin's own schedule asks again); and exactly these five calls under `/api/apps/{orgId}/{appId}/`: `GET placements`, `GET placements/artwork`, `GET assets` (with `limit`, `cursor`, and `q`), `GET assets/{assetId}/renditions/{sha256}`, and `POST drafts`. Links into the console (**Open console**, **View in console**, **Open in console**, and a toast's **Review**) open in your browser; they are navigations built from validated IDs on the connected console (for the development console, `http://127.0.0.1:3100`, where it signs you in; its requests stay on `localhost:3100`), including a placement’s ID, and never carry the token. The placement page link needs the artwork loaded; before that, **Open in console** opens the image page. The placements endpoint accepts `draft` or `declare`; the other four require `draft`. All of them authenticate only with that bearer token, never cookies, and must allow cross-origin requests from the Figma plugin UI. The hosted console does so for all five on both production hosts (checked on October 11, 2026); a console without the Insert reads answers them 404, and Insert then says it doesn't support Insert yet while Send keeps working. Rendition bytes are served `private, no-store`. The plugin never calls the public delivery routes. Local development requires that console server to be running on port 3100. The development-only origin is not available to a published plugin.

A read times out after 20 seconds, and a download after 20 seconds plus 15 per MiB the console listed for it. A read that fails with a network error, 502, 503, or 504 is tried twice more, after 1 and 4 seconds (or after the wait the console asks for in `Retry-After`, when it exposes one and it is longer), and one answered with 429 is tried again only when the console asks for a wait. A read whose console asks for a wait of more than 30 seconds is not tried again. A draft upload times out after 30 seconds plus 15 per MiB of its body and is never retried, since it may have arrived; the message says so. Searching or refreshing while a list loads abandons the earlier request, and changing the connection abandons every request in flight.

Messages are plain and say what to do next, without HTTP codes or developer terms: a refused or revoked saved pasted token offers Connect again or a new token (a revoked token’s 403 included, wherever it is met); a freshly pasted token the console refuses still says to create a new one in Settings › Tokens; a token without the Draft permission says so; HTTP 409 keeps the console's own message; an export too large to send says "over 3.3 MB as a PNG" (whichever limit it met: 4 MiB of PNG, Vercel's 4.5 MB request, or HTTP 413; every PNG under 3.3 MB fits); a busy console (429) asks to try again in a minute; a server error says "Assetlib had a problem ({status})"; an unreachable console says to check the internet connection (the local console is named, since it may not be running); timeouts say how many seconds the plugin waited, and a draft that timed out may have arrived anyway. A console without the Insert endpoints (a 404) is reported as such while Send keeps working, a network failure on an Insert read is said as one ("Can't reach Assetlib. Check your internet connection.", with **Try again**), and an image removed after the list loaded asks for a Refresh, with **Refresh** in the error line. When a pasted token’s `GET /api/token` fails with a network error, a tokenless request distinguishes an older console that needs organization and app IDs from one that cannot be reached; only an answer enables the ID fields; a later **Connect** with the ID fields still empty asks the console about the token again. Finished operations are Figma toasts of at most 100 characters; every toast, result, and error is also announced through one status and one alert region. The shared contract allows at most 4 MiB decoded PNG bytes and 4,500,000 bytes for the JSON body, Vercel's request limit, so a base64 PNG above about 3.3 MB decoded does not fit.

`npm run e2e:local` runs the same bundles and fakes against a running local console with Node's real `fetch`. Start the console on port 3100 (`npm run setup && npm run dev` in `apps/console`), create a **Draft** token in Settings › Tokens, copy the organization and app IDs from Settings › General (the run checks what `GET /api/token` answers against them), and write `{"origin":"http://localhost:3100","orgId":"…","appId":"…","token":"…"}` to a file outside both repositories with mode 600. Then:

```sh
npm run e2e:local -- --connection /path/to/local-connection.json
npm run e2e:local -- --pair --account /path/to/local-account.json
```

With `--pair` (a console with migration 039, and `{"email":"…","password":"…"}` for a local owner or editor in a file with mode 600), it starts a connection request and cancels it (a claim then answers that it was cancelled), starts another, signs in and approves it through the console's session routes on `127.0.0.1` as the connect page would, polls until the plugin saves the browser connection, reads placements and artwork with the issued token, disconnects (`DELETE …/current`), checks that `GET /api/token` with that token then answers 403 `revoked`, checks the four routes' preflights, and checks that no token, key, or password appears in a URL, notice, stored record, or the UI. With `--connection` it starts on the first-run screen and connects with the token alone, then inserts `travel.coast` from each published environment and the first image with a PNG version, drags `travel.coast` from Draft onto the canvas (a placeholder at the drop point, filled and linked in one undo step), syncs the draft insert back, pasting the file's link when the first Sync asks for it (the app's draft `travel.coast` then shows the synced test image, and the layer's link names it), reads the artwork again, checks the new image's bytes and CORS preflights (`/api/token` included), and checks that the token appears only in the bearer header. WebP-only images are skipped, because converting them needs a browser. It is not part of `npm test`.
