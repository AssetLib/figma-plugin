# Assetlib for Figma

Insert your app's placement artwork and library images into Figma, send one selected Figma node to an Assetlib placement as a draft, then sync that node's later edits. Inserting only reads; sending and syncing update drafts; publishing remains a separate action in the Assetlib console.

## Install as a development plugin

Use Node.js 22 or newer (`.nvmrc` names 24) and the Figma desktop app.

```sh
npm ci
npm run verify
```

The build creates a minified `dist/code.js` and a self-contained `dist/ui.html`. Both outputs must exist before importing the plugin. While changing the source, `npm run watch` rebuilds both, unminified and with inline source maps, on every save.

1. In Figma desktop, open a design file, select **Plugins → Development → Import plugin from manifest…**, and choose this repository's `manifest.json`.
2. Run **Plugins → Development → Assetlib**. Rebuild after source changes; use Figma's development hot reload or reopen the plugin.

`manifest.json` commits the plugin `id` `1690264758934826227`, which Figma assigned when this plugin was created as a development plugin. The plugin is not published to the Figma Community. Figma scopes client storage to the plugin ID, so saved connections and sync destinations belong to that ID; don't change it in the repository. A manifest without an `id` imports, but the plugin then cannot save its connection: Figma reports `Cannot access client storage without a plugin ID`.

To use a development ID of your own instead: select **Plugins → Development → New plugin**, choose **Figma design** and **Custom UI**, save the generated starter in a separate temporary folder, and copy its `id` into your local `manifest.json` before importing. If Figma lists that starter under the same ID, remove its development entry first. Don't commit your ID. Client storage under a different ID starts empty, so connections and sync destinations saved under the other ID don't carry over.

See Figma's [development plugin instructions](https://help.figma.com/hc/en-us/articles/360042786733-Create-a-classic-plugin-for-development), [manifest reference](https://developers.figma.com/docs/plugins/manifest/), and [client storage reference](https://developers.figma.com/docs/plugins/api/figma-clientStorage/). The manifest uses Plugin API `1.0.0` and the required `documentAccess: "dynamic-page"`; it does not request private APIs.

## Connect

The plugin opens on a first-run screen until it is connected: the Assetlib lockup, a short explanation, and the connection form. Create a **Draft token** in **Settings › Tokens** in the [Assetlib console](https://console.assetlib.dev) (only workspace owners can create tokens; **Open Assetlib console** opens it in your browser), paste it into **Draft token**, and choose **Connect**. A Figma access token is neither needed nor accepted. A draft token can read every image in its app and update draft placement bindings; treat it accordingly.

A pasted token must look like an Assetlib token (`alk_` and 43 more characters); anything else is refused at once, with nothing sent. The plugin then asks the console which organization and app the token belongs to (`GET /api/token`), so nobody copies IDs, and saves the connection with the workspace and app names when the console returns them. A token the console refuses or has revoked, or one without the Draft permission (a CI declare token), is explained under the token field, which is marked and focused. A console from before `GET /api/token` (it answers 404, or without the CORS headers a plugin window can read) gets the organization and app ID fields instead, under "This console also needs the organization and app IDs. Find them in Settings › General.", a neutral notice rather than an error (no field is marked), with the organization ID focused; the form then uses them. The ID fields belong to the console that asked for them: choosing the other console hides them (a token pasted for it is identified with `GET /api/token` again), and **Disconnect** forgets them.

**Console** chooses the console: `console.assetlib.dev` (the default) or `localhost:3100 (development)`. Figma rejects IP-literal development domains such as `http://127.0.0.1:3100`, and the console accepts the `localhost` host for token routes in local mode. Other origins are rejected.

Once connected, the plugin shows its tabs, and the account chip at the top right names the connection: "{Workspace} · {App}" when the console said (a long workspace name shortens first, so the app's name stays whole), else the app by the start of its ID. A Figma toast says "Connected to {Workspace} · {App}", or "Connected to Assetlib" when the console gave no names. The chip opens the connection settings below the top bar: the workspace and app (without names, the app as the chip names it, with both IDs on hover), "Connected with token {prefix}…", **Open console**, **Disconnect**, and the token form (paste another token and choose **Connect**; with the field empty, **Connect** tests the saved connection again). **Connect** is the panel's main button only on the first run and while the connection needs attention; otherwise the footer's **Insert** or **Send** is, and **Connect** is secondary. **Esc** closes them. **Disconnect** forgets the token on this device and returns to the first-run screen; the token itself keeps working elsewhere until an owner revokes it in the console.

Each time the plugin opens, it tests the saved connection by reading the placements. A failed test opens nothing: the chip shows a warning, and the view in front says why, once, with the one action that helps. On **Insert** the list says it in its place; on **Send** a notice above **Placement** says it. The action is **Try again** (offline, busy, a server error, or a timeout; on Send it runs the test again) or, for a refused token, **Update token**, which opens the settings at the token field. While the settings are open the reason shows under the token field instead (a refused token is marked), and the list or the notice steps aside, so the failure is never said twice; a test that fails while you are in the settings (after you saved a new token, say) is said there and focuses the token field, unless you are typing in another field. A refused token on a later read (the Insert list, or an insert) works the same way. The chip returns to connected after the next successful read, and the reason goes. If the test itself failed, for example while offline, the next successful read also loads the placements before the label changes, so Send works without another test. If Figma can't save new settings, the previous connection keeps working, with its lists, Send, and Sync, and the message under the token field asks you to try again; the token you pasted stays in the field.

Connections saved by earlier builds may name the console's previous host, `https://assetlib-console.vercel.app`, and have no names. The plugin loads such a connection on `https://console.assetlib.dev` with the same token and saves the change, and sync destinations remembered under the previous host still apply. The console still accepts app tokens on the previous host, and the manifest keeps it allowed so an unrebuilt `dist/` keeps working. New connections cannot choose it. Saved tokens are not checked against the `alk_` format again, so an older save keeps loading.

Settings and the token are saved through `figma.clientStorage` on this device. The token field is cleared after saving, and only a short prefix is displayed afterward. The plugin does not log the token. Figma client storage is local plugin storage, not an encrypted credential vault; clearing it or changing the plugin ID loses the connection and remembered sync destinations.

When `figma.fileKey` is available, the plugin uses it. Availability depends on the plugin's publication state. Otherwise the Send tab asks for the file's link (in Figma, Cmd+L copies it) and parses the key from `https://www.figma.com/file/<key>/…` or `https://www.figma.com/design/<key>/…`. It remembers the link as a suggestion and asks for confirmation once each time the plugin opens in this fallback mode: node IDs alone cannot safely identify a file across documents. Use the link of the currently open file.

## Insert artwork

The plugin opens on **Insert** (it remembers the tab you last used). Its bars stay fixed and only the list scrolls: the top bar (the **Insert** and **Send** tabs and the account chip), the search field and **Refresh**, then **Placements** or **Images** and, for placements, the environment.

- **Placements** lists the app's placements, grouped by screen under headers that stay in view, each with its base art, its size, and what it declares (for example `1170 × 1560 · 2 states · light, dark · arm b`). Pick an environment: **Draft** (the default, and what Send and Sync change), **Staging**, or **Production**; each one's tooltip says what it is and names its latest release. Once the artwork has loaded, an environment with nothing published yet cannot be chosen; one picked while the list loads, or remembered from an earlier session, is kept and shows Draft with a note until that environment has a release. Tags carry a word, never colour alone, with a sentence in their tooltip: **Not set** (the thumbnail becomes an empty slot), **Changed** (Draft differs from Production), **Draft only** (Production has no image there yet), and, with a warning glyph because Insert can't use them, **Unavailable** (the console didn't return the image) and **Needs re-upload** (an image without prepared versions). Select a row, then choose its state, appearance, and A/B arm in the footer when the placement declares them. A cell without its own art shows the art it inherits, and the footer says so (for example "Uses Control · Any art"), as the app would.
- **Images** lists every active image in the app, newest first, in a grid, with search by name and **Load more**. Each tile's name takes at most two lines and then ends in an ellipsis, breaking anywhere when it has no spaces (`onboarding_hero_dark_final_v2`); its tooltip has the whole name, size, and type.

While a list loads it shows grey placeholder rows or tiles. A list that can't load says why in its place, with the one action that helps: **Try again** (a network, busy, or server error), **Update token** (a refused token or one without the Draft permission; it opens the settings at the token field, and the list's own words step aside while the token field says why), or **Go to Send** (a console without the Insert routes). An empty app says where placements come from (**Read the guide**), an empty library offers **Open console**, and a search with no matches offers **Clear search**.

While the plugin connects, sends, syncs, or inserts, only the actions that would conflict with it wait (**Connect**, **Disconnect**, **Send to draft**, **Sync**, **Insert**, and **Match ratio**); they keep keyboard focus and say they are unavailable, and choosing one then does nothing. The running one says what it is doing on its button ("Connecting…", "Sending…", "Syncing…", "Inserting…"). The tabs, lists, search, connection fields, environment, and scale stay usable throughout. A list that is loading can still be searched, and **Refresh** or a new image search replaces the load. An error that arrives while you type in a field (a token, a file link, a search) is shown and announced without taking focus from the field; that includes a failed connection test, which opens nothing and marks the token field without moving to it. When a connection test passes, the connection settings close and keyboard focus moves to the account chip. They stay open while you work in them: while you are in one of their fields that you moved to during the test, or while an entry you changed (a new token, an edited ID, another console) is not saved yet.

Choose **Insert** in the footer. The image arrives with an image fill, centered in the current view and selected, and a Figma toast says so: art from a placement as a component, an image from the library as a frame. Placement inserts are named after the placement and cell (for example `onboarding.hero · b · dark`) and sized to the placement's width and height; image inserts take the image's name and size. **1×**, **2×**, and **3×** set the scale: 1× keeps that size, 2× and 3× divide it, for device frames drawn in points; the footer then shows the size in Figma (for example `→ 390 × 520`). The choice, the tab, the browse mode, and the environment are remembered on this device.

A placement's component carries a description that names the placement and its size, and a documentation link to the app's placements in the console. Figma's MCP server passes both to coding agents that build the screen from the file, so the description tells them to use the accessor generated for that placement, which carries the bundled fallback, instead of exporting the image. Copies and instances of the component carry the same description. If the file is published as a team library, these components appear in the publish dialog; leave them unselected.

The plugin downloads the largest prepared version of the image that is PNG or WebP and at most 4 MiB, preferring PNG. Figma accepts PNG but not WebP, so a WebP version (photos have only WebP versions) is converted to PNG in the plugin window first, with a Display P3 image converted to sRGB. An image larger than 4 MiB in every version can't be inserted, and the footer says so before you try, with **Open in console**; so does an image uploaded before the console prepared versions, which has none (upload it again to use it in Figma). Originals are never downloaded. An animated (Lottie) image is inserted as its still poster, and an SVG image as its PNG version, not as editable vectors.

Previews are downloaded the same way, from the smallest version up to 512 KiB, and shown from memory; an image without such a version shows an empty checkerboard. Only rows and tiles within 300 px of the list's view load previews, three at a time, the most recently scrolled-in first; one that scrolls away before its download starts gives up its place. The footer's preview loads whenever it shows. A preview that fails with a network or server error is tried again after 1 and 4 seconds, and **Refresh** tries every failed preview again. If the console limits requests, previews pause and resume shortly.

## Send artwork

On the **Send** tab:

1. Select exactly one layer. The plugin shows its name and size in whole pixels, or says why the selection can't be sent ("Select a frame or layer to send.", "Select one layer. Sending several at once isn't supported yet.", "This layer has no visible area to export.").
2. Choose a placement: nothing is chosen for you, unless the layer is linked or was sent before. State, appearance, and A/B arm choices are limited to what that placement declares. **Any** appearance and **Control** arm map to `null` in the API. Omitting a state uses the placement's declared default state; an explicit state must be declared. The line under the pickers names the PNG the export will make (for example "Exports 1170 × 2534 PNG").
3. Choose **Send to draft** in the footer. When the layer's ratio differs from the placement's by more than 2%, Send and Sync stay unavailable and a callout gives the layer's size and the ratio the placement needs. Resize the layer, or choose **Match ratio**: the plugin keeps the layer's width and sets its height to the placement's ratio (an auto-layout hug or fill height becomes fixed), as one undo step. The size follows resizes on the canvas without reselecting.
4. A Figma toast says where the art went ("Sent to {placement} draft", with **Review**, which opens the console's releases), and the result under the form says "Draft updated. Publish it from the console when it's ready." with **View in console**. When a Sync also updated other draft cells that used the layer's earlier art, the result says how many, with the cells under **Details**.

Exports are PNG. The plugin uses the placement's width as the export constraint, or the placement's height when the layer is proportionally taller. Figma preserves the layer's aspect ratio; the plugin does not crop or stretch it. Within the 2% tolerance, match the layer's aspect ratio to the placement when you need exact canvas dimensions. After export the plugin reads the PNG's own size and stops before upload if that ratio is more than 2% off.

If a binding fails with HTTP 409, the console may still have created the image. The result says so with the console's own words ("The image was uploaded, but Assetlib couldn't put it in {placement}: …") and **Open image in console**, and no success toast appears; check the console before retrying to avoid unnecessary duplicate images. A send does not publish a release; drafts don't go live until someone publishes in the Assetlib console.

## Sync later edits

After the console creates an asset successfully, the plugin remembers the file key, node ID, placement, state, appearance, and arm for that node and connection. Select the same node again to see **Sync to &lt;placement&gt;**. Sync re-exports the node, sends its remembered binding, and sets `rebind: true`.

The console replaces references to the previous asset from that same file and node in draft cells and states within the connected app. The result says how many other cells it updated, with the cells under **Details**, and a toast says "Synced {placement} to draft". Sync can therefore update several draft destinations that already reference that source. If the remembered placement or cell options no longer exist, refresh the placements and choose a current destination before sending again.

Art inserted from a placement is linked to the cell it came from, so **Sync to &lt;placement&gt;** appears as soon as it is selected, including for teammates who open the file with a connection to the same app. Edit it, adding layers inside if needed, then choose Sync: its first Sync fills exactly that cell in draft, never the cell it inherited from, and later syncs replace that layer's earlier sends wherever they are bound in draft. After the first successful Sync the plugin also remembers the target on this device, as for any sent node. A copy of linked art (for example with Cmd+D) is not linked; send it with **Send to draft** like any other node. Library images are not linked to a placement. When Figma does not supply the file key, paste the file's link on the Send tab before Sync is enabled.

## Data and network access

The plugin sends only the selected node's exported PNG bytes (base64 in JSON), node ID and name, file key, PNG export settings, chosen placement coordinates, asset name, schema version, and sync flag. `source.versionId` is `null`. The app-scoped draft token is sent as a bearer token to the chosen console origin, including once to `GET /api/token` when it is pasted.

It never sends the Figma document, unrelated layers, or a Figma token. Selecting a frame or group exports its visible contents as one PNG; it does not upload its editable layer tree.

It receives the pasted token's organization and app IDs, the workspace and app names when the console returns them, and the token's scopes; the app's placements; for each placement cell, which image it shows in draft, staging, and production, and when staging and production were published; the app's image names, sizes, and prepared versions; and the bytes of the versions it previews or inserts. Rendition URLs are built from the image ID and hash; the plugin never sends the token to a URL taken from a response.

Art inserted from a placement stores plugin data `assetlib.link.v1`: the console origin, organization and app IDs, placement key, state, appearance, arm, environment, image ID, the node's ID, and the insert time. It never holds the token. Plugin data is private to this plugin but travels with the file, so anyone with a copy of the file can read it; organization and app IDs are not secret, since they appear in public delivery URLs. Its component description holds the placement key and size, and its documentation link is `{console}/w/{organization ID}/{app ID}/placements`; anyone who can open the file reads both, including coding agents through Figma's MCP server. Neither holds the token.

The manifest declares:

```json
{
  "allowedDomains": ["https://console.assetlib.dev", "https://assetlib-console.vercel.app"],
  "devAllowedDomains": ["http://localhost:3100"],
  "reasoning": "Reads images from, and sends exported artwork to, the Assetlib console you connect."
}
```

Every request goes through one module that refuses any other route: `GET /api/token` on the chosen console, which tells a pasted token its own organization and app (tried once, so the form answers at once), and exactly these five calls under `/api/apps/{orgId}/{appId}/`: `GET placements`, `GET placements/artwork`, `GET assets` (with `limit`, `cursor`, and `q`), `GET assets/{assetId}/renditions/{sha256}`, and `POST drafts`. Links into the console (**Open console**, **View in console**, **Open in console**, and a toast's **Review**) open in your browser; they are navigations built from validated IDs on the connected console, and never carry the token. The placements endpoint accepts `draft` or `declare`; the other four require `draft`. All of them authenticate only with that bearer token, never cookies, and must allow cross-origin requests from the Figma plugin UI. The hosted console does so for placements and drafts on both production hosts; the artwork, image, and rendition reads exist only in a console that includes them, and until the hosted console does, Insert shows that the console does not support it yet while Send keeps working. Rendition bytes are served `private, no-store`. The plugin never calls the public delivery routes. Local development requires that console server to be running on port 3100. The development-only origin is not available to a published plugin.

A read times out after 20 seconds, and a download after 20 seconds plus 15 per MiB the console listed for it. A read that fails with a network error, 502, 503, or 504 is tried twice more, after 1 and 4 seconds (or after the wait the console asks for in `Retry-After`, when it exposes one and it is longer), and one answered with 429 is tried again only when the console asks for a wait. A read whose console asks for a wait of more than 30 seconds is not tried again. A draft upload times out after 30 seconds plus 15 per MiB of its body and is never retried, since it may have arrived; the message says so. Searching or refreshing while a list loads abandons the earlier request, and changing the connection abandons every request in flight.

Messages are plain and say what to do next, without HTTP codes or developer terms: a refused or revoked token says to create a new one in Settings › Tokens; a token without the Draft permission says so; HTTP 409 keeps the console's own message; HTTP 413 says the export is over 4 MiB; a busy console (429) asks to try again in a minute; a server error says "Assetlib had a problem ({status})"; an unreachable console says to check the internet connection (the local console is named, since it may not be running); timeouts say how many seconds the plugin waited, and a draft that timed out may have arrived anyway. A console without the Insert endpoints is reported as such while Send keeps working, and an image removed after the list loaded asks for a Refresh, with **Refresh** in the error line. One message differs from the plugin's UX spec on purpose: a network failure on an Insert read after the placements loaded says "This console doesn't support Insert yet, or Assetlib couldn't be reached. Send still works." rather than "Can't reach Assetlib. Check your internet connection.", because a console without those reads answers them without the CORS headers a plugin window can read, which looks the same as a network failure; it can become the plain sentence once every console the plugin connects to serves the Insert reads. Finished operations are Figma toasts of at most 100 characters; every toast, result, and error is also announced through one status and one alert region. The shared contract allows at most 4 MiB decoded PNG bytes and 4,500,000 bytes for the JSON body, Vercel's request limit, so a base64 PNG above about 3.3 MB decoded does not fit.

## Development and verification

There are no runtime dependencies. The only devDependencies are exact pins:

| Package | Version | Age evidence checked for October 8, 2026 |
| --- | --- | --- |
| `@figma/plugin-typings` | `1.117.0` | npm registry `time` metadata: `2025-08-13T21:50:04.952Z`; [registry metadata](https://registry.npmjs.org/@figma/plugin-typings). [Figma's matching release tag](https://github.com/figma/plugin-typings/tree/v1.117.0) is dated `2025-08-13T21:46:41Z`. |
| `typescript` | `5.9.3` | npm registry `time` metadata: `2025-09-30T21:19:38.784Z`; [registry metadata](https://registry.npmjs.org/typescript). |
| `esbuild` | `0.25.12` | npm registry `time` metadata: `2025-11-01T23:36:22.605Z`; [registry metadata](https://registry.npmjs.org/esbuild). |

All three releases predate the September 24, 2026 cutoff by more than two weeks.

Every lockfile entry records the registry `resolved` URL and `integrity` hash, so `npm ci` fetches exactly these versions and verifies each tarball. The `@figma/plugin-typings` entry was refreshed from the registry on October 9, 2026; its hash matches the registry's published `dist.integrity` for 1.117.0.

```sh
npm run typecheck    # Figma main-thread types; separate browser UI types
npm test             # Compile shared modules, then run Node's built-in test runner
npm run build        # Bundle main and inline the UI script, minified
npm run verify       # Typecheck, tests, and build
npm run test:browser # Build, then drive dist/ui.html in headless Chrome
npm run watch        # Rebuild on every change, unminified, with inline source maps
npm run contrast     # Contrast of every text colour pair in Figma's light and dark themes (also run by npm test)
```

`.github/workflows/verify.yml` runs `npm ci`, `npm run verify`, and `npm run test:browser` on Node.js 22 and 24 for every push to `main` and every pull request. The build fails if a release `dist/ui.html` would grow past 160 KB (160,000 bytes), and then leaves no `dist/ui.html` behind. It embeds Instrument Sans (`src/assets/instrument-sans-variable.woff2`, about 40 KB as base64) as an `@font-face`, so the plugin needs no font host; `sh brand/sync.sh` in the Assetlib workspace copies the font and its licence there from the brand source.

The interface uses Figma's theme variables (`themeColors: true`), with Assetlib's brand tokens as fallbacks, the brand's Instrument Sans at Figma's density (11 px labels and meta, 12 px titles and actions, 13 px headlines), and vermilion only for the focus ring. `scripts/contrast.mjs` measures every text colour pair the stylesheet uses against Figma's documented light and dark values (`tests/fixtures/figma-theme.json`) and the fallbacks: text at 4.5:1 or more, the focus ring and callout glyphs at 3:1 or more. `tests/contrast.test.mjs` runs it, and fails on a text colour the script does not measure.

`src/code.ts` handles selection, Figma exports, inserted frames and placement components, and client storage, and checks the shape of every message from the plugin window before acting on it. `src/ui.html` and the modules in `src/ui/` provide the interface: `main.ts` routes messages and renders once per animation frame, `http.ts` makes every console request, `connection.ts`, `send.ts`, and `insert.ts` run their parts of the panel, `thumbnails.ts` loads previews, `state.ts` holds shared state, and `dom.ts` holds element, error, render, and focus helpers. `src/image.ts` converts WebP to PNG in the plugin window. `src/shared/` holds pure request, timeout and retry, message, picker, export, file-key, library, link (`links.ts`: console links), placement marker (`marker.ts`), and error logic. `tests/shared.test.mjs` runs the compiled shared logic with `node --test`. `tests/plugin.test.mjs` bundles `src/code.ts` and `src/ui/main.ts` with esbuild and runs both in `node:vm` against the fake `figma` API, DOM, console, and `fetch` in `tests/fakes.mjs`, covering the first run, token-only connections through `GET /api/token` and an older console's ID fields (which belong to that console and go with Disconnect), Disconnect, saved and new connections, connection errors and recovery (a failed test said once, in the view or under the token field, with nothing opening by itself), connection switches, Send, Sync, the inline result and toasts, the ratio gate and Match ratio, live size updates, the exported PNG checks, Insert from placements and images, links, preferences, previews (a fake `IntersectionObserver` drives what is in view), timeouts, retries and aborted requests, which actions wait during an operation (and that choosing one then does nothing), focus through rebuilds, errors, and closing settings, list states with their actions, and main's message and toast checks (a fake `fetch` answers `GET /api/token` for tokens a test types). Neither runs real Figma or a real console.

`npm run test:browser` (`scripts/ui-browser.mjs`) loads the built `dist/ui.html` in headless Chrome over the DevTools protocol, with no dependencies, and with `parent` and `fetch` replaced by a fake main thread and a fake console holding 7 placements and 30 or 2,000 images, whose previews are real PNGs in each image's proportions. It checks that the tabs and search stay usable during a slow artwork load, that focus survives Refresh, Load more, Insert, Sync, and a passing connection test (which moves it to the account chip, never the page), that an error arriving while a token is typed keeps every keystroke in the field, that a connection save Figma refuses during a load leaves the list and Refresh working, that the first run connects with only a token (and asks an older console for the IDs with a neutral notice, marking no field), that at least seven placement rows show at 420 × 720 with a selection and all three pickers while the bars stay fixed, that nothing overflows sideways at 320 × 480 (a 63-character placement key in a Sync's Details included), that the embedded font loads, that errors render inside the window, that every control inside a callout stands apart from it and hover shows in Figma's themes, that a failed opening connection test is said once with at most one primary button on screen, and that the footer line, the account chip (a shortened workspace name keeps even spaces around the "·"), the empty grid, tile names (layer names such as `travel.coast.background.large` wrap within two lines, never cut at the tile's edge), and a selected tile fit at 420 px. With `ASSETLIB_SCREENSHOTS=<directory>` it also writes a screenshot of every state in both themes there, for review. It finds Chrome through `CHROME_PATH` or the usual install paths. It is a browser check, not a Figma check: the page is a top-level `file://` document rather than Figma's cross-origin iframe; Figma's theme variables are set from the fixture only where a test asks for a theme.

`npm run e2e:local` runs the same bundles and fakes against a running local console with Node's real `fetch`. Start the console on port 3100 (`npm run setup && npm run dev` in `apps/console`), create a **Draft** token in Settings › Tokens, copy the organization and app IDs from Settings › General (the run checks what `GET /api/token` answers against them), and write `{"origin":"http://localhost:3100","orgId":"…","appId":"…","token":"…"}` to a file outside both repositories with mode 600. Then:

```sh
npm run e2e:local -- --connection /path/to/local-connection.json
```

It starts on the first-run screen and connects with the token alone, then inserts `travel.coast` from each published environment and the first image with a PNG version, syncs the draft insert back (the app's draft `travel.coast` then shows the synced test image), reads the artwork again, checks the new image's bytes and CORS preflights (`/api/token` included), and checks that the token appears only in the bearer header. WebP-only images are skipped, because converting them needs a browser. It is not part of `npm test`.

Known limits: one node or image at a time; PNG only for sending; inserts are raster images, not editable vectors; no update or relink of an inserted frame yet; no OAuth; no document-wide sync; no automatic release publication; local-device settings and sync history. Actual Figma exports and inserts, client storage across restarts, preview rendering, and WebP conversion require a manual check in Figma desktop against a console in addition to the local verification commands.
