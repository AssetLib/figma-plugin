# Assetlib for Figma

Insert your app's placement artwork and library images into Figma, send one selected Figma node to an Assetlib placement as a draft, then sync that node's later edits. Inserting only reads; sending and syncing update drafts; publishing remains a separate action in the Assetlib console.

## Install as a development plugin

Use Node.js 22 or newer (`.nvmrc` names 24) and the Figma desktop app.

```sh
npm ci
npm run verify
```

The build creates a minified `dist/code.js` and a self-contained `dist/ui.html`. Both outputs must exist before importing the plugin. While changing the source, `npm run watch` rebuilds both, unminified and with inline source maps, on every save.

1. In Figma desktop, open a design file, select **Plugins → Development → Import plugin from manifest…**, and choose this repository's `manifest.json`.
2. Run **Plugins → Development → Assetlib**. Rebuild after source changes; use Figma's development hot reload or reopen the plugin.

`manifest.json` commits the plugin `id` `1690264758934826227`, which Figma assigned when this plugin was created as a development plugin. The plugin is not published to the Figma Community. Figma scopes client storage to the plugin ID, so saved connections and sync destinations belong to that ID; don't change it in the repository. A manifest without an `id` imports, but the plugin then cannot save its connection: Figma reports `Cannot access client storage without a plugin ID`.

To use a development ID of your own instead: select **Plugins → Development → New plugin**, choose **Figma design** and **Custom UI**, save the generated starter in a separate temporary folder, and copy its `id` into your local `manifest.json` before importing. If Figma lists that starter under the same ID, remove its development entry first. Don't commit your ID. Client storage under a different ID starts empty, so connections and sync destinations saved under the other ID don't carry over.

See Figma's [development plugin instructions](https://help.figma.com/hc/en-us/articles/360042786733-Create-a-classic-plugin-for-development), [manifest reference](https://developers.figma.com/docs/plugins/manifest/), and [client storage reference](https://developers.figma.com/docs/plugins/api/figma-clientStorage/). The manifest uses Plugin API `1.0.0` and the required `documentAccess: "dynamic-page"`. It sets `enablePrivatePluginApi`, which gives a development or organization-private plugin the open file's key (`figma.fileKey`); a plugin published to the Figma Community can't have it, so such a build asks for each file's link once instead (see [Sync later edits](#sync-later-edits)). It declares two relaunch buttons for Figma's properties panel: **Sync to Assetlib** on linked layers and **Open Assetlib** on a document that has any.

## Connect

The plugin opens on a first-run screen until it is connected: the Assetlib lockup, a short explanation, and the connection form. Create a **Draft token** in **Settings › Tokens** in the [Assetlib console](https://console.assetlib.dev) (only workspace owners can create tokens; **Open Assetlib console** opens it in your browser), paste it into **Draft token**, and choose **Connect**. A Figma access token is neither needed nor accepted. A draft token can read every image in its app and update draft placement bindings; treat it accordingly.

A pasted token must look like an Assetlib token (`alk_` and 43 more characters); anything else is refused at once, with nothing sent. The plugin then asks the console which organization and app the token belongs to (`GET /api/token`), so nobody copies IDs, and saves the connection with the workspace and app names when the console returns them. Once a session, after the saved connection's first passing test, it asks again quietly, so a connection saved before the console named apps, or a workspace or app renamed since, shows today's names; a failure, or an answer without names, changes nothing. A token the console refuses or has revoked, or one without the Draft permission (a CI declare token), is explained under the token field, which is marked and focused. A console from before `GET /api/token` (it answers 404, or without the CORS headers a plugin window can read) gets the organization and app ID fields instead, under "This console also needs the organization and app IDs. Find them in Settings › General.", a neutral notice rather than an error (no field is marked), with the organization ID focused; the form then uses them. The ID fields belong to the console that asked for them: choosing the other console hides them (a token pasted for it is identified with `GET /api/token` again), and **Disconnect** forgets them.

**Console** chooses the console: `console.assetlib.dev` (the default) or `localhost:3100 (development)`. Figma rejects IP-literal development domains such as `http://127.0.0.1:3100`, and the console accepts the `localhost` host for token routes in local mode. Other origins are rejected.

Once connected, the plugin shows its tabs, and the account chip at the top right names the connection: "{Workspace} · {App}" when the console said (a long workspace name shortens first, so the app's name stays whole, and an app name that leaves the workspace no room shows alone, as in a narrow window), else the app by the start of its ID. A Figma toast says "Connected to {Workspace} · {App}" (the app's name alone when both would pass the toast's 100 characters), or "Connected to Assetlib" when the console gave no names. The chip opens the account menu below the top bar: the app's name (without names, the app as the chip names it, with both IDs on hover), "{Workspace} · Connected with token {prefix}…", **Open console**, **Update token**, and, set apart on the right, **Disconnect**. **Update token** shows the token form (paste another token and choose **Save token**; with the field empty, it tests the saved connection again); the form shows at once while the connection needs attention, with **Connect** as the panel's main button. Otherwise the footer's **Insert** or **Send** is the main button. **Esc** closes the menu, which is a menu again the next time it opens. **Disconnect** forgets the token on this device and returns to the first-run screen; its toast has **Undo** for six seconds, which saves the same connection again (only an owner can create another token), unless you connected again meanwhile. The token itself keeps working elsewhere until an owner revokes it in the console.

Each time the plugin opens, it tests the saved connection by reading the placements. A failed test opens nothing: the chip shows a warning, and the view in front says why, once, with the one action that helps. On **Insert** the list says it in its place; on **Send** a notice above **Placement** says it. The action is **Try again** (offline, busy, a server error, or a timeout; on Send it runs the test again) or, for a refused token, **Update token**, which opens the settings at the token field. While the settings are open the reason shows under the token field instead (a refused token is marked), and the list or the notice steps aside, so the failure is never said twice; a test that fails while you are in the settings (after you saved a new token, say) is said there and focuses the token field, unless you are typing in another field. A refused token on a later read (the Insert list, or an insert) works the same way. The chip returns to connected after the next successful read, and the reason goes. If the test itself failed, for example while offline, the next successful read also loads the placements before the label changes, so Send works without another test. If Figma can't save new settings, the previous connection keeps working, with its lists, Send, and Sync, and the message under the token field asks you to try again; the token you pasted stays in the field.

Connections saved by earlier builds may name the console's previous host, `https://assetlib-console.vercel.app`, and have no names. The plugin loads such a connection on `https://console.assetlib.dev` with the same token and saves the change, and sync destinations remembered under the previous host still apply. The console still accepts app tokens on the previous host, and the manifest keeps it allowed so an unrebuilt `dist/` keeps working. New connections cannot choose it. Saved tokens are not checked against the `alk_` format again, so an older save keeps loading.

Settings and the token are saved through `figma.clientStorage` on this device. The token field is cleared after saving, and only a short prefix is displayed afterward. The plugin does not log the token. Figma client storage is local plugin storage, not an encrypted credential vault; clearing it or changing the plugin ID loses the connection and remembered sync destinations.

Each Send records which Figma file the art came from, by the file's key. Where Figma gives the plugin the key (a development or organization-private plugin), the plugin uses it, and saves it in the document with the first layer it links. Otherwise it uses the key saved in the document, which everyone who opens the file shares. A file with neither is asked for its link once, at its first **Send to draft** or **Sync** and not when the plugin opens: the Send tab says, in a neutral notice, "Link this file once so Assetlib can trace art back to it. In Figma, press Cmd+L to copy the file's link, then paste it here." (Ctrl+L on Windows and Linux). The plugin reads the key from `https://www.figma.com/file/<key>/…` or `https://www.figma.com/design/<key>/…` (a branch's link, `…/<key>/branch/<branch key>/…`, names the branch), saves it in the document, and then runs the Send or Sync that asked. The link's file name is compared with this file's, letters of every script included; a link that names another file (for example "This link is for “Coast-house”, but this file is “Roam onboarding”. Paste this file's link."), or names none, is questioned and saved only after **Use anyway**, and editing the link withdraws the question. In a file you can only view, the plugin can't save it in the document, so the key lasts until you close the plugin, and the Send tab says so. Once the key comes from the document, the Send tab names the file it was saved for ("File: {name} · Change"). A duplicated file keeps its original's key until its own link is pasted with **Change**. The link last pasted on this device fills in the field only for the file it names.

## Insert artwork

The plugin opens on **Insert** (it remembers the tab you last used). Its bars stay fixed and only the list scrolls: the top bar (the **Insert** and **Send** tabs and the account chip), the search field and **Refresh**, then **Placements** or **Images** and, for placements, the environment.

The window opens 420 px wide and 64 px shorter than the canvas on screen, from 480 to 720 px tall. Drag the grip in its bottom-right corner to resize it, from 320 × 480 up to 900 × 1000; only the list grows. The size you leave it at is remembered on this device, and a double-click on the grip goes back to the default. Below 400 px wide the environment becomes a dropdown and the footer's pickers show only their values (each keeps its name for screen readers); from 560 px a placement's size and declarations move to a column on the right, and the image grid adds columns as it widens.

- **Placements** lists the app's placements, grouped by screen under headers that stay in view, each with its base art, its size, and what it declares (for example `1170 × 1560 · 2 states · light, dark · arm b`). Pick an environment: **Draft** (the default, and what Send and Sync change), **Staging**, or **Production**; each one's tooltip says what it is and names its latest release. Once the artwork has loaded, an environment with nothing published yet cannot be chosen; one picked while the list loads, or remembered from an earlier session, is kept and shows Draft with a note until that environment has a release. Tags carry a word, never colour alone, with a sentence in their tooltip: **Not set** (the thumbnail becomes an empty slot), **Changed** (Draft differs from Production), **Draft only** (Production has no image there yet), and, with a warning glyph because Insert can't use them, **Unavailable** (the console didn't return the image) and **Needs re-upload** (an image without prepared versions). Select a row, then choose its state, appearance, and A/B arm in the footer when the placement declares them. A cell without its own art shows the art it inherits, and the footer says so (for example "Uses Control · Any art"), as the app would.
- **Images** lists every active image in the app, newest first, in a grid, with search by name and **Load more**. Each tile's name takes at most two lines and then ends in an ellipsis, breaking after a `.`, `_`, or `-` first (`travel.coast.|background`) and anywhere only as a last resort; its tooltip has the whole name, size, and type.

While a list loads it shows grey placeholder rows or tiles. A list that can't load says why in its place, with the one action that helps: **Try again** (a network, busy, or server error), **Update token** (a refused token or one without the Draft permission; it opens the settings at the token field, and the list's own words step aside while the token field says why), or **Go to Send** (a console without the Insert routes). An empty app says where placements come from (**Read the guide**), an empty library offers **Open console**, and a search with no matches offers **Clear search**.

While the plugin connects, sends, syncs, or inserts, only the actions that would conflict with it wait (**Connect**, **Disconnect**, **Send to draft**, **Sync**, **Insert**, and **Match ratio**); they keep keyboard focus and say they are unavailable, and choosing one then does nothing. The running one says what it is doing on its button ("Connecting…", "Sending…", "Syncing…", "Inserting…"), with a spinner, in ink, so it never looks like an unavailable one. The tabs, lists, search, connection fields, environment, and scale stay usable throughout. A list that is loading can still be searched, and **Refresh** or a new image search replaces the load. An error that arrives while you type in a field (a token, a file link, a search) is shown and announced without taking focus from the field; that includes a failed connection test, which opens nothing and marks the token field without moving to it. When a connection test passes, the connection settings close and keyboard focus moves to the account chip. They stay open while you work in them: while you are in one of their fields that you moved to during the test, or while an entry you changed (a new token, an edited ID, another console) is not saved yet.

**Keyboard.** **Tab** moves between the panel's parts: the tabs, the account chip, the search, **Refresh**, **Placements** or **Images**, the environment, the list, the Sync bar (when the selected layer is linked), then the footer. The tabs, each segmented control, and the list are one stop each, and the arrow keys move inside them: **←** and **→** switch tabs (and show the one they reach) and choose within **Placements**/**Images**, the environment (passing over one with nothing published), and **1×**/**2×**/**3×**. In the list, **↑** and **↓**, **Home**, and **End** move the choice, and typing the start of a placement key or an image name jumps to the next one that matches; in the image grid **←** and **→** move by one tile and **↑** and **↓** by a row. **Enter** or a double-click inserts the row or tile, with the state, appearance, and A/B arm the footer shows (choosing the chosen row again keeps them); on one Insert can't use, it says why instead. **/** (outside a text field) or **Cmd+F** (Ctrl+F on Windows and Linux) focuses the search from either tab, with its text selected. **Esc** in the search or the list clears the search, then the choice. When an insert fails, focus moves to its error.

**Drag.** You can also drag a row or tile onto the canvas. Only one that **Insert** could insert now drags (not one marked **Not set**, **Unavailable**, or **Needs re-upload**, nor an image over 4 MiB in every version, nor while something else is being inserted, sent, or synced); the chosen row drags the state, appearance, and A/B arm its footer shows. The download starts as the drag starts. Where it lands decides what happens: on an image frame (a frame showing an image with nothing inside, such as one the plugin inserted), its image is replaced, as **Fill** or **Replace image** would; anywhere else a grey placeholder named "{name} · loading" appears there, centered on the drop point (or added last to an auto layout frame), inside the frame, group, section, or component it landed on, or on the page; placement art, a component, goes on the page when it lands in a component. The placeholder takes the image when its download finishes, at the size **1×**, **2×**, or **3×** gives, and the placeholder and its image are one undo step. If the download fails, the placeholder goes and the error says why. A drag that ends back in the plugin window inserts nothing, and a file dragged from your desktop keeps Figma's own behaviour. Rows and tiles that drag show a grab cursor. Until your first insert, a hint bar under the list says "Drag onto the canvas, or select an item and press Enter." ("Drag onto the canvas or press Enter." below 400 px), except while the Sync bar shows; its close button hides it for good on this device.

What is selected on the canvas decides what the footer's main button does, and names it:

| Selected | Button | What happens |
| --- | --- | --- |
| Nothing | **Insert** | A new layer, centered in the current view |
| One linked shape, frame, component, or instance (art inserted, filled, replaced, or sent from this app; not a copy) | **Replace image** | Its image is swapped, and it is linked to the chosen cell |
| A frame or component with layers inside | **Insert into {name}** | A new layer inside it, centered, or added last in an auto layout frame. Placement art is a component, and Figma doesn't put a component inside another, so with a component, or a frame inside one, it is **Insert** and goes 40 px right of it instead |
| Shapes (rectangle, ellipse, polygon, star, vector, boolean), or frames, components, and instances with nothing inside | **Fill {name}** or **Fill {n} layers** | Each one shows the image; text, lines, groups, sections, and frames with layers inside are skipped |
| Only layers that can't show an image (text, lines, groups, sections, linked by a Send or not), or an instance with layers inside | **Insert** | A new layer 40 px right of the selection |

A new layer has an image fill and is selected, and a Figma toast says so: art from a placement as a component, an image from the library as a frame. Placement inserts are named after the placement and cell (for example `onboarding.hero · b · dark`) and sized to the placement's width and height; image inserts take the image's name and size. **1×**, **2×**, and **3×** set the scale: 1× keeps that size, 2× and 3× divide it, for device frames drawn in points; the footer then shows the size in Figma first (for example `→ 390 × 520 · Draft`), so a narrow window keeps it. An item that can't be inserted shows no scale control, and below 400 px the footer drops its preview (the chosen row shows it) so the item's name stays readable. Inserting into a frame narrower than the new layer shows a hint that names a scale that fits (for example "Wider than “Home” (390 px). Try 3×."; a long name is cut to 24 characters). Figma gives instances no new layers, so an instance with layers inside is not a frame to insert into; if Figma refuses a frame anyway, nothing is left behind and the error suggests **Insert as new frame**. A component, or a frame inside a component, takes a library image but not placement art, which is a component itself; the footer then says the art goes beside it.

A fill keeps the layer's size, position, constraints, and other paints, so the scale control is hidden. It replaces the layer's topmost image paint, keeping its scale mode, crop, filters, opacity, blend mode, and visibility, or adds an image paint on top when there is none. Each layer filled with placement art is linked to the cell with its own ID, so each syncs on its own and later shows **Replace image**. Layers inside an instance are filled but can't be linked, since Figma keeps no plugin data there, and the toast says Sync isn't available for them (it says so too for any other layer Figma doesn't let the plugin link). If Figma refuses the image on some of the selected layers, the toast says how many it filled, and whether Sync is unavailable for any of them. **Replace image** relinks the layer to the chosen cell; on a component the plugin inserted, the description agents read then names that placement, and a layer still named for the placement it showed takes the new one's name (a description or name you wrote yourself is never changed). A library image never writes or removes a link, so a linked layer filled with one stays linked to its cell. In the modes that use the selection, **Insert as new frame** under the main button makes a new layer beside the selection instead.

Every insert, fill, replace, and drop is one undo step (Cmd+Z). The toast after a fill or a replace has **Undo**, which takes back only the fill: the toast goes when the selection or the page changes, when any layer on the page changes after the fill (a filled layer moved or resized; another layer renamed, hidden, locked, recoloured, added, or deleted, which leaves the selection as it was), or when the plugin makes another edit (a file link, a Send's link, Match ratio), and Undo does nothing if their paints, name, or description changed since the fill. Only an instance of a filled component may follow the fill without retiring the toast. The choice, the tab, the browse mode, the environment, the scale, the window's size, and whether the hint bar was closed are remembered on this device.

A placement's component carries a description that names the placement and its size, and a documentation link to the app's placements in the console. Figma's MCP server passes both to coding agents that build the screen from the file, so the description tells them to use the accessor generated for that placement, which carries the bundled fallback, instead of exporting the image. Copies and instances of the component carry the same description. If the file is published as a team library, these components appear in the publish dialog; leave them unselected.

For a new layer (and a drag) the plugin downloads the largest prepared version of the image that is PNG or WebP and at most 4 MiB, preferring PNG; for a fill or a replace, the smallest one at least three times as wide as the image is drawn in the layers (it covers each layer, so a layer proportionally taller than the image draws it wider than the layer), never wider than the original, else the largest. Figma accepts PNG but not WebP, so a WebP version (photos have only WebP versions) is converted to PNG in the plugin window first, with a Display P3 image converted to sRGB. An image larger than 4 MiB in every version can't be inserted, and the footer says so before you try, with **Open in console**; so does an image uploaded before the console prepared versions, which has none (upload it again to use it in Figma). A version downloaded for an insert or a drag is kept in the plugin window for a minute, so dropping it, or inserting it again, doesn't download it twice. Originals are never downloaded. An animated (Lottie) image is inserted as its still poster, and an SVG image as its PNG version, not as editable vectors.

Previews are downloaded the same way, from the smallest version up to 512 KiB, and shown from memory; an image without such a version shows an empty checkerboard. Only rows and tiles within 300 px of the list's view load previews, three at a time, the most recently scrolled-in first; one that scrolls away before its download starts gives up its place. The footer's preview loads whenever it shows. A preview that fails with a network or server error is tried again after 1 and 4 seconds, and **Refresh** tries every failed preview again. If the console limits requests, previews pause and resume shortly.

## Send artwork

On the **Send** tab:

1. Select exactly one layer. The plugin shows its name and size in whole pixels, or says why the selection can't be sent ("Select a frame or layer to send.", "Select one layer. Sending several at once isn't supported yet.", "This layer has no visible area to export.").
2. Choose a placement: nothing is chosen for you, unless the layer is linked or was sent before. State, appearance, and A/B arm choices are limited to what that placement declares. **Any** appearance and **Control** arm map to `null` in the API. Omitting a state uses the placement's declared default state; an explicit state must be declared. The line under the pickers names the PNG the export will make (for example "Exports 1170 × 2534 PNG"); it steps aside while the ratio callout below says the export can't be sent. With nothing to send, the layer card is a dashed slot saying why.
3. Choose **Send to draft** in the footer. The first Send or Sync in a file whose key the plugin doesn't have asks for the file's link first (see [Sync later edits](#sync-later-edits)). When the layer's ratio differs from the placement's by more than 2%, Send stays unavailable and a callout gives the layer's size and the ratio and size the placement needs ("This frame is 390 × 844. home.banner needs 2.44 : 1 (1170 × 480). Resize the frame or match the ratio."). Resize the layer, or choose **Match ratio**: the plugin keeps the layer's width and sets its height to the placement's ratio (an auto-layout hug or fill height becomes fixed), as one undo step. The size follows resizes on the canvas without reselecting.
4. A Figma toast says where the art went ("Sent to {placement} draft", with **Review**, which opens the console's releases), and the result under the form says "Draft updated. Publish it from the console when it's ready." with **View in console**, in place of the footnote about drafts. When a Sync also updated other draft cells that used the layer's earlier art, the result says how many, with the cells under **Details** (each named by its placement and the axes it declares). The sent layer is now linked to that cell (see below); a component's description, when Assetlib wrote it or it was empty, then names that placement for coding agents, as an insert's does.

Exports are PNG. The plugin uses the placement's width as the export constraint, or the placement's height when the layer is proportionally taller. Figma preserves the layer's aspect ratio; the plugin does not crop or stretch it. Within the 2% tolerance, match the layer's aspect ratio to the placement when you need exact canvas dimensions. After export the plugin reads the PNG's own size and stops before upload if that ratio is more than 2% off.

If a binding fails with HTTP 409, the console may still have created the image. The result says so with the console's own words ("The image was uploaded, but Assetlib couldn't put it in {placement}: …") and **Open image in console** in the same callout, and no success toast appears; check the console before retrying to avoid unnecessary duplicate images. A send does not publish a release; drafts don't go live until someone publishes in the Assetlib console.

## Sync later edits

Art inserted from a placement, a layer filled or replaced or dropped with it, and a layer sent to a placement are linked to their cell. Whenever one is selected, on either tab, the **Sync bar** above the footer says "Linked to {placement}", with the cell and where its art came from (for example "welcome · Dark · Control · from Production"; a sent layer's art is from Draft), the image's preview once the Insert list has loaded it, **Open in console** (the linked image's page in the console), and **Sync to draft**. **Cmd+Enter** (Ctrl+Enter on Windows and Linux) is Sync too, outside the connection settings. Sync re-exports the layer and sends it to that cell's draft with `rebind: true`: the console replaces the layer's earlier sends wherever they are bound in draft in the connected app, the result says how many other cells it updated (with the cells under **Details**), and a toast says "Synced {placement} to draft" with **Review**. A linked layer's first Sync fills exactly its cell, never the cell it inherited from. The link travels with the file, so teammates connected to the same app see the Sync bar on the layers you inserted or sent.

Linked layers also show **Sync to Assetlib** in Figma's properties panel, with their cell under it, and a document with any linked layer shows **Open Assetlib** when nothing is selected. **Sync to Assetlib** opens the plugin with the Sync bar focused; it never syncs by itself.

The Sync bar also says when Sync can't run, with the one action that helps:

- The layer's ratio is more than 2% off the placement's: "This frame is {w} × {h}; {placement} is {W} × {H}. Match ratio makes it {w} × {h′}.", with **Match ratio** as the bar's main button, and Sync unavailable. On the Send tab the callout above says it when it is about the placement chosen there.
- A copy of a linked layer (for example made with Cmd+D) isn't linked: "Copy of a linked frame. Copies aren't linked. Send it to replace {placement}'s draft." **Send…** opens the Send tab with that placement and cell chosen, for a **Send to draft** of its own (not a Sync, so the original's earlier sends stay). Once sent, the copy is linked in its own right.
- A layer linked to a placement in another app or workspace: "Linked to another workspace. Connect to that workspace to sync it."
- A placement or cell that no longer exists in the app: "Linked to {placement}. This placement no longer exists in this app." (or "This cell…"); **Send elsewhere…** opens the Send tab to choose another.

The bar shows the linked image's preview only once it has one: another workspace's link, a removed placement, or art the Insert list hasn't loaded shows no image square. Layers linked before the Sync to Assetlib button existed (and their documents) get the button the next time they are inserted, filled, replaced, sent, or synced; nothing adds it to them in bulk.

After a Send or Sync the plugin also remembers the layer's placement and cell on this device, and that wins over the layer's link there. **Replace image**, or a fill with placement art, links the layer to the chosen cell and forgets the target this device remembered for it, so its next Sync goes to the new cell; Undo doesn't bring that target back, so a layer that was sent but never linked then needs **Send to draft** again. Another device that sent or synced the layer keeps its own remembered target until it sends the layer again. Library images are not linked to a placement. A layer inside an instance can't be linked, and a draft the console didn't put in its cell (the 409 result above) links nothing.

## Data and network access

The plugin sends only the selected node's exported PNG bytes (base64 in JSON), node ID and name, file key, PNG export settings, chosen placement coordinates, asset name, schema version, and sync flag. `source.versionId` is `null`. The app-scoped draft token is sent as a bearer token to the chosen console origin, including once to `GET /api/token` when it is pasted and once a session for the saved connection's names (again when a connection change cut that request short or the answer could not be used, and the same connection came back).

It never sends the Figma document, unrelated layers, or a Figma token. Selecting a frame or group exports its visible contents as one PNG; it does not upload its editable layer tree.

It receives the pasted token's organization and app IDs, the workspace and app names when the console returns them, and the token's scopes; the app's placements; for each placement cell, which image it shows in draft, staging, and production, and when staging and production were published; the app's image names, sizes, and prepared versions; and the bytes of the versions it previews or inserts. Rendition URLs are built from the image ID and hash; the plugin never sends the token to a URL taken from a response.

Art inserted from a placement, a layer filled, replaced, or dropped with it, and a layer sent to a placement store plugin data `assetlib.link.v1`: the console origin, organization and app IDs, placement key, state, appearance, arm, environment, image ID, the node's ID, and the insert or send time. It never holds the token. The document stores `assetlib.file.v1` on its root: the file's key, whether it came from Figma or a pasted link, when it was saved, and the file's name then. A linked layer's relaunch data holds the text under its **Sync to Assetlib** button (its placement key, cell, and environment), and the document's holds the text under **Open Assetlib**. Plugin data is private to this plugin but travels with the file, so anyone with a copy of the file can read it; organization and app IDs are not secret, since they appear in public delivery URLs. Its component description holds the placement key and size, and its documentation link is `{console}/w/{organization ID}/{app ID}/placements`; anyone who can open the file reads both, including coding agents through Figma's MCP server. Neither holds the token.

The manifest declares:

```json
{
  "allowedDomains": ["https://console.assetlib.dev", "https://assetlib-console.vercel.app"],
  "devAllowedDomains": ["http://localhost:3100"],
  "reasoning": "Reads images from, and sends exported artwork to, the Assetlib console you connect."
}
```

A drag onto the canvas hands Figma the drop point and a description of what to insert (the name, size, scale, placement cell, and image ID), never the token; the download is the same request as an insert's. Every request goes through one module that refuses any other route: `GET /api/token` on the chosen console, which tells a pasted token its own organization and app (tried once, so the form answers at once), and exactly these five calls under `/api/apps/{orgId}/{appId}/`: `GET placements`, `GET placements/artwork`, `GET assets` (with `limit`, `cursor`, and `q`), `GET assets/{assetId}/renditions/{sha256}`, and `POST drafts`. Links into the console (**Open console**, **View in console**, **Open in console**, and a toast's **Review**) open in your browser; they are navigations built from validated IDs on the connected console, and never carry the token. The placements endpoint accepts `draft` or `declare`; the other four require `draft`. All of them authenticate only with that bearer token, never cookies, and must allow cross-origin requests from the Figma plugin UI. The hosted console does so for all five on both production hosts (checked on October 11, 2026); a console without the Insert reads answers them 404, and Insert then says it doesn't support Insert yet while Send keeps working. Rendition bytes are served `private, no-store`. The plugin never calls the public delivery routes. Local development requires that console server to be running on port 3100. The development-only origin is not available to a published plugin.

A read times out after 20 seconds, and a download after 20 seconds plus 15 per MiB the console listed for it. A read that fails with a network error, 502, 503, or 504 is tried twice more, after 1 and 4 seconds (or after the wait the console asks for in `Retry-After`, when it exposes one and it is longer), and one answered with 429 is tried again only when the console asks for a wait. A read whose console asks for a wait of more than 30 seconds is not tried again. A draft upload times out after 30 seconds plus 15 per MiB of its body and is never retried, since it may have arrived; the message says so. Searching or refreshing while a list loads abandons the earlier request, and changing the connection abandons every request in flight.

Messages are plain and say what to do next, without HTTP codes or developer terms: a refused or revoked token says to create a new one in Settings › Tokens (a revoked token's 403 included, wherever it is met); a token without the Draft permission says so; HTTP 409 keeps the console's own message; an export too large to send says "over 3.3 MB as a PNG" (whichever limit it met: 4 MiB of PNG, Vercel's 4.5 MB request, or HTTP 413; every PNG under 3.3 MB fits); a busy console (429) asks to try again in a minute; a server error says "Assetlib had a problem ({status})"; an unreachable console says to check the internet connection (the local console is named, since it may not be running); timeouts say how many seconds the plugin waited, and a draft that timed out may have arrived anyway. A console without the Insert endpoints (a 404) is reported as such while Send keeps working, a network failure on an Insert read is said as one ("Can't reach Assetlib. Check your internet connection.", with **Try again**), and an image removed after the list loaded asks for a Refresh, with **Refresh** in the error line. When `GET /api/token` fails with a network error, the form asks for the organization and app IDs (an older console without that route's CORS headers looks the same); a later **Connect** with the ID fields still empty asks the console about the token again. Finished operations are Figma toasts of at most 100 characters; every toast, result, and error is also announced through one status and one alert region. The shared contract allows at most 4 MiB decoded PNG bytes and 4,500,000 bytes for the JSON body, Vercel's request limit, so a base64 PNG above about 3.3 MB decoded does not fit.
