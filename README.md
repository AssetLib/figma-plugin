# Assetlib for Figma

Insert your app's placement artwork and library images into Figma, then send one or several selected layers to their own draft placements. Destinations are remembered, and first and repeat sends use the same **Send to draft** action. Publishing remains a separate action in the Assetlib console.

Submitted to Figma Community on 2026-10-21; review is pending. Use the development install below until the public listing is available.

## Install as a development plugin

Use Node.js 22 or newer (`.nvmrc` names 24) and the Figma desktop app.

```sh
npm ci
npm run verify
```

The build creates a minified `dist/code.js` and a self-contained `dist/ui.html`. Both outputs must exist before importing the plugin. While changing the source, `npm run watch` rebuilds both, unminified and with inline source maps, on every save.

1. In Figma desktop, open a design file, select **Plugins → Development → Import plugin from manifest…**, and choose this repository's `manifest.json`.
2. Run **Plugins → Development → Assetlib → Open Assetlib**. Rebuild after source changes; use Figma's development hot reload or reopen the plugin.

`manifest.json` commits the plugin `id` `1690264758934826227`, which Figma assigned when this plugin was created as a development plugin. The plugin is not published to the Figma Community. Figma scopes client storage to the plugin ID, so saved connections and send destinations belong to that ID; don't change it in the repository. A manifest without an `id` imports, but the plugin then cannot save its connection: Figma reports `Cannot access client storage without a plugin ID`.

To use a development ID of your own instead: select **Plugins → Development → New plugin**, choose **Figma design** and **Custom UI**, save the generated starter in a separate temporary folder, and copy its `id` into your local `manifest.json` before importing. If Figma lists that starter under the same ID, remove its development entry first. Don't commit your ID. Client storage under a different ID starts empty, so connections and send destinations saved under the other ID don't carry over.

See Figma's [development plugin instructions](https://help.figma.com/hc/en-us/articles/360042786733-Create-a-classic-plugin-for-development), [manifest reference](https://developers.figma.com/docs/plugins/manifest/), and [client storage reference](https://developers.figma.com/docs/plugins/api/figma-clientStorage/). The manifest uses Plugin API `1.0.0` and the required `documentAccess: "dynamic-page"`. It does not enable private plugin APIs. When Figma does not expose the file key, the plugin asks for the file's link once when Send needs it (see [Send artwork](#send-artwork)). It declares two relaunch buttons for Figma's properties panel: **Send to draft…** on linked layers and **Open Assetlib** on a document that has any.

## Test against staging

Choose **Change → Console → Staging console**, then **Connect to Assetlib**. Approve in `assetlib-billing-staging.vercel.app`. To keep a saved production connection untouched, import a separate development plugin using your own ID (see above); keep the repository’s ID unchanged. The account chip says **Staging** while connected to this separate console; its workspaces, images, tokens, and browser links stay there. Inside that console, Draft, Staging, and Production still name its own release environments. Publish test releases only to **Staging** in the console.

The release manifest allows the exact staging host alongside production; arbitrary preview hosts are not supported. Production remains the default, and saved connections stay unchanged. A staging token is never reused on production. Localhost appears only in `npm run watch` or `node scripts/build.mjs --dev` builds and is allowed only for development plugins.

## Connect

The plugin opens on a first-run screen until it is connected: the Assetlib lockup, "Bring app artwork into Figma. Send edits as drafts; publish in Assetlib.", **Connect to Assetlib**, and **Use a token instead**. Under Connect, it says: "Approve in your browser. You need editor, publisher, or owner access." **Figma guide** opens the [guide](https://www.assetlib.dev/guide#figma). A Figma access token is neither needed nor accepted.

**Connect to Assetlib** starts a connection request on the chosen console and opens its connect page in your browser (`https://console.assetlib.dev/connect/figma`, `https://assetlib-billing-staging.vercel.app/connect/figma` for staging, or `http://127.0.0.1:3100/connect/figma` for the local console). The plugin then shows "Approve in your browser" and a code such as `BCDF-GHJK`; sign in, check that the page shows the same code, choose the workspace, and approve. Assetlib never asks you to type the code. The request expires after 10 minutes ("Waiting for approval · expires in {n} min", renewed every 15 seconds), with a spinner while waiting or saving (none with reduced motion). The plugin asks the console every 2 seconds whether it was approved (less often if the console asks it to, or while the console can't be reached), and again when you come back to Figma; **Check now** asks now, **Open browser again** opens the page again, and **Cancel** ends the request. A request still waiting when you close the plugin resumes when you open it again ("Approve in the {host} tab you opened earlier, or cancel and start again."). Once approved, the console issues the plugin a draft-only token of its own, which the plugin saves with the workspace and app names and the email that approved it, and a toast says "Connected to {Workspace} · {App} as {email}". A declined request says "The request was declined in the browser. Connect again to approve it, or choose another workspace." An expired or cancelled request says so too, with **Connect to Assetlib** to start again; one approved for another plugin window on this device connects this window too (plugin windows waiting on one request take turns asking the console, so they never slow each other down, and **Cancel** in one keeps a connection another already saved from it); one used elsewhere is stopped ("This request was already used, so Assetlib stopped it. Connect again."). An approval that arrives while a Send or Insert runs is saved once it ends ("Saving connection…"), so that operation finishes with the connection it started with. **Connect again** from Insert or Send opens the connection settings and focuses **Check now** once the request waits. If the settings were already open, **Cancel** returns focus to the visible connection button; otherwise it closes the settings and returns focus to the account chip. A console from before one-click Connect (its connection routes give a plugin window no answer, while `GET /api/token` does) opens the token form ("This console can’t connect from Figma yet. Use a token instead."), and hides **Connect to Assetlib** and its browser help until another console is chosen. The token form’s button becomes the primary action, including for a refused pasted token. A console that can’t be reached says "Assetlib couldn’t be reached. Check your internet connection, then try again." ("Can’t reach the console at localhost:3100. Check that it’s running." locally), with **Try again** and **Use a token instead**. When layers on the current page are linked to one of your workspaces, the connect page offers that workspace first.

While the settings are open for a refused pasted token, Insert and Send keep their duplicate failure notices hidden, including after an empty, malformed, or refused replacement token is submitted. Send’s **Try again** keeps its notice and focus while retesting the same connection; identifying or saving a replacement connection hides the old notice.

**Use a token instead** shows the token form and makes **Connect with token** its main button, with **Connect to Assetlib** secondary (an unreachable console keeps **Try again** primary). The help says "Ask a workspace owner for an Assetlib Draft token: Settings › Tokens. Not a Figma token." To connect, create a **Draft token** in **Settings › Tokens** in the [Assetlib console](https://console.assetlib.dev) (only workspace owners can create tokens), paste it into **Draft token**, and choose **Connect with token**. A draft token can read every image in its app and update draft placement bindings; treat it accordingly.

A pasted token must look like an Assetlib token (`alk_` and 43 more characters); anything else is refused at once, with nothing sent. The plugin then asks the console which organization and app the token belongs to (`GET /api/token`), so nobody copies IDs, and saves the connection with the workspace and app names when the console returns them. Once a session, after the saved connection's first passing test, it asks again quietly, so a connection saved before the console named apps, or a workspace or app renamed since, shows today's names; a failure, or an answer without names, changes nothing. A token the console refuses or has revoked, or one without the Draft permission (a CI declare token), is explained under the token field, which is marked and focused. A console from before `GET /api/token` (it answers 404, or the token’s request gets no readable answer but a tokenless request does) gets the organization and app ID fields instead, under "This console also needs the organization and app IDs. Find them in Settings › General.", a neutral notice rather than an error (no field is marked), with the organization ID focused; the form then uses them. If neither request gets an answer, the form says the console couldn’t be reached, marking no field and asking for no IDs. If the token request failed on the network but the tokenless request answered, submitting again with both ID fields empty re-asks the token; a successful answer hides the ID fields and saves the returned names. The ID fields belong to the console that asked for them: choosing the other console hides them (a token pasted for it is identified with `GET /api/token` again), and **Disconnect** forgets them.

The line "Assetlib at console.assetlib.dev · Change" keeps the console choice out of the way. The line and the console picker both stay hidden while a connection request waits or a healthy account menu shows. **Change** reveals and focuses **Console**; it starts revealed for a chosen or saved staging or development console, a request or page hint on it, or while ID fields show. **Console** chooses `console.assetlib.dev` (the default) or **Staging console**; development builds also offer `localhost:3100 (development)`. Figma rejects IP-literal development domains such as `http://127.0.0.1:3100`, and the console accepts the `localhost` host for token routes and the connection request routes in local mode; its sign-in, connect page, and every console page the plugin links to (**Open console**, **Open in console**, **View in console**, a toast's **Review**, a component's documentation link) are on `127.0.0.1`, which the plugin only opens in your browser. Other origins are rejected.

Once connected, the plugin shows its tabs, and the account chip at the top right names the connection: "{Workspace} · {App}" when the console said (a long workspace name shortens first, so the app's name stays whole, and an app name that leaves the workspace no room shows alone, as in a narrow window), else the app by the start of its ID. A Figma toast says "Connected to {Workspace} · {App}" (the app's name alone when both would pass the toast's 100 characters), or "Connected to Assetlib" when the console gave no names. The chip opens the account menu below the top bar: the app's name (without names, the app as the chip names it, with both IDs on hover), "{Workspace} · Connected with token {prefix}…", **Open console**, **Connect with browser**, **Update token**, and, set apart on the right when the actions fit on one line, **Disconnect**. The actions wrap in a narrow window. **Connect with browser** starts a request offering the current workspace; its approval replaces the pasted connection without ending the pasted token (an owner revokes it). **Update token** shows the token form (paste another token and choose **Save token**; with the field empty, it tests the saved connection again); the form shows at once while the connection needs attention. A refused pasted token offers **Connect to Assetlib** as the panel’s main button, with secondary **Save token** below; a blank Save token says "Paste a new token, or choose Connect to Assetlib above." without sending anything. A network or server failure keeps **Connect** as the form’s main button. Otherwise the footer's **Insert** or **Send** is the main button. **Esc** closes the menu, which is a menu again the next time it opens. **Disconnect** forgets the token on this device and returns to the first-run screen; after a refused pasted token it says "Disconnected. Assetlib had stopped accepting that token." with no Undo. For a healthy pasted token, its toast has **Undo** for six seconds, which saves the same connection again (only an owner can create another token), unless you connected again meanwhile. A healthy pasted token itself keeps working elsewhere until an owner revokes it in the console.

A connection made with **Connect to Assetlib** shows "{Workspace} · Connected as {email}" in the account menu, with **Open console**, **Switch workspace**, and **Disconnect**, and no token form. **Switch workspace** starts a new request while the current connection keeps working (Insert and Send included); once the new one is approved, the token it replaces is ended (and so is a browser connection another plugin window saved on this device meanwhile), and **Cancel** leaves everything as it was. A plugin window whose connection another window replaced that way takes up the device's connection when the console refuses its own, rather than asking you to connect again; a draft refused that way says "The connection changed in another plugin window, so nothing was sent. Try again." **Disconnect** ends the token in the console first, so it has no Undo: "Disconnected. This connection was ended." If the console can't be reached, the plugin forgets the connection anyway and says "Disconnected on this device. End the connection in the console under Settings › Profile." When a linked layer belongs to another app on the same console, the linked-artwork bar says "Switch to that workspace to sync it." with **Switch workspace**, which offers that workspace first.

Each time the plugin opens, it tests the saved connection by reading the placements. A failed test opens nothing: the chip shows a warning, and the view in front says why, once, with the one action that helps. On **Insert** the list says it in its place; on **Send** a notice above **Placement** says it. The action is **Try again** (offline, busy, a server error, or a timeout; on Send it runs the test again) or, for a refused pasted token, **Connect again**, which starts a browser request offering the current workspace. It says "Assetlib no longer accepts this token. Connect again to approve the plugin in your browser, or paste a new token." A token lacking the required scope keeps **Update token**, which opens the settings at the token field. While the settings are open the reason shows under the token field instead (a refused token is marked), and the list or the notice steps aside, so the failure is never said twice; a test that fails while you are in the settings (after you saved a new token, say) is said there and focuses the token field, unless you are typing in another field. A refused token on a later read (the Insert list, or an insert) works the same way. A refused Send also warns the chip and offers **Connect again** in the error line. A connection made with **Connect to Assetlib** never shows the token form: when the console no longer accepts it, the view says why ("This Figma connection was ended.", "Your role no longer allows sending drafts. Ask a workspace owner, then connect again.", or "This Figma connection expired.", each followed by what to do) with **Connect again**, which starts a request offering the same workspace; a refused insert or draft says it in the error line with the same action. The chip returns to connected after the next successful read, and the reason goes. An artwork read that started before a newer refusal still supplies artwork, but cannot clear that refusal or its recovery action. If the test itself failed, for example while offline, the next successful read also loads the placements before the label changes, so Send works without another test. If Figma can't save new settings, the previous connection keeps working, with its lists and Send, and the message under the token field asks you to try again; the token you pasted stays in the field.

Connections saved by earlier builds may name the console's previous host, `https://assetlib-console.vercel.app`, and have no names. The plugin loads such a connection on `https://console.assetlib.dev` with the same token and saves the change, and send destinations remembered under the previous host still apply. The console still accepts app tokens on the previous host, and the manifest keeps it allowed so an unrebuilt `dist/` keeps working. New connections cannot choose it. Saved tokens are not checked against the `alk_` format again, so an older save keeps loading.

Settings and the token are saved through `figma.clientStorage` on this device. The token field is cleared after saving, and only a short prefix of a pasted token is displayed afterward; a token the console issued to **Connect to Assetlib** is never displayed or put in a field. While a request waits, only its read key, code, expiry, and when a plugin window last asked about it are kept there (at most 15 minutes, and deleted when the request ends). The plugin does not log the token. Figma client storage is local plugin storage, not an encrypted credential vault; clearing it or changing the plugin ID loses the connection and remembered send destinations.

Each Send records which Figma file the art came from. The plugin uses Figma's file key when available, otherwise the key saved in the document. When neither is available, Send asks you to choose **Share → Copy link** in Figma and paste the link. Cmd+L (Ctrl+L on Windows and Linux) is an optional shortcut. A valid link whose name matches this document saves automatically; saving it does not send artwork. The plugin accepts `/file/` and `/design/` links, including branch links. A link naming another file, or no file name, needs **Use anyway**; editing the link withdraws that confirmation. A matching name is a check, not proof of identity. In a view-only file the key lasts only for the session. **File: {name} · Change** lets you correct it, including after duplicating a file. The link last pasted on this device is only a prefill for the file it names.

## Insert artwork

In **Images**, **Upload images…** stays available above the library and opens this app’s Images page in the console. Image files belong in Images; the app catalog defines placements. When Placements or Send has no placements, **Set up app catalog** opens this app’s **Settings › Connect** instructions. An engineer keeps the catalog in the app repository and runs `assetlib sync`; Send then sends selected Figma layers to existing Draft placements. These links only open the console and never upload or change the Figma document.

The plugin opens on **Insert** (it remembers the tab you last used). The first connected Placements view explains placements, cells, and environments in a callout that scrolls with the list, with **Figma guide** linking to the [Figma guide](https://www.assetlib.dev/guide#figma). **Got it** hides it and focuses the search; the first successful insert or drop hides it too. It stays hidden on Images, when the list is empty or has an error, and after dismissal on this device. The drag hint stays hidden while the intro shows. **Search placements or screens** matches placement keys and screen names. Its bars stay fixed and only the list scrolls: the top bar (the **Insert** and **Send** tabs and the account chip), the search field and **Refresh**, then **Placements**, **Images**, or **In this file** and, for placements, the environment. A chosen placement’s cell strip scrolls separately in its footer when needed.

The visible **All**, **With art**, and **No art** filters show the number of placements each choice would return for your current search and environment. **With art** includes a placement when any of its cells has artwork, including inherited art; **No art** means every cell is empty in that environment. The result line keeps the shown count, total placement count, and environment visible together. Filters reset when the connection changes or a linked placement is revealed; **Clear filters** recovers from an empty result. Images use larger previews with names and dimensions below them. **Search image names** describes the scope, and the result count says “loaded · more available” until every matching page has loaded.

The window opens 420 px wide and 64 px shorter than the canvas on screen, from 480 to 720 px tall. Drag the grip in its bottom-right corner to resize it, from 320 × 480 up to 900 × 1000; only the list grows. The size you leave it at is remembered on this device, and a double-click on the grip goes back to the default. Below 400 px wide the image grid keeps two flexible columns even when a scrollbar uses layout space, and the environment becomes a dropdown; from 560 px a placement’s ratio and declarations move to a column on the right, with its short name over its full key, and the image grid adds columns as it widens.

- **Placements** lists the app’s placements grouped by screen. Each 72 px row has an up-to-80 × 56 px preview in the placement’s proportions, a short name (the last part of its key), and the full key and ratio with its declared axes, such as `3:4 · 2 states · light/dark · arm b`. An empty cell has a dashed slot in the same proportions. One chip says **{n} behind**, **In this file**, or **Not in this file**; until all pages are included it says “on this page” instead. The presence chip’s tooltip names the linked environments, independently of the environment browsed in Insert. Behind counts linked layers whose art differs from their environment’s current art; select a layer and choose **Update Figma layer** to change it. Before artwork loads the chips say only whether the placement is present. **Unavailable** and **Needs re-upload**, with a warning glyph, take precedence when Insert cannot use the base art. Draft status stays in the row’s tooltip: no art, new or changed Draft art, or how many cells inherit. New and Changed compare cells’ own Draft art with Production when it has a release; inherited art is present, while a null cell shows nothing. Production is the automatic environment, falling back to Draft until a Production release exists. Picking **Draft**, **Staging**, or **Production** remembers an explicit choice; old saved environments without an explicit choice use the new automatic default. An explicitly chosen environment without a release shows Draft and a note until it has one. Environment tooltips explain where the art goes and name published releases and dates. Sending changes Draft; publishing stays in the console. Select a row to show its cell strip when it has several cells. State rows start with the default, and columns show Control then the declared arms, with Any, Light and Dark within each. Each cell previews its art; a dashed outline means it inherits, and its tooltip names the source. The footer names the chosen axes and any inherited art. A cell with no art in the shown environment says "No image in Draft for this cell yet.", or "No image in {Environment} for this cell. Sending puts it in Draft." With one exportable layer selected, **Send selected layer here** opens Send with that placement and cell chosen and **Send to draft** focused; without a selection, only the note shows. This explicit Send keeps the footer visible even when the layer is already linked to that empty cell. Inherited art is present, so it offers no empty-cell action.
- **Images** lists every active image in the app, newest first, in a grid, with search by name and **Load more**. Each tile's name takes at most two lines and then ends in an ellipsis, breaking after a `.`, `_`, or `-` first (`travel.coast.|background`) and anywhere only as a last resort; its tooltip has the whole name, size, and type.
- **In this file** lists this app’s linked layers and copies, grouped by their top-level frame. Search matches layer names, placement keys, and frame names. Each row shows the linked image, layer name, cell and environment, with **Behind**, **Current**, **Copy**, or **Removed** after artwork loads. Click a row, press **Enter**, or double-click to select and reveal it on the canvas; arrows only choose in the list. The linked-artwork bar then offers the layer’s available actions. On a multi-page file the list starts with “This page only.”; **Include all pages** loads the other pages for the rest of this plugin session and labels groups with page and frame. **Refresh** scans again, as does returning to this view or window. The local scan holds at most 2,000 entries. Once the file key is known, it reports bounded linked-layer metadata and scan coverage to the console’s Figma view (see Data and network access). It never updates artwork by itself. This view has no Insert footer or environment selector.


While a list loads it shows grey placeholder rows or tiles. A list that can’t load shows a headline above its reason, with the one action that helps: “Couldn’t load the list” with **Try again** (a network, busy, or server error), “Connect to Assetlib again” with **Connect again** (a refused token), “This token can’t be used here” with **Update token** (a token without the Draft permission; it opens the settings at the token field), or “Insert isn’t available here” with **Go to Send** (a console without the Insert routes). The action is primary unless the linked-artwork bar shows, when it is secondary. An empty app says where placements come from (**Read the guide**), an empty library offers **Open console**, and a search with no matches offers **Clear search**.

While the plugin connects, sends, inserts, or uses newer artwork, actions that would conflict wait and keep keyboard focus. Send shows “Sending {n} of {total}…” with per-layer progress; incoming artwork shows “Updating Figma layer…” while the Insert footer keeps its usual label. Tabs, Insert search, lists, environment, scale, and connection fields stay usable. Send destinations cannot change during a running batch. An error that arrives while you type keeps focus and your text in the field.

**Keyboard.** **Tab** moves between the panel's parts: the tabs, the account chip, the search, **Refresh**, **Placements**, **Images**, or **In this file**, the environment, the list, the linked-artwork bar’s title and actions (when the selected layer is linked), then the footer. The tabs, each segmented control, and the list are one stop each, and the arrow keys move inside them: **←** and **→** switch tabs (and show the one they reach) and choose within the Browse choices, the environment (passing over one with nothing published), and **1×**/**2×**/**3×**. In the list, **↑** and **↓**, **Home**, and **End** move the choice, and typing the start of a placement’s short name or full key, a layer name, or an image name jumps to the next one that matches; in the image grid **←** and **→** move by one tile and **↑** and **↓** by a row. **Enter** or a double-click inserts the row or tile, with the cell chosen in the footer (choosing the chosen row again keeps it); on one Insert can't use, it says why instead. In the cell strip, one checked cell is a tab stop: **←/→** choose in its row, **↑/↓** choose the same or nearest occupied column in the next state row, **Home/End** choose the row’s ends, and **Space** chooses. **Enter** or a double-click inserts that cell. The strip is at most 160 px tall and scrolls when it has many cells. In **In this file**, **Enter** and a double-click reveal the layer instead of inserting. **/** (outside a text field) or **Cmd+F** (Ctrl+F on Windows and Linux) focuses the search from either tab, with its text selected. **Esc** in the search or the list clears the search, then the choice. When an insert fails, focus moves to its error.

**Drag.** You can also drag a row or tile onto the canvas. Only one that **Insert** could insert now drags (not one marked **Not set**, **Unavailable**, or **Needs re-upload**, nor an image over 4 MiB in every version, nor while something else is being inserted or sent); the chosen row drags the state, appearance, and A/B arm its footer shows. The download starts as the drag starts. Where it lands decides what happens: on an image frame (never an instance; a frame showing an image with nothing inside, such as one the plugin inserted), its image is replaced, as **Fill** or **Replace image** would; anywhere else a grey placeholder named "{name} · loading" appears there, centered on the drop point (or added last to an auto layout frame), inside the nearest frame, group, section, or component that can hold it, or on the page. An instance’s image is never replaced by a drop; its nearest permitted ancestor holds the placeholder. Placement art cannot go inside a component or instance. The placeholder fits both dimensions of a frame or component without enlarging the reference art; elsewhere **1×**, **2×**, or **3×** sets its size. It takes the image when its download finishes, and the placeholder and its image are one undo step. If the download fails, the placeholder goes and the error says why. A drag that ends back in the plugin window inserts nothing, and a file dragged from your desktop keeps Figma's own behaviour. Rows and tiles that drag show a grab cursor. Until your first insert, a hint bar under the list says "Drag onto the canvas, or select an item and press Enter." ("Drag onto the canvas or press Enter." below 400 px), except while the linked-artwork bar or intro shows; its close button hides it for good on this device.

What is selected on the canvas decides what the footer’s main button does, and names it. The note explains the destination and link before any component limitation: a fill names the layer or count and cell, says its size and position stay for one layer, and counts skipped layers; an insert into a container names it; an insert beside an unsupported selection says so. Replace names the old and new cell when it relinks, or says the link stays (including with a library image). Nothing selected needs no note:

| Selected | Button | What happens |
| --- | --- | --- |
| Nothing | **Insert** | A new layer, centered in the current view |
| One instance of a local Assetlib placement component | **Replace in component** or **Fill component** | Changes the main’s image and link, so every instance follows; never writes an override on this instance |
| One instance of an Assetlib component from a library | **Insert** | A new layer beside it; change the library’s image in its own file |
| Several layers including Assetlib placement instances | **Fill {n} layers** when any can be filled | Skips those instances so they keep following their main; the note counts them |
| One linked shape, frame, component, or other instance that shows an image (art inserted, filled, replaced, or sent from this app; not a copy) | **Replace image** | Its image is swapped, and it is linked to the chosen cell |
| A frame or component with layers inside | **Insert into {name}** | A new layer inside it, centered, or added last in an auto layout frame. Placement art is a component, and Figma doesn't put a component inside another, so with a component, or a frame inside one, it is **Insert** and goes 40 px right of it instead |
| Shapes (rectangle, ellipse, polygon, star, vector, boolean), or frames, components, and other instances with nothing inside | **Fill {name}** or **Fill {n} layers** | Each one shows the image; text, lines, groups, sections, and frames with layers inside are skipped |
| Only layers that can't show an image (text, lines, groups, sections, linked by a Send or not), or an instance with layers inside | **Insert** | A new layer 40 px right of the selection |

A new layer has an image fill and is selected, and a Figma toast says so: art from a placement as a component, an image from the library as a frame. Placement inserts are named after the placement and cell (for example `onboarding.hero · b · dark`) and sized to the placement's width and height; image inserts take the image's name and size. **1×**, **2×**, and **3×** show only for a new layer on the canvas or beside the selection: 1× keeps the reference size, 2× and 3× divide it. Into a container, the art fits both its width and height while keeping its proportions, never enlarging the reference size. The footer shows the actual resulting size first (for example `→ 390 × 520 · Production`), then the chosen cell’s axes. Fill and replace keep the existing layer’s dimensions. An item that can’t be inserted shows no scale control; below 400 px the footer drops its preview so the name stays readable. Figma gives instances no new layers, so an instance with layers inside is not a frame to insert into; if Figma refuses a frame anyway, nothing is left behind and the error suggests **Insert as new layer**. A component, or a frame inside a component, takes a library image but not placement art, which is a component itself; the footer then says the art goes beside it.

A fill keeps the layer's size, position, constraints, and other paints, so the scale control is hidden. It replaces the layer's topmost visible image paint, keeping its scale mode, crop, filters, opacity, blend mode, and visibility, or adds a visible image paint on top when none is visible. Hidden image paints stay as they are. Each layer filled with placement art is linked to the cell with its own ID, so each has its own send destination and later shows **Replace image**. Layers inside an instance are filled but can't be linked, since Figma keeps no plugin data there, and the toast explains that those layers cannot be linked (it says so too for any other layer Figma doesn't let the plugin link). If Figma refuses the image on some of the selected layers, the toast says how many it filled, and whether any of them could not be linked. **Replace image** relinks the layer to the chosen cell; on a component the plugin inserted, the description agents read then names that placement, and a layer still named for the placement it showed takes the new one's name (a description or name you wrote yourself is never changed). A library image never writes or removes a link, so a linked layer filled with one stays linked to its cell. In the modes that use the selection, **Insert as new layer** under the main button makes a new layer beside the selection instead.

Every insert, fill, replace, and drop is one undo step (Cmd+Z). The toast after a fill, replace, or Update offers **Undo**, which takes back the fill's image, link, name, and marker and nothing else. It isn't offered when the selection moved away from the filled layers before the fill finished, or when any filled layer had a fill style, is an instance, or sits inside one; Cmd+Z on the canvas still takes the fill back. The toast goes when the selection or the page changes, when a Send starts, when the plugin makes another edit (a file link, a Send's link, Match ratio), or, with one filled layer selected, when it is resized or renamed or its image changes on the canvas (Cmd+Z included). Undo takes nothing back, and says "Not undone. These layers changed after the fill.", if a filled layer was moved, resized, rotated, hidden, locked, renamed, relinked, repainted, restyled (fill style, opacity, strokes, effects, corners, constraints), moved into another layer, or deleted since the fill. Edits Figma doesn't tell plugins about stay as they are after Undo: one to another layer that leaves the selection as it was (hiding or locking it in the layers panel, say), a reorder among siblings (except in an auto layout frame, where moving the layer changes its position and Undo says "Not undone"), or a change to a filled layer the guard doesn't compare (stroke position or dashes, export settings, layout grids, absolute position, prototype links). Undo is its own step, so Cmd+Z after it brings the fill back. If Figma refuses one of Undo's changes, Undo puts back what it already changed and says it didn't undo the fill. The choice, the tab, the browse mode (including In this file), an explicitly chosen environment, the scale, the window's size, and whether the hint bar and intro were dismissed are remembered on this device.

A placement's component carries a description that names the placement and its size, and a documentation link to the app's placements in the console. Figma's MCP server passes both to coding agents that build the screen from the file, so the description tells them the image is data-supplied and that its exact match in code is the accessor generated for that placement, which carries the bundled fallback: they render it with that accessor instead of a downloaded file, and download it only as the bundled fallback of a placement not yet in the app's catalog. These are the two exceptions Figma's design-to-code skill allows to its rule that agents download every image. Copies and instances of the component carry the same description. If the file is published as a team library, these components appear in the publish dialog; leave them unselected.

For a new layer (and a drag) the plugin downloads the largest prepared version of the image that is PNG or WebP and at most 4 MiB, preferring PNG; for a fill or a replace, the smallest one at least three times as wide as the image is drawn in the layers (it covers each layer, so a layer proportionally taller than the image draws it wider than the layer), never wider than the original, else the largest. Figma accepts PNG but not WebP, so a WebP version (photos have only WebP versions) is converted to PNG in the plugin window first, with a Display P3 image converted to sRGB. An image larger than 4 MiB in every version can't be inserted, and the footer says so before you try, with **Open in console**; so does an image uploaded before the console prepared versions, which has none (upload it again to use it in Figma). A version downloaded for an insert or a drag is kept in the plugin window for a minute, so dropping it, or inserting it again, doesn't download it twice. Originals are never downloaded. An animated (Lottie) image is inserted as its still poster, and an SVG image as its PNG version, not as editable vectors.

In **Images**, add two or three candidates to **Compare**. The temporary shortlist survives search changes; Refresh and a connection change clear it. Compare uses the same Light, Dark, Transparency, Fit, and 100% preview controls as Send, shows source and decoded-preview dimensions, and describes compatibility with the current Figma destination. **Use this image** becomes available after that candidate's preview decodes and only selects it; Insert or Fill remains a separate action. A failed preview can be retried with Refresh preview. Changing the Figma selection or connection closes the comparison.

Send also previews exactly which other current Draft cells a replacement changes, including the source family each inherits. A partial family names missing states: the first nonempty family wins every state, so a missing state does not fall through to another family. Incomplete artwork responses show impact unavailable. A read immediately before Send checks the reviewed impact; a change requires **Impact reviewed** and another explicit Send. Later batch rows in the same placement are checked again after a successful write. This read is not an atomic lock on all sibling cells: the existing conditional write protects the target's resolved artwork. These counts describe the current Draft, not live app reach.

Previews are downloaded the same way, from the smallest version up to 512 KiB, and shown from memory; an image without such a version shows an empty checkerboard. Only rows and tiles within 300 px of the list's view load previews, three at a time, the most recently scrolled-in first; one that scrolls away before its download starts gives up its place. The footer’s and Send’s current Draft previews load whenever they show. A preview that fails with a network or server error is tried again after 1 and 4 seconds, and **Refresh** tries every failed preview again. If the console limits requests, previews pause and resume shortly.

Browsing **Placements**, **Images**, and **In this file** keeps each view’s search, selected artwork/cell, keyboard position, and scroll during this open session. Connection changes clear that context; refreshed or deleted items are checked before reuse. Empty placement results offer a counted change to one constraint while keeping the other.

## Send artwork

On the **Send** tab:

1. Select one or several layers, up to 50. Each row shows its layer and draft destination, with any problem beside it. A frame or group exports as one image including its visible contents.
2. Choose a row to set its placement, state, appearance, and A/B arm. Open **Placement** to compare Draft previews, keys, screens, ratios, and whether each placement fits the selected layer. Fits appear first. A candidate shows its default cell; the current choice shows its selected cell. **Find placement** searches the app's declared placements; the plugin does not create placements. Destinations save automatically on this device for that file, layer, and connection. Changing one never sends artwork. Existing links and remembered destinations are shown when you return.
3. Review the rows, then choose the footer's **Send to draft** action. It stays in the same place for first and repeat sends and names how many ready rows it will send. Blocked rows stay visible; two layers targeting the same draft cell need different destinations or an explicit skip. The plugin exports and sends the reviewed rows one at a time. Each request changes only its displayed binding. Other explicit bindings stay as they were; inherited cells can follow their base artwork.
4. Check each row's result. Successful sends remain visible while the plugin is open, and retrying a failed row does not resend completed rows. A successful send links the layer to its cell. **Review these drafts** opens the exact successfully assigned placements and cells in the console. Failed, uncertain, and unassigned uploads are excluded; when nothing was assigned, the link opens Releases. The console shows current Draft artwork, which may have changed since sending. Publishing remains a separate action for the whole Draft.

The visual placement list has counted **All**, **Fits this layer**, and **No Draft artwork** filters. Counts follow the current search; an unmatched saved choice stays visible without increasing the count. Empty means the candidate’s default cell has no Draft art, or the selected cell for the current destination. Inherited art counts as present. Unknown artwork waits for loading before the empty filter is available. When nothing matches, a counted recovery action removes only the search or the artwork/fit filter, choosing the adjustment with the fewest positive matches. The other constraint and the destination stay. A different ratio stays labeled and must be corrected before Send.

In the visual placement list, arrows, Home, and End move focus without changing the destination. Click a row, or press Enter or Space, to choose it; Escape closes the list unchanged. Search keeps an unmatched current choice labeled, and **Clear search** restores candidates within the active filter. Choosing the current placement keeps its cell. Previews load near the chooser’s scroll area, independently of Insert.

Before sending or approving a replacement, compare **Selected Figma layer** with **Current Draft**. The selected layer’s preview is generated locally, limited to a 256 px long edge and 256 KiB, and never uploaded by previewing. **Inspect artwork** opens a larger comparison at the same fit. **Transparency**, **Light**, and **Dark** backgrounds affect only the preview. **Fit** contains the image; **100%** displays one preview pixel per CSS pixel and allows scrolling in a bounded, keyboard-focusable viewport. Figma layer or Draft source dimensions, placement reference dimensions, and decoded preview dimensions are labeled separately; this is not an app-rendering simulation. Left/right arrows switch between the layer and Draft except within the background/scale groups or the scroll viewport; Escape closes it and returns focus to Inspect artwork without changing the destination. Opening the inspector requests a local preview up to 1024 px and 1 MiB; Draft inspection uses a rendition up to 2048 px and 1 MiB. Preview caching is bounded to 200 entries and 8 MiB of encoded data. **Refresh preview** rereads the local layer; a preview is not proof that every later nested canvas edit has been detected. Unknown or unavailable previews are labeled, and do not block an explicit Send. Batches also show **Needs attention** and **Next issue**, which moves through included rows needing a destination, a compatible ratio, a conflict decision, or result review. It does not change the canvas selection or send anything.

The visual Send cell chooser shows declared states by row and appearance/A/B arm by column, with the resolved Draft artwork and **Assigned**, **Inherits {source}**, or **No Draft art** on each cell. Its scroll area keeps state and column headers visible; the line above names the selected destination. **Any** appearance and **Control** arm are the base choices. Click, arrows, Enter, or double-click only select and remember a destination; **Send to draft** remains a separate action. Before artwork is known, the existing selectors remain available with unknown previews labeled. When Draft changed since the layer's remembered image or the review, resolve the row's conflict before replacing it. **Skip this layer** leaves both the current draft and the canvas unchanged; **Use this layer instead** approves replacing the reviewed draft on the next Send. A later draft change requires review again.

A layer whose aspect ratio differs from its placement by more than 2% stays blocked. Resize it or choose **Match ratio**, which keeps its width and changes its height in one undo step. A queued operation keeps its original connection, selection, file, and destinations; changing them cannot redirect it.

Exports are PNG at up to 3× the layer’s size, capped by the sharpest raster’s native density (at least 1×) and a 2048 px long edge, the largest rendition Assetlib keeps. The export snaps down to a multiple of the placement’s reduced ratio when possible: a 390 × 292.5 layer for 1200 × 900 exports 1168 × 876. When the edge cap binds, the note ends “the largest size Assetlib keeps.” If the PNG exceeds 3.3 MB, the plugin tries 2× and then 1× with the same native-density and edge limits, skipping duplicate sizes, and refuses it if none fit. Figma preserves the layer’s aspect ratio; the plugin does not crop or stretch it. The placement’s width and height are a reference for proportions and the app’s requested size. Before upload the plugin reads the PNG’s own dimensions and refuses a long edge over 2048 px or a ratio more than 2% off the placement.

A partial response may mean the image was uploaded but not assigned. Its row offers the image in the console and is excluded from bulk retry. A timeout or lost response may also have reached the server, so the row says the send could not be confirmed and asks you to check the draft. The plugin never automatically retries an uncertain upload. Results last for the open plugin session; saved destinations and document links remain after reopening.

## Send later edits

Art inserted from a placement, filled or replaced with it, and successfully sent to a cell carries a link. On **Send**, its row shows the remembered destination and uses the same footer action as a new layer. The plugin does not automatically upload edits and does not claim that every canvas change has been detected.

On **Insert**, the linked-artwork bar says **Linked to {placement}**, with the cell, preview, and available publication information. **Send to draft** opens the Send review. Selecting the title reveals the placement and its cell in Insert. The bar stays hidden on Send, where the rows show destinations and results. Removed placements offer **Send elsewhere…**. Copies require their own destination and link; **Send…** prefers another declared cell without its own Draft art. A link to another workspace offers switching to that workspace.

When the linked environment has different art and the layer can take an image, **Update Figma layer** names the incoming action, with Draft, Staging, or Production shown beside it and in its tooltip. It replaces the visible image, preserving its crop, scale mode, size, position, cell, and environment, in one undo step with an Undo toast. A layer with children or no supported visible image cannot use this action. Main rechecks the link and layer before editing, so a changed layer is refused. Publication and changed-art claims wait for artwork read after the plugin first saw the current link; a failed quiet refresh keeps the previous artwork without claiming it is current.

Linked layers show **Send to draft…** in Figma's properties panel. It opens Send with the review action focused and never sends by itself; its stored command remains `sync` for existing links. A document with linked layers shows **Open Assetlib** when nothing is selected. The plugin menu and Figma's Actions search also offer **Open Assetlib**, **Insert artwork…**, and **Send selection to draft…**. Without a connection, they show the connection screen.

**Cmd+Enter** (Ctrl+Enter on Windows and Linux), outside the connection settings, activates the visible Send action while on Send. On Insert with a linked layer, it opens Send for review first. No shortcut is required.

A successful send remembers the cell on this device and links the layer in the document, so teammates connected to the same app can find it. A fill or replacement with placement artwork clears the older remembered send target on this device. Library images do not create a placement link. Layers inside instances and uploads the console could not assign are not linked.
## Data and network access

The console's Figma view receives metadata for this app's linked layers on scanned pages, once the file key is known. Each report includes the file key and name, current page, page count, whether the scan covered this page or the file, whether any page or layer could not be read, and up to 500 entries: layer and original source-node IDs, layer/page/top-level-frame names and IDs, placement coordinates, linked image and environment, copy/instance status, whether an image is visible, and child count. Names are limited to 200 characters without splitting an emoji; control characters become spaces. If encoded metadata would exceed 1 MB, the report includes fewer entries and is marked partial. The report contains no image bytes, editable layer tree, token, or unsent-design fingerprint. Unreadable or truncated scans are partial; the console must not infer that an omitted layer was removed. The local In this file list still holds up to 2,000 entries.

Reports follow the existing scans: connection, page or selection changes, explicit Refresh, file-link confirmation, inserts, updates, successful bound Sends, and Undo. Other pages are loaded only after **Include all pages**. Unchanged background scans report at most once a minute; explicit Refresh can retry immediately. Reports use the current app's Draft token, are cancelled on a connection change, and cannot block an artwork operation or turn a failed Send into a success. The account settings disclose this reporting. Without a known file key the inventory stays local. In **In this file**, choose **Link this file to show it in the console** to open the existing file-link form. Saving that link reports the scanned layers without exporting artwork or resuming an earlier Send. A saved identity whose file name differs from the open document also pauses reporting and offers the same confirmation, covering renamed files and renamed duplicates. A duplicate with the exact same name cannot be distinguished when Figma does not provide its file key: use Send’s **File → Change** to confirm the duplicate’s own link before relying on its inventory. Reports do not recover earlier insertions from unopened files. The console derives successful send times from its accepted artwork imports, never from a layer's insertion/update timestamp. It cannot see unsent Figma edits.

The plugin sends only each reviewed selected layer's exported PNG bytes (base64 in JSON), node ID and name, file key, PNG export settings, chosen placement coordinates, asset name, schema version, and the expected draft image used for conflict checking. Each layer is sent separately, with broad rebinding disabled. `source.versionId` is `null`. The app-scoped draft token is sent as a bearer token to the chosen console origin, including once to `GET /api/token` when it is pasted and once a session for the saved connection's names (again when a connection change cut that request short or the answer could not be used, and the same connection came back). **Connect to Assetlib** sends `{"client":"figma"}`, with the organization and app IDs of a workspace this page's layers link as a hint when there is one, to start a connection request, with no credentials; then the request's read key as the bearer to ask whether it was approved or to cancel it; and a connection's own token to end it, at **Disconnect**, after **Switch workspace** or another plugin window's connection replaces it, or when Figma couldn't save it. When the start, or a pasted token’s `GET /api/token`, gets no answer, it asks `GET /api/token` with no token at all, to tell an older console from one that can't be reached. It opens the console's connect page in your browser with the request's write key in the URL's fragment; the plugin never stores the write key, and the browser doesn't send a fragment to a server.

It never sends the Figma document, unrelated layers, or a Figma token. Selecting a frame or group exports its visible contents as one PNG; it does not upload its editable layer tree.

It receives the pasted token's organization and app IDs, the workspace and app names when the console returns them, and the token's scopes; for a connection request, its read and write keys, code, and expiry, and once it is approved, the issued token, the organization and app IDs and names, and the email of the account that approved it, which is saved with the connection on this device and shown as "Connected as"; the app's placements; for each placement cell, which image it shows in draft, staging, and production, and when staging and production were published; the app's image names, sizes, and prepared versions; and the bytes of the versions it previews or inserts. Rendition URLs are built from the image ID and hash; the plugin never sends the token to a URL taken from a response.

Art inserted from a placement, a layer filled, replaced, or dropped with it, and a layer sent to a placement store plugin data `assetlib.link.v1`: the console origin, organization and app IDs, placement key, state, appearance, arm, environment, image ID, the node's ID, and the insert or send time. It never holds the token. The document stores `assetlib.file.v1` on its root: the file's key, whether it came from Figma or a pasted link, when it was saved, and the file's name then. A linked layer's relaunch data holds the text under its **Send to draft…** button (its placement key, cell, and environment), and the document's holds the text under **Open Assetlib**. Plugin data is private to this plugin but travels with the file, so anyone with a copy of the file can read it; organization and app IDs are not secret, since they appear in public delivery URLs. Its component description holds the placement key and size, and its documentation link is `{console}/w/{organization ID}/{app ID}/placements` (on `http://127.0.0.1:3100` for the development console); anyone who can open the file reads both, including coding agents through Figma's MCP server. Neither holds the token.

The manifest declares:

```json
{
  "allowedDomains": ["https://console.assetlib.dev", "https://assetlib-console.vercel.app", "https://assetlib-billing-staging.vercel.app"],
  "devAllowedDomains": ["http://localhost:3100"],
  "reasoning": "Reads images from, and sends exported artwork to, the Assetlib console you connect."
}
```

A drag onto the canvas hands Figma the drop point and a description of what to insert (the name, size, scale, placement cell, and image ID), never the token; the download is the same request as an insert's. Every request goes through one module that refuses any other route: `GET /api/token` on the chosen console, which tells a pasted token its own organization and app (tried once, so the form answers at once), and which, without a token, tells an older console from one that can't be reached after a connection request or a pasted token’s `GET /api/token` got no answer; the connection request routes `POST /api/plugin-connections`, `POST /api/plugin-connections/claim`, `POST /api/plugin-connections/cancel`, and `DELETE /api/plugin-connections/current` (each tried once with a 10-second timeout; the plugin's own schedule asks again); and exactly these six calls under `/api/apps/{orgId}/{appId}/`: `GET placements`, `GET placements/artwork`, `GET assets` (with `limit`, `cursor`, and `q`), `GET assets/{assetId}/renditions/{sha256}`, `POST drafts`, and `POST figma/inventory`. Links into the console (**Open console**, **View in console**, **Open in console**, and a toast's **Review**) open in your browser; they are navigations built from validated IDs on the connected console (for the development console, `http://127.0.0.1:3100`, where it signs you in; its requests stay on `localhost:3100`), including a placement’s ID, and never carry the token. The placement page link needs the artwork loaded; before that, **Open in console** opens the image page. The placements endpoint accepts `draft` or `declare`; the other five require `draft`. All of them authenticate only with that bearer token, never cookies, and must allow cross-origin requests from the Figma plugin UI. The hosted console does so for the original five routes on both production hosts (checked on October 11, 2026); the inventory route must be deployed before reports can appear; a console without these reads answers them 404. Send also requires the artwork endpoint to check the destination before uploading. Rendition bytes are served `private, no-store`. The plugin never calls the public delivery routes. Local development requires that console server to be running on port 3100. The development-only origin is not available to a published plugin.

A read times out after 20 seconds, and a download after 20 seconds plus 15 per MiB the console listed for it. A read that fails with a network error, 502, 503, or 504 is tried twice more, after 1 and 4 seconds (or after the wait the console asks for in `Retry-After`, when it exposes one and it is longer), and one answered with 429 is tried again only when the console asks for a wait. A read whose console asks for a wait of more than 30 seconds is not tried again. A draft upload times out after 30 seconds plus 15 per MiB of its body and is never retried, since it may have arrived; the message says so. Searching or refreshing while a list loads abandons the earlier request, and changing the connection abandons every request in flight.

Messages are plain and say what to do next, without HTTP codes or developer terms: a refused or revoked saved pasted token offers Connect again or a new token (a revoked token’s 403 included, wherever it is met); a freshly pasted token the console refuses still says to create a new one in Settings › Tokens; a token without the Draft permission says so; HTTP 409 keeps the console's own message; an export too large to send says "over 3.3 MB as a PNG" (whichever limit it met: 4 MiB of PNG, Vercel's 4.5 MB request, or HTTP 413; every PNG under 3.3 MB fits); a busy console (429) asks to try again in a minute; a server error says "Assetlib had a problem ({status})"; an unreachable console says to check the internet connection (the local console is named, since it may not be running); timeouts say how many seconds the plugin waited, and a draft that timed out may have arrived anyway. A console without the Insert endpoints (a 404) is reported as such; Send also requires the artwork endpoint before uploading, a network failure on an Insert read is said as one ("Can't reach Assetlib. Check your internet connection.", with **Try again**), and an image removed after the list loaded asks for a Refresh, with **Refresh** in the error line. When a pasted token’s `GET /api/token` fails with a network error, a tokenless request distinguishes an older console that needs organization and app IDs from one that cannot be reached; only an answer enables the ID fields; a later **Connect** with the ID fields still empty asks the console about the token again. Finished operations are Figma toasts of at most 100 characters; every toast, result, and error is also announced through one status and one alert region. The shared contract allows at most 4 MiB decoded PNG bytes and 4,500,000 bytes for the JSON body, Vercel's request limit, so a base64 PNG above about 3.3 MB decoded does not fit.

Community listing copy and editable artwork are in [community/](community/README.md). Preparation is not publication: Figma reviews submissions before listing the plugin.

`npm run e2e:local` runs the same bundles and fakes against a running local console with Node's real `fetch`. Start the console on port 3100 (`npm run setup && npm run dev` in `apps/console`), create a **Draft** token in Settings › Tokens, copy the organization and app IDs from Settings › General (the run checks what `GET /api/token` answers against them), and write `{"origin":"http://localhost:3100","orgId":"…","appId":"…","token":"…"}` to a file outside both repositories with mode 600. Then:

```sh
npm run e2e:local -- --connection /path/to/local-connection.json
npm run e2e:local -- --pair --account /path/to/local-account.json
```

With `--pair` (a console with migration 039, and `{"email":"…","password":"…"}` for a local owner or editor in a file with mode 600), it starts a connection request and cancels it (a claim then answers that it was cancelled), starts another, signs in and approves it through the console's session routes on `127.0.0.1` as the connect page would, polls until the plugin saves the browser connection, reads placements and artwork with the issued token, disconnects (`DELETE …/current`), checks that `GET /api/token` with that token then answers 403 `revoked`, checks the four routes' preflights, and checks that no token, key, or password appears in a URL, notice, stored record, or the UI. With `--connection` it starts on the first-run screen and connects with the token alone, then inserts `travel.coast` from each published environment and the first image with a PNG version, drags `travel.coast` from Draft onto the canvas (a placeholder at the drop point, filled and linked in one undo step), opens Send for the draft insert, pastes the file's link once and verifies that it saves without uploading, then explicitly sends the reviewed layer with `rebind: false` and the expected draft image (the app's draft `travel.coast` then shows the sent test image, and the layer's link names it), reads the artwork again, checks the new image's bytes and CORS preflights (`/api/token` included), and checks that the token appears only in the bearer header. WebP-only images are skipped, because converting them needs a browser. It is not part of `npm test`.
